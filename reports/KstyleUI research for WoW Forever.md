# Out-craft Forever's UI suites within Midnight's rules

KstyleUI is a Retail-engine addon project, not a Classic one. WoW Forever launched on 4 November 2026 as client **1.60.1.70840** (product `wowf`, TOC **16001**, internal game type **`camelot`**). It runs Blizzard's Mainline 12.1.5 UI code under a `Camelot/` override layer, and Blizzard said that Midnight's secret values and addon restrictions apply to Forever in full. That sets the engineering contract. KstyleUI may restyle or replace every visible frame, but combat numbers such as health, auras, casts and cooldowns must reach the screen only through widget setters, curves, duration objects and the AuraContainer engine. No module may read the combat log, do Lua arithmetic on health, or change protected frames in combat. EllesmereUI, ElvUI, NihilUI, ForeverUI and the other suites work under the same limits, so better data access is not available to anyone. The open position is craft. No suite pairs EllesmereUI's coverage with the choreographed motion, layered depth and editorial typography of Narcissus. EllesmereUI's core makes **13 animation groups**, where Narcissus declares **282**. The style DNA of the user's installed Narcissus, Plumber, DialogueUI and WaypointUI (45° chamfers, double-line bevels, soft outward shadows, semibold sans text with a soft shadow, 0.15 to 0.5 s eased motion) can be reproduced with original art and OFL fonts. None of their code or art can be copied into a project that wants its own licence. KstyleUI should reimplement NaowhForever's pre-commit hooks, Lua 5.1 regression tests, package check and PR rules, and add a secret-value lint of its own. Its CI must run a real Lua 5.1, because on this Mac both LuaJIT and luacheck accept `goto`, which the game rejects.

## Forever is Retail 12.1.5 behind a 1.60 version number

Blizzard announced Forever at BlizzCon on 12 September 2026 and launched it on 4 November at 23:00 UTC (5 November in Europe). It is an expanded vanilla-era Azeroth with a **level cap of 60** and no flying. It adds three zones, more than 1,000 quests, nine dungeons, two raids and the Skyborne race, and its raids unlock on 9 December ([Warcraft Wiki](https://warcraft.wiki.gg/wiki/World_of_Warcraft:_Forever), [Variety](https://variety.com/2026/gaming/news/world-of-warcraft-forever-release-november-1236859755/)). Its codename was "Camelot". Blizzard said the name would change before launch, but the rename never reached the code. Blizzard's live TOCs still contain **208** `[AllowLoadGameType camelot]` directives, and the Forever-specific folders are still named `Camelot/` ([Gethe forever branch](https://github.com/Gethe/wow-ui-source/tree/forever/Interface/AddOns)).

The client is the Retail binary. The installed copy logs itself as `World of Warcraft Retail ARM64 1.60.1.70840` ([local gx.log](file:///Applications/World%20of%20Warcraft/_forever_/Logs/gx.log)). Blizzard's UI Discord post of 15 September said Forever "shares Mainline WoW's UI architecture, including the vast majority of APIs available in 12.1.5". It added that "the addon disarmament changes introduced in Midnight, including secrets, will also be active in Forever", and that the 12.1.0 AuraContainer and AuraButton changes are available ([Patch 1.60.1 API notes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes/notes), [GameWave](https://gamewave.fr/world-of-warcraft-forever/wow-forever-les-restrictions-d-addons-de-midnight-seront-aussi-appliquees/)). The wiki's diff runs from 12.1.5 (69952) to 1.60.1 (70205). It counts **176 global API functions added and 10 removed**, and **471 FrameXML functions added and 1,041 removed** ([Patch 1.60.1 API changes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes)). The version number 1.60 is branding, not an engine generation. KstyleUI is written against the 12.1.x API (C_ namespaces, mixins, the Settings API, Edit Mode, the Menu API and secret values), and Classic Era guides do not apply.

Forever loads most of the Retail UI, including Edit Mode, the Settings panel, the Cooldown Manager, the built-in Damage Meter and the talents and spellbook frame. About 60 Blizzard addons carry `Camelot/` overrides, among them the unit frames, action bars, minimap, micro menu, bag bar, nameplates, talents, chat, world map and objective tracker. Forever does not load Housing, Delves, the Encounter Timeline and Encounter Warnings, Mythic+, the Encounter Journal, the Retail Group Finder, the PvP UI, Garrisons or the Trading Post. It adds Forever-only systems: `Blizzard_SwingTimer` (an Edit Mode system), the Legacy System, Statistics, a vanilla-style group finder and a full gamepad UI (`Blizzard_Gamepad`, `Blizzard_GamepadActionBars`, `Blizzard_GamepadTargeting`) ([Blizzard_SwingTimer.toc](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SwingTimer/Blizzard_SwingTimer.toc), [Blizzard_EncounterTimeline.toc](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_EncounterTimeline/Blizzard_EncounterTimeline.toc)). Beta Changes 5 (build 70425, 16 October) **reskinned the player, target, pet, target-of-target, totem and focus frames and the minimap header** and reorganized their child frames, with the warning that "Addons that skin or anchor to these frames may need to adjust things" ([API notes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes/notes)). Players also choose a `ForeverExperiencePreset` of Classic or Enhanced, and Edit Mode offers Modern and Classic presets, so the default layout differs between players ([GameRulesDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/GameRulesDocumentation.lua)).

### Read the client and the Gethe forever branch before any wiki

Blizzard publishes no web API reference for Forever. The authoritative source is the client itself, through the in-game `/api` browser and `ExportInterfaceFiles code` and `ExportInterfaceFiles art`. These export commands work only from the real console at the login or character-select screen, after a launch with `-console` ([Viewing Blizzard's interface code](https://warcraft.wiki.gg/wiki/Viewing_Blizzard%27s_interface_code)). The best mirror is the **`forever` branch of Gethe/wow-ui-source**. Its head commit "1.60.1 (70840)" is the same build as the installed client, and it holds 349 Blizzard addons and the generated API documentation ([Gethe forever branch](https://github.com/Gethe/wow-ui-source/tree/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated)). A diff of `forever` against `live` (12.1.5) is the fastest way to see what Forever changed in any Blizzard file. Next in priority come the wiki's [Patch 1.60.1 API changes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes), [API notes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes/notes), [TOC format](https://warcraft.wiki.gg/wiki/TOC_format), [WOW_PROJECT_ID](https://warcraft.wiki.gg/wiki/WOW_PROJECT_ID), [Secret Values](https://warcraft.wiki.gg/wiki/Secret_Values) and [Patch 12.0.0 API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes) pages. After those comes the Retail 12.1.5 documentation for anything Forever did not change. Blizzard's Forever guidance came only through Discord posts that the wiki mirrors, and the only formal policy is the old [UI Add-On Development Policy](https://us.forums.blizzard.com/en/wow/t/ui-add-on-development-policy/24534). Townlong Yak returned HTTP 403 to requests for a Forever build, and wago.tools could not be checked. Spell, item and NPC IDs come from [Wowhead Forever](https://www.wowhead.com/forever), because Forever uses classic-era IDs ([NaowhForever CONTRIBUTING](https://github.com/naowh-gaming/NaowhForever/blob/main/.github/CONTRIBUTING.md)).

### Gate Forever at load time, not with a bare project-ID compare

A Forever-only TOC is `KstyleUI_Forever.toc` or `KstyleUI_Camelot.toc` with `## Interface: 16001` and `## AllowLoadGameType: camelot`. Since build 70291, `forever` is an alias for `camelot` in TOC suffixes, the `[Game]` variable and folder lookup. Blizzard's own code still uses `camelot` everywhere ([API notes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes/notes), [TOC format](https://warcraft.wiki.gg/wiki/TOC_format)). Forever is in the `mainline` family, so `Category`, `Group`, `IconTexture`, `AddonCompartmentFunc` and the 12.x directives all apply.

Sources disagree about how to detect Forever at runtime. The table sets out the evidence.

| Signal | Evidence for | Evidence against |
|---|---|---|
| `WOW_PROJECT_ID == WOW_PROJECT_CAMELOT` (18) | Live source sets `WOW_PROJECT_CAMELOT = 18; WOW_PROJECT_ID = WOW_PROJECT_CAMELOT;` ([ProjectConstants.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_ProjectConstants/Camelot/ProjectConstants.lua)). The wiki lists 18 ([WOW_PROJECT_ID](https://warcraft.wiki.gg/wiki/WOW_PROJECT_ID)). A guide reports 18 on beta build 70338 ([wowforeverguides](https://wowforeverguides.com/addons/developers)). NaowhUI, ElvUI and LibSpecialization use it. | Beta build 69913 returned `WOW_PROJECT_ID` = 1 ([wowforeverbuilds](https://wowforeverbuilds.com/news/what-the-wow-forever-beta-breaks-for-addons-secret-health-values-dead-secure-sni)). The constant is nil outside the camelot game type ([GlueParent.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_GlueParent/Mainline/GlueParent.lua)). Narcissus warns "WOW_PROJECT_* may be nil" ([Initialization.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/Initialization.lua)). |
| Interface number 16000 to 19999 | EllesmereUI gates on it "never on WOW_PROJECT_ID", because it is "the one signal every Forever build reports the same way" ([EllesmereUI_ClientGate.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_ClientGate.lua)). | Not a documented flavor constant. One research note argued against it. |
| TOC metadata `X-GameType == "Camelot"` | Narcissus, Plumber and DialogueUI fall back to it. | Their own TODO expects the rename to "Forever". |

The **safest choice is load-time gating**. With only a suffixed Forever TOC and `AllowLoadGameType: camelot`, KstyleUI never loads outside Forever, so a runtime flag only confirms what the loader has already decided. If code does need a runtime flag (for example in a library shared with other projects), never write the bare `WOW_PROJECT_ID == WOW_PROJECT_CAMELOT`. Outside Forever both sides are nil, and `nil == nil` is true. A nil-safe project check combined with the interface range covers every reported build:

```lua
local _, _, _, iface = GetBuildInfo()
local IS_FOREVER = (WOW_PROJECT_CAMELOT ~= nil and WOW_PROJECT_ID == WOW_PROJECT_CAMELOT)
	or (iface >= 16000 and iface < 20000)
```

## Secret values let modules show combat data but never compute it

In tainted addon code, a secret value can be stored, passed to functions, checked with `type()` and concatenated. **Arithmetic, comparisons (even with nil), boolean tests, `#`, use as a table key and indexing all raise an immediate Lua error** ([Secret Values](https://warcraft.wiki.gg/wiki/Secret_Values)). Passing a secret to a widget setter gives that widget a "secret aspect", and the matching getter then returns secrets too. Anchoring spreads the aspect, so `GetPoint` and `GetWidth` on a frame anchored to a secret-anchored frame also return secrets. Forever added **`FrameStrata` as a new secret aspect** ([API notes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes/notes)). `Enum.AddOnRestrictionType` has six states: Combat, Encounter, ChallengeMode, PvPMatch, Map and Chat ([RestrictedActions docs](https://github.com/Gethe/wow-ui-source/tree/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated)). Blizzard describes the goal as limiting addons' ability "to perform complex logic and decision making based off combat information", and says the changes are "not intended to prevent 'look and feel' customization of UI elements" ([Patch 12.0.0 API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes)). That intent is what makes KstyleUI possible.

### Forever changes the rules in a handful of places

Forever's API docs flag `UnitHealth`, `UnitHealthMissing`, `UnitHealthPercent` and `UnitInRange` with `SecretReturns = true`. **Health is always secret to addon code, in combat or out** ([UnitDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)). In contrast, **threat is readable**. EllesmereUI notes that `C_Secrets.ShouldUnitThreatValuesBeSecret` is false on Forever ([ThreatData.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIForeverEssentials/EllesmereUIForeverEssentials_ThreatData.lua)). Combo points are disputed. A forum thread and EllesmereUI's code say they can be secret ([forum](https://us.forums.blizzard.com/en/wow/t/combo-points-are-secret-values/2352853), [ForeverExtras](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIUnitFrames/EUI_UnitFrames_ForeverExtras.lua)), and a fan site says they are not ([wowforevertierlist](https://wowforevertierlist.com/addons/restrictions)). Treat them as secret. EllesmereUI draws each pip as a one-point StatusBar (`SetMinMaxValues(i-1, i)` then `SetValue(count)`), so the comparison happens in C.

The NaowhForever contribution guide adds four Forever rules that KstyleUI should adopt as written ([CONTRIBUTING](https://github.com/naowh-gaming/NaowhForever/blob/main/.github/CONTRIBUTING.md)). First, **aura data goes secret during boss pulls before `InCombatLockdown()` turns true**. A combat check therefore does not protect an aura read. Guard every aura read with `C_Secrets.ShouldAurasBeSecret()` and freeze aura-driven state while it returns true. EllesmereUI applies the same rule, and defers aura restyles when the predicate is true or when a `pcall` of `C_UnitAuras.GetAuraDataByIndex` fails ([EllesmereUI_AuraKit.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_AuraKit.lua)). Second, **the combat log is closed to addons**. Registering `COMBAT_LOG_EVENT_UNFILTERED` errors in 12.x ([Patch 12.0.0 API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes)). That is why Forever ships a native swing timer API (`PLAYER_SWING`, `C_SwingTimer`) ([SwingTimerDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/SwingTimerDocumentation.lua)). No Blizzard text addresses Forever's combat log directly, but every source that mentions it agrees. Third, **Forever uses classic-era spell IDs**. EllesmereUI found that the Retail GCD reference spell 61304 "reports nothing" on Forever and uses 29515 instead ([EllesmereUI_Lite.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_Lite.lua)). Fourth, **Forever does not load Blizzard's deprecated shims**. Use `C_SpellBook.IsSpellKnown`, not `IsPlayerSpell`. During the beta, `GetSpellInfo`, `GetItemInfo` and `GetTalentInfo` were already gone ([wowforeverbuilds](https://wowforeverbuilds.com/news/what-the-wow-forever-beta-breaks-for-addons-secret-health-values-dead-secure-sni)).

Secure snippets are the remaining open risk. Beta build 69913 lacked `loadstring_untainted`, which broke action-bar paging, secure group headers and click-casting. The live source still calls that function at line 79 of [RestrictedExecution.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_RestrictedAddOnEnvironment/RestrictedExecution.lua), and EllesmereUI 9.6.1 has 40 `RegisterStateDriver` call sites on Forever. The bug is probably fixed, but it needs an in-game check before the action-bar module is built.

### Replace combat frames, mirror data viewers, reskin the rest

The leading Forever suites now agree on a hybrid approach. They **replace** the combat HUD (unit, party, raid and boss frames and action bars) with addon-owned secure frames, **mirror or skin** Blizzard's data viewers, and **reskin** non-combat windows. EllesmereUI says it builds its own action buttons to eliminate "the taint surface from reusing Blizzard's protected buttons", so the reason is taint, not features ([EllesmereUIActionBars.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIActionBars/EllesmereUIActionBars.lua)). Taint hygiene comes down to a short list of rules. Keep per-frame state in a weak-keyed side table and never write a field onto a Blizzard frame. Hook with `hooksecurefunc` or `HookScript` and never `SetScript` on a Blizzard frame. Never `Hide()` a Blizzard frame that other Blizzard code lays out. Naowh fades such frames with `SetAlpha`, because hiding the XP bar containers tainted the action bars, and EllesmereUI reparents stock bars to a hidden frame instead ([CONTRIBUTING](https://github.com/naowh-gaming/NaowhForever/blob/main/.github/CONTRIBUTING.md), [EUI_ActionBars_Disposal.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIActionBars/EUI_ActionBars_Disposal.lua)). Check `EditModeManagerFrame:IsShown()` before any `SetParent`, and defer the call with `C_Timer.After(0)`. Run secure setup synchronously at `PLAYER_LOGIN`, which is the only window where it is allowed while the player is in combat. Queue other protected work in combat and run it on `PLAYER_REGEN_ENABLED` ([EllesmereUI_Lite.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_Lite.lua)).

Some rules are specific to KstyleUI's window chrome. `ReloadUI()` is blocked from addon code even on a click, so a reload button must be a secure macro button running `/reload`. A named addon frame in `UISpecialFrames` taints `CloseAllWindows`, so KstyleUI needs its own Escape handler. `SetPropagateKeyboardInput` is protected in combat. While Blizzard's gamepad handling is active, opening or closing a Blizzard panel from addon code is forbidden ([NaowhForever Core/README.md](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/NaowhForever/Core/README.md)). To reproduce restricted states solo, set the testing CVars `addonCombatRestrictionsForced`, `addonEncounterRestrictionsForced`, `addonMapRestrictionsForced` and `addonChatRestrictionsForced` ([Secret Values](https://warcraft.wiki.gg/wiki/Secret_Values)).

## Four installed addons share a style DNA built from chamfers, shadows and short eased motion

Narcissus, Plumber and DialogueUI (all by Peterodox) and WaypointUI (by AdaptiveX) look premium for the same reason. Every surface is drawn art, not a generated box. A read-only audit of the installed copies measured these traits directly from their textures and code ([style DNA notes](file:///Users/lee/KstyleUI/research_notes/KstyleUI%20research%20for%20WoW%20Forever/installed_addon_style_dna.md)).

### Colour, type and shape

All four use **near-black neutral surfaces from #0d0d0d to #2b2b2b at 80 to 92% opacity**. Text is never pure white at rest. Narcissus settings use three text tiers, #666666 for disabled, #ababab for normal and #ebebeb for highlight, and show #ffffff only on hover ([Narcissus SettingsFrame.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/SettingsFrame.lua)). Each surface has one accent family. Plumber uses bronze and copper (#d7c0a3 text, an amber-to-rust #dfa63c to #9f4925 button face, a #64513e bevel). DialogueUI uses parchment and brick. WaypointUI has a gold tab rim, #856d00. Narcissus and Plumber share a brightened quality palette, Rare **#699eff** and Epic **#b953ff**, and Plumber's code says "use the color in Narcissus" ([Narcissus Color.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/NarciDB/Color.lua), [Plumber API.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Plumber/API.lua)). Narcissus also tints its chrome by the current zone (`MapColors`) and brightens text tints with a per-channel square root. WaypointUI authors all its in-world art in white or greyscale and tints it at runtime. That is the most flexible base for a suite with user-chosen accents.

Narcissus leads on typography. Its base font is **Source Sans Pro Semibold at 11 px with a soft (0.6, −0.6) black shadow instead of an outline**. Menus use 14 px, and numerals use 12, 18 and 24 px. Tiny all-caps labels get letter spacing of 2, and Semplicita Pro is used for capped headings ([FontSettings.xml](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/Font/FontSettings.xml)). DialogueUI uses a serif storybook stack. Plumber and WaypointUI mostly use Blizzard's Friz Quadrata with a 1 px shadow.

Panels use **45° chamfered corners of about 5 to 8 UI px**, not round ones. The measurements are Narcissus settings about 7 to 8 px, Plumber's generic box about 7 px and WaypointUI's widget container about 5 px. Borders are a double-line bevel (dark outer line, light hairline, dark inner line). Soft shadows extend outside the frame through nine-slice corners anchored at their **centre** on the frame's corners, with a 0.25/0.75 texture split ([Plumber SharedWidgets.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Plumber/Modules/Shared/SharedWidgets.lua)). Masks and additive light do much of the work. Narcissus has **102 XML MaskTextures and 93 ADD blends**, while Blizzard's `BackdropTemplate` appears 8 times in Narcissus and never in Plumber or DialogueUI. Narcissus item slots are opaque JPG colour art with a separate alpha mask, which saves texture memory. Dividers are gradient textures that fade at both ends, never 1 px colour lines. Each addon has a signature motif: the Narcissus hexagon, the WaypointUI diamond and Plumber's chamfered bronze plates. KstyleUI needs a motif of its own.

### Motion and interaction

The three Peterodox addons ship one identical Penner-style easing module (`linear`, `outSine`, `inOutSine`, `outQuart`, `outQuint`, `inQuad`) and drive most motion through hand-written `OnUpdate` tweens ([Narcissus Easing.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/API/Easing.lua)). WaypointUI has a chainable tween engine with 33 easings and **one pooled `OnUpdate` frame that removes itself when idle** ([ui-anim engine.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/WaypointUI/packages/ui-anim/src/engine.lua)). The most common durations in Narcissus's 282 animation groups are 0.2 s (95 uses), 0.25 s (85), 0.5 s (67) and 0.15 s (65). The Narcissus settings window fades in over 0.25 s. At the same time it rises 24 px along a 0.4 s smooth path that overshoots by 2 px and settles, and it closes instantly ([SettingsFrame.xml](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/SettingsFrame.xml)). On hover, DialogueUI and Plumber slide button content **8 px with `outQuart` over 0.25 s**, and a press moves the content 1 px down ([UITemplates.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/DialogueUI/Code/Dialogue/UITemplates.lua)). Narcissus's fade driver scales the duration by the remaining alpha distance, so an interrupted fade never jumps. Its smooth scroll uses a 0.14 blend and plays a 0.4 s rubber-band bounce (−6, +2, 0 px) at either end ([FadeFrame.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/NarciDB/FadeFrame.lua), [ScrollFrame.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Narcissus/NarciDB/ScrollFrame.lua)).

Smaller rules recur across the four. One highlight frame moves to whichever row is hovered. Tooltips use 8 px padding with 2 px line spacing and 4 px paragraph spacing. Sounds are rare stock SOUNDKIT checkbox and open/close sounds. DialogueUI treats gamepad as first-class, with PlayStation, Xbox and Switch glyph sets. The settings windows share a layout. Each has a left category rail of 180 to 260 px, search and filter controls, schema-driven options with `showWhen` and `disableWhen` (WaypointUI), a live preview pane (Plumber and Narcissus), golden-ratio proportions (Plumber's centre column is 0.618 of the width, about 937 × 576 overall) and lazy construction on first open ([SettingsPanelNew.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Plumber/Modules/ControlCenter/SettingsPanelNew.lua), [Settings_Schema.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/WaypointUI/Code/Settings/Settings_Schema.lua)). DialogueUI shows how to theme. A theme is a texture root, a set of colour tokens and a Font-object colour map, and a `ThemeChanged` callback re-skins every registered frame ([ThemeUtil.lua](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/DialogueUI/Code/Utility/ThemeUtil.lua)).

### Copy nothing: three licences and a pile of commercial fonts

KstyleUI can study these addons, but it cannot copy them. **Narcissus** code is MPL 2.0, which is file-level copyleft, and its art is **CC BY-NC-SA 4.0**, which forbids commercial use and forces the same licence on derived art ([Narcissus licence](https://www.curseforge.com/wow/addons/narcissus/license)). **Plumber** is GPLv3, so incorporating its code or art would make KstyleUI GPLv3 ([Plumber](https://www.curseforge.com/wow/addons/plumber)). **WaypointUI** is listed as GPLv3 on CurseForge, but its GitHub repository shows no LICENSE file, so its terms are unclear ([WaypointUI](https://www.curseforge.com/wow/addons/waypointui), [GitHub](https://github.com/Adaptvx/Waypoint-UI)). **DialogueUI is All Rights Reserved** ([DialogueUI licence](https://www.curseforge.com/wow/addons/dialogueui/license)). The fonts are a separate problem. Fremont ships under a Fontspring Desktop EULA. Semplicita Pro is "© Canada Type … All rights reserved", and Friz Quadrata and Arial Narrow are commercial. DialogueUI's Trajan Pro 3 carries the copyright field "extracted by PdfGrabber". DialogueUI also ships a folder its manifest calls "only Blizzard Assets", and WaypointUI bundles `.ogg` files named after Blizzard sounds ([DialogueUI GameAssets manifest](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/DialogueUI/Art/GameAssets/Manifest.txt)). KstyleUI may freely use the techniques (centre-anchored slices, distance-proportional fades, the shared highlight) and Penner's BSD-licensed easing formulas, reimplemented in its own code. It may bundle OFL or Apache fonts downloaded from their upstream sources, and it may reference game fonts and textures by their in-game path without shipping them. This reading of the licences is not legal advice. The user reports that NaowhForever is also all rights reserved, so the same rule covers its checks (see the last section).

## Rivals cover every module but animate almost nothing

**EllesmereUI** is the default modern suite on Forever. It has **9,509,211 CurseForge downloads**, and v9.7.8 shipped on 6 November ([CurseForge](https://www.curseforge.com/wow/addons/ellesmereui)). It is a 23-addon suite on its own Ace3-free framework, with a custom options panel (search, live previews, video guides), an Unlock Mode, and a first-install module picker followed by a style picker with mock cards. It has four looks. The Forever-only "WoW Forever" look is the default on Forever and imitates Blizzard's bronze art ([EllesmereUI_StyleCards.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_StyleCards.lua), [EllesmereUIChat_Forever.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIChat/EllesmereUIChat_Forever.lua)). Its Forever Essentials addon adds spell uprank, a classic spellbook and talents, a flight timer, map reveal, a loot feed and a threat meter. Its visual identity is flat, teal-accented (#0CD29D) and pixel-perfect, with optional rounded corners of radius 0 to 16. It uses little motion: **13 `CreateAnimationGroup` calls in the core**, 2 in Unit Frames and 3 in Action Bars. Its GitHub tracker has **450 open issues**. The Forever ones are functional breakage: action bars that taint `Blizzard_GamepadActionBars`, Action Bar 1 failing to page to possess bars or stealth, keybinds casting the wrong spell in combat, and chat tabs dying on a protected table ([EllesmereUI issues](https://github.com/EllesmereGaming/EllesmereUI/issues?q=forever)).

The other suites fill out the field. On Forever the **Naowh stack** is curation on top of EllesmereUI. NaowhUI is an Ace3 installer that writes EllesmereUI, BigWigs, Edit Mode and Naowh Forever profiles with per-class layouts. Naowh Forever 1.1.34 is a 16001-only companion window (BiS, dungeon journal, training planner, professions, threat meter) in which "every module starts off" ([NaowhForever README](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/NaowhForever/README.md)). **NihilUI** appeared around 5 November with **69 downloads** at v0.2.2. It is All Rights Reserved, minimal and centred on the combat HUD, and its installer is gated behind Patreon with BattleTag-bound copies checked every 6 hours. It publishes performance figures of 0.0095 ms per health or threat update with 0 KB garbage over 20,000 events, and a 0.02 ms per-event ceiling "enforced by tests" ([CurseForge](https://www.curseforge.com/wow/addons/nihilui), [nihil.gg](https://nihil.gg)). **ElvUI** added initial Forever support in 16.00 (13 October) and gamepad support in 16.01 (3 November) ([ElvUI changelog](https://raw.githubusercontent.com/tukui-org/ElvUI/main/CHANGELOG.md)). **ForeverUI** is Forever-only, with 28,086 downloads, a role-first setup questionnaire, a 12-type damage meter and a "flat and dark" default with an optional bronze theme ([CurseForge](https://www.curseforge.com/wow/addons/foreverui)). **SpartanUI** 9.0 ships painted looks ([releases](https://github.com/spartanui-wow/SpartanUI/releases)). **GW2 UI** (2.7M downloads) has hand-painted art "with smooth animations" and switches to a gamepad layout on Forever ([CurseForge](https://www.curseforge.com/wow/addons/gw2-ui)). Classic-look restorers such as ClassicUI Forever (95.6K downloads) round out the field ([mmonster](https://mmonster.co/wow-forever/guides/addons/ui)).

Every credible suite covers unit, raid and party frames, nameplates, action bars, cast bars, minimap, chat, bags and bank, tooltips, movers, profile import and export, and an installer. On Forever the rising expectations are a threat meter, a swing timer, a damage meter that works under secret values, gamepad support and spell-rank handling. Reddit could not be read during the research, so the trackers are the best proxy for player complaints. They point at reliability on Forever's edge cases (gamepad taint, stance and stealth paging, rank-based buffs, pet happiness, the keyring) and at accessibility, with repeated requests for scalable fonts and a low-vision character sheet ([EllesmereUI issues](https://github.com/EllesmereGaming/EllesmereUI/issues), [NaowhForever issues](https://github.com/naowh-gaming/NaowhForever/issues)).

The visual field splits three ways: flat-modern minimal (ElvUI, EllesmereUI's own style, NihilUI, ForeverUI), Blizzard bronze mimicry (EllesmereUI's Forever look, ClassicUI Forever) and painted fantasy (SpartanUI, GW2 UI). **No suite combines choreographed enter and exit motion, layered depth, editorial typography and one art direction carried across every Blizzard window.** That combination is Narcissus's signature, and Narcissus is not a UI suite. EllesmereUI is closest on coverage, and GW2 UI is closest on art and motion but is themed to another game. The best onboarding today, EllesmereUI's mock cards, is functional and static, so an animated first run would be new. Monetisation is contentious on Forever, where a forum thread about a paid levelling addon passed 600 replies ([ForeverMeta](https://forevermeta.me/en/guides/wow-forever-addons-interface)). KstyleUI's strategy follows from this. It must match EllesmereUI's baseline modules and configuration experience, beat everyone on motion, depth and type, and be the most reliable suite on Forever's edge cases. Every animation must also respect the taint limits that already break EllesmereUI's gamepad paths.

## The renderer offers masks, slices and Slug text, but no blur

Addon textures can be **BLP, JPEG, PNG or TGA with power-of-two dimensions**. PNG paths must include the `.png` extension, and since 9.0.1 a new file needs only `/reload` ([SetTexture](https://warcraft.wiki.gg/wiki/API_TextureBase_SetTexture)). Plumber ships 256², 512² and 1024² PNGs on Forever. Addons cannot register real atlases, because `C_Texture` on Forever has only atlas getters ([TextureUtilsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/TextureUtilsDocumentation.lua)). A KstyleUI atlas is therefore a power-of-two sheet plus a Lua table of texture coordinates, with 2 to 4 px of padding between cells so bilinear filtering does not bleed. The Forever build has native nine-slice on a single texture (`SetTextureSliceMargins` with `Enum.UITextureSliceMode` Stretched or Tiled), `SetSpriteSheetCell`, and an undocumented `SetSVG` that Blizzard's own UI never calls ([SimpleTextureBaseAPIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleTextureBaseAPIDocumentation.lua)). Treat `SetSVG` as an experiment until it is tested in game.

The premium techniques are all available. They include mask textures (`CreateMaskTexture`, `AddMaskTexture`, with `CLAMPTOBLACKADDITIVE` wrap) and `SetGradient`, which takes `CreateColor` objects, not raw numbers. Other options are the blend modes DISABLE, BLEND, ALPHAKEY, ADD and MOD, desaturation, and `SetVertexOffset` for skewed shapes ([UIOBJECT Texture](https://warcraft.wiki.gg/wiki/UIOBJECT_Texture), [UI.xsd](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SharedXML/UI.xsd)). Radial progress bars come with a **feathered edge** (`SetRadialProgressBarFeather`) and a matching `RadialProgress` animation type, which replaces the old two-half-circle trick for ring meters ([RadialProgress docs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleAnimRadialProgressAPIDocumentation.lua)). The Cooldown widget takes a custom swipe texture, edge texture and circular edge, plus the secret-aware `SetCooldownFromDurationObject` ([FrameAPICooldownDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/FrameAPICooldownDocumentation.lua)). **There is no blur, backdrop filter or shader API.** "Frosted glass" must be faked with a dark translucent gradient, a very low-alpha tiled noise texture, a 1 px top highlight and an inner-glow nine-slice. Soft shadows and glows come from one pre-rendered falloff PNG, nine-sliced, with BLEND for shadows and ADD for glows.

Animation should run in the engine wherever it can. AnimationGroups on Forever support Alpha, Translation, TranslationLine, Scale, ScaleLine, Rotation, Path, FlipBook, VertexColor, TextureCoordTranslation and RadialProgress, with smoothing `NONE`, `IN`, `OUT`, `IN_OUT` or `OUT_IN` and looping `NONE`, `REPEAT` or `BOUNCE` ([UI.xsd](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SharedXML/UI.xsd)). Secret values add a second reason to prefer engine animation. EllesmereUI's swing timer re-arms a `C_DurationUtil` duration object on `PLAYER_SWING`. The engine then animates the bar through `SetTimerDuration` and writes the remaining time through a duration text binding, with no Lua running per frame ([EUI_ResourceBars_SwingTimer.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUIResourceBars/EUI_ResourceBars_SwingTimer.lua)). Keep custom `OnUpdate` tweens for eased width and value changes on non-secret data. Run them through one pooled driver that unregisters when idle and allocates nothing per frame. Text that scales during an animation needs a Slug font and `FontString:SetScaleAnimationMode(Enum.FontStringScaleAnimationMode.Vertex)`. Blizzard's docs warn that Vertex mode on a non-Slug font "may cause significant pixelation" ([UISharedDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/UISharedDocumentation.lua)).

Pixel-perfect layout starts from Blizzard's own `PixelUtil`, which takes **one UI unit per physical pixel at an effective scale of `768 / physicalHeight`** ([PixelUtil.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SharedXML/PixelUtil.lua)). The UI Scale slider only goes from **0.65 to 1.15** ([Graphics.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua)). A 1440p display needs 0.533 and 4K needs 0.356. This Mac's backbuffer is 3456 × 2234, which needs 0.344 ([local gx.log](file:///Applications/World%20of%20Warcraft/_forever_/Logs/gx.log)). All of these are below the slider's minimum, so KstyleUI must scale its own root frame from code on `PLAYER_LOGIN`, `UI_SCALE_CHANGED` and `DISPLAY_SIZE_CHANGED`:

```lua
local function PixelPerfectScale(root)
	local _, h = GetPhysicalScreenSize()
	root:SetScale((768 / h) / UIParent:GetEffectiveScale())
end
```

Inside that root, design in pixels and snap with `PixelUtil.SetSize` and `PixelUtil.SetPoint`. On Retina displays everything is physically tiny at 1:1, so offer a whole-number density setting (1× or 2×) rather than fractional scales, and author art at 2× the intended size. Art that must not be sharpened gets `SetSnapToPixelGrid(false)` and `SetTexelSnappingBias(0)`, which is Blizzard's `NineSliceUtil.DisableSharpening` pattern ([NineSlice.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SharedXML/NineSlice.lua)). One unknown decides the whole strategy. If `GetPhysicalScreenSize()` returns 1728 × 1117 points instead of 3456 × 2234 pixels on macOS, one "pixel" is two device pixels.

Fonts load from TTF or OTF through `SetFont(path, size, flags)`. The flags are `""`, `MONOCHROME`, `OUTLINE`, `THICKOUTLINE` and **`SLUG`**, which renders through the client's GPU Slug library ([SetFont](https://warcraft.wiki.gg/wiki/API_FontInstance_SetFont)). Blizzard sets `slug="true"` on 35 font members, mainly nameplate and huge outlined fonts ([Fonts.xml](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_Fonts_Shared/Shared/Fonts.xml)). Slug is not safe for every font. Plumber reverted its switch because "it caused rendering problems with certain fonts" ([Plumber changelog](file:///Applications/World%20of%20Warcraft/_forever_/Interface/AddOns/Plumber/Modules/ControlCenter/Changelog/enUS.lua)), and an older bug report traced over-thick outlines to Slug ([WoWUIBugs #286](https://github.com/Stanzilla/WoWUIBugs/issues/286)). The policy is Slug for large numerals, scale-animated text and outlined text over the 3D world, and the default rasteriser for small body text unless an in-game comparison favours Slug. For the face itself, the evidence favours **Source Sans 3 Semibold** for body text. It is OFL, and Narcissus proves it reads well at 9 to 14 px in WoW. Inter and IBM Plex Sans are OFL alternatives, and Cinzel or Marcellus suit sparing all-caps titles ([Inter OFL](https://github.com/google/fonts/blob/main/ofl/inter/OFL.txt), [Cinzel OFL](https://github.com/google/fonts/blob/main/ofl/cinzel/OFL.txt)). Ship static instances, because variable-font support is unverified. Add per-alphabet fallbacks with `CreateFontFamily` and Noto Sans or Noto Sans CJK. Ship each font's `OFL.txt`, and rename any modified Source build, because "Source" is a Reserved Font Name.

## Embed oUF, LibEditMode and AceDB, and use AI art only for ornament

Every Retail integration point exists on Forever. A premium options window should be a **canvas-layout Settings category** hosting KstyleUI's own styled frame, optionally with a small vertical-layout subcategory for searchable basic toggles ([Settings API guide](https://warcraft.wiki.gg/wiki/Creating_a_settings_menu)). Prefer `Settings.RegisterAddOnSetting` to `RegisterProxySetting`, which tainted spellcasting in a 10.0-era report ([WoWInterface](https://wowinterface.com/forums/showthread.php?p=341406)). Register the addon compartment entry through the TOC, which costs nothing. Frame positioning is a real design choice. **LibEditMode** release 19 (3 November) lists 16001 and puts addon frames into Blizzard's Edit Mode, and it says it limits method reuse to reduce taint ([LibEditMode](https://github.com/p3lim-wow/LibEditMode)). EllesmereUI and NaowhForever instead built their own unlock modes, and EllesmereUI's code documents how Edit Mode's layout passes taint frames. LibEditMode fits Forever's built-in systems (the Swing Timer is an Edit Mode system, and gamepad layouts are saved separately), but KstyleUI should prototype it early against the taint scan.

The library stack is proven on Forever. **oUF** (MIT) lists `16001` and `AllowLoadGameType: standard, camelot`, and release 14.2.1 (3 November) added "core: Scrub secrets" ([oUF.toc](https://raw.githubusercontent.com/oUF-wow/oUF/master/oUF.toc), [oUF releases](https://github.com/oUF-wow/oUF/releases)). Other libraries are LibStub (public domain), CallbackHandler, **AceDB-3.0** for profiles (Ace3 is BSD-style, [licence](https://raw.githubusercontent.com/WoWUIDev/Ace3/master/LICENSE.txt)) and LibSharedMedia-3.0 (LGPL 2.1), which lets users swap KstyleUI's fonts and statusbar textures. LibCustomGlow (MIT) lists only 12.0 interfaces in its TOC, but NaowhForever embeds it on Forever through its `.pkgmeta` ([naowh .pkgmeta copy](file:///private/tmp/claude-501/-Users-lee/1c722721-459a-44d5-9d89-4921154ab7a5/scratchpad/naowh_ref/.pkgmeta)). LibEditMode's licence allows embedding it unmodified in an addon but forbids distributing it standalone ([LibEditMode licence](https://raw.githubusercontent.com/p3lim-wow/LibEditMode/master/LICENSE.txt)). EllesmereUI replaced AceAddon, AceEvent and AceDB with one lightweight file that still reads the AceDB SavedVariables format ([EllesmereUI_Lite.lua](file:///Applications/World%20of%20Warcraft/_classic_beta_/Interface/AddOns/EllesmereUI/EllesmereUI_Lite.lua)). KstyleUI can follow the same route: keep the AceDB profile format, and skip the rest of the Ace3 runtime unless a module needs it.

The asset pipeline uses **PNG (RGBA, straight alpha, power of two) as the default format**. Converting to BLP is optional, through Pillow 9.1.0 or later, which can save BLP2, or through `blp2any` ([Pillow 9.1.0 notes](https://pillow.readthedocs.io/en/stable/releasenotes/9.1.0.html), [JuicyPixels-blp](https://hackage-content.haskell.org/package/JuicyPixels-blp-0.5.0.0)). Keep geometry procedural: hairlines, fills, gradients, chamfer masks drawn with Pillow at 4× and downsampled, shadows from one Gaussian falloff, rings from radial progress, and shimmer from a TextureCoordTranslation over a gradient strip. Procedural geometry stays pixel-exact at every density and can be themed. Image models produce slightly asymmetric, noisy detail at 1 to 2 px. NaowhForever draws its whole icon set from a script, `Tools/media/make_media.py`, so its art can be regenerated ([Tools README copy](file:///private/tmp/claude-501/-Users-lee/1c722721-459a-44d5-9d89-4921154ab7a5/scratchpad/naowh_ref/Tools/README.md)). Use **AI-generated art** only for irregular, rich material such as ornamental corners, crests, emblem watermarks, material textures (brushed metal, smoked glass), feature icons and FlipBook keyframes for sparkles. The Higgsfield tools in this environment include image generation, `remove_background` and `upscale_image`. The research could not confirm which models output true alpha, because the Higgsfield API returned 503 during research. Generate on a flat #FF00FF background with "no shadow, no text", then key the colour out locally. Script a check that alpha has true 0 and 255 regions and no magenta-tinted fringe, because "RGBA mode alone does not prove transparency" ([tessl image skill](https://tessl.io/registry/skills/github/MengTo/Skills/codex-gpt-image-2-5-flare)). Lock the style with one hero reference image passed to every later generation. Generate greyscale where possible and tint in game. Record the model, prompt, seed and date for every shipped asset, and confirm the model's commercial-use terms before publishing.

Development on macOS uses VS Code with lua-language-server and Ketho's WoW annotations ([vscode-wow-api](https://github.com/Ketho/vscode-wow-api)). Pure-Lua modules (layout maths, easing, palette, profile migration) get busted tests ([busted](https://github.com/lunarmodules/busted)). wowless is a pre-alpha headless FrameXML interpreter that runs only in Docker and loads Retail code, so at most it is a load smoke test ([wowless](https://github.com/wowless/wowless)). The BigWigs packager added Forever support in v2.6.0, and v2.7.0 (5 November) allows Forever interface versions in Mainline TOCs ([packager releases](https://github.com/BigWigsMods/packager/releases)). In-game debugging uses `/fstack`, `/etrace`, `/tinspect`, `/dump` and `/api`, plus the installed BugSack 12.1.9 and BugGrabber 12.1.1, both of which list 16001 ([SlashCommands.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_ChatFrameBase/Shared/SlashCommands.lua)).

## Reimplement NaowhForever's checks, then add a secret-value lint

The user asked that KstyleUI use the same tests and checks as NaowhForever. NaowhForever is all rights reserved, so KstyleUI must write its own scripts from the behaviour described here and must not copy their source. The guide judges every change against **five acceptance criteria** ([CONTRIBUTING](https://github.com/naowh-gaming/NaowhForever/blob/main/.github/CONTRIBUTING.md)). The first is **off by default and free while off**. A feature that is off registers no events, runs no hooks, builds no frames and runs no `OnUpdate`. The second is **cheap while on**: event-driven code, `OnUpdate` only while something animates, and no table churn in hot paths. The third is **no taint and no Lua errors**, with the rules quoted earlier. The fourth is **Forever only**: no Retail branches, classic-era IDs and no deprecated shims. The fifth is **your own code**. The house style in [STYLE.md](https://github.com/naowh-gaming/NaowhForever/blob/main/.github/STYLE.md) puts each module in its own folder, loaded through its own XML file, so adding a file never edits a TOC. Load order is layering (settings and API, constants, data, rules, view, then UI). Each file keeps exactly one comment, its first line. Sizes, timings, IDs and colours are named constants, and colours come only from the theme. Every on/off switch and its default live in one features file, and UI is built only from shared components. Code is Lua 5.1, ASCII only, with CRLF line endings.

The checks enforce those rules mechanically. The table describes each check in the copies the user supplied, with its purpose ([naowh_ref copies](file:///private/tmp/claude-501/-Users-lee/1c722721-459a-44d5-9d89-4921154ab7a5/scratchpad/naowh_ref/)). ### This Mac cannot catch `goto` locally

A test run on this Mac confirmed the guide's warning. **luacheck 1.2.0, which runs on PUC Lua 5.5 here, reported zero warnings with `--std lua51` on a file that uses `goto`.** LuaJIT 2.1 compiles `goto` but rejects `//`, and Homebrew has no `lua5.1`. Locally, `LUA=luajit bash Tools/regression/run-all.sh` still catches `//`, but only CI on Ubuntu with `apt install lua5.1` catches `goto`. KstyleUI should add a pygrep hook that rejects `goto` and `::label::` in addon files, so the gap closes at commit time. The installed Ketho annotations are **v0.22.3, for patch 12.0.1 (February 2026)** ([local CHANGELOG](file:///Users/lee/.local/share/wow-dev/vscode-wow-api/CHANGELOG.md)). They include `C_Secrets.ShouldAurasBeSecret`, `issecretvalue`, `UnitHealthPercent`, `C_DamageMeter` and `SetAlphaFromBoolean`. They lack `WOW_PROJECT_CAMELOT` and `C_SwingTimer`, and they still annotate Retail's deprecated shims such as `IsPlayerSpell` ([Deprecated_SpellBook.lua](file:///Users/lee/.local/share/wow-dev/vscode-wow-api/Annotations/Core/FrameXML/Blizzard_Deprecated/Deprecated_SpellBook.lua.lua)), which Forever does not load. lua-language-server will therefore accept calls that fail on Forever. KstyleUI's `read_globals` should come from a script that walks the Gethe `forever` branch's generated API docs and FrameXML globals, and should carry an explicit deny list of shim names. That list is the cheapest way to enforce Naowh's "no deprecated shims" rule. Any lua-language-server diagnostic run is an extra check on top of it, not a replacement.

### Extend the checks for a suite that touches every Blizzard frame

NaowhForever is a companion window that rarely touches Blizzard frames. KstyleUI reskins most of them, so its taint-scan allowlist will be its main review document. Every allowed entry needs the same one-line reason Naowh requires. The scan should also flag three patterns that EllesmereUI found in production: **any field write onto a Blizzard frame**, **any `SetParent` without an Edit Mode guard nearby**, and **`Hide()` on a Blizzard layout frame**. KstyleUI also needs a **secret-value lint** that Naowh does not have. It should flag comparisons, arithmetic, `#`, table-key use and boolean tests on the results of `UnitHealth`, `UnitPower`, `UnitCastingInfo` and aura data, unless an `issecretvalue` guard comes first. It should also flag any reference to `COMBAT_LOG_EVENT` or `CombatLogGetCurrentEventInfo`. The research notes on Forever's restrictions proposed exactly this lint. The pixel test should grow to cover chamfer slices and centre-anchored corner pieces. The theme test should generalise to "no hex or RGB literal outside the token file", so the style DNA stays in one place. A performance test in the style of `test-combat-perf.lua` should hold every combat path to a fixed per-call budget with zero garbage. NihilUI already advertises such a budget, so KstyleUI should not ship without one. Each PR should also record an in-game pass with the restriction CVars forced on.

Some rules need adapting. **Off by default** conflicts with what a full UI overhaul is for, and the fix is the onboarding. Code defaults stay off, and a first-run picker (EllesmereUI's pattern) turns on the modules the player chooses. Because a reskin works through hooks, "free while off" means installing hooks on first enable, not at load. A skin turned off mid-session should ask for a reload, because Blizzard frames keep whatever it changed. The Conventional Commits title rule fits the owner's factory rule that every PR title carries its Linear ID. The title regex accepts `feat(unitframes): LEE-123 secure player frame`, because the summary only has to start with a non-space character. The `## Changelog` body rule and the untouched-version rule carry over unchanged. Line endings are the one deliberate deviation worth considering. The purpose of the check is one enforced ending that git never rewrites. On a Mac where agent file tools write LF, enforcing LF with the same `* -text` attribute keeps that purpose with less friction than CRLF. Keep CRLF only if exact parity with NaowhForever matters more.

## Conclusion

Midnight's secret values move the contest between UI suites from data to craft. Every suite gets the same display-only access, so the hard engineering problem in KstyleUI is taint hygiene, and the advantage it can win is motion, depth and typography. The two goals reinforce each other. Engine-driven animation (AnimationGroups, `SetTimerDuration`, duration text bindings, radial progress) is both the cheapest way to animate and the only way to animate values Lua cannot read. A Narcissus-grade feel is therefore something KstyleUI should build into its core architecture from the first module. The research also shows where the risk lies. EllesmereUI's open Forever bugs come from touching Blizzard's secure paths (gamepad bars, paging, Edit Mode), not from styling. KstyleUI will touch more Blizzard frames than any companion addon, so its taint-scan allowlist and its secret-value lint are worth more than any single visual feature.

Forever is also a moving target. The Gethe branch recorded four live builds (70707, 70755, 70790 and 70840) between 4 and 6 November ([commits](https://github.com/Gethe/wow-ui-source/commits/forever)), the `camelot` name may still change, and the Classic and Enhanced presets give players different default frames. A small daily job like NaowhForever's build watch should diff each new `wowf` build of the Gethe branch against the frames and APIs KstyleUI uses. That way a reskinned frame breaks in a pull request instead of in a player's raid.
