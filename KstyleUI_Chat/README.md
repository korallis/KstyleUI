# KstyleUI_Chat

Chat panels, a framed card in the Frames HUD style or bare text on a soft shadow in Orbs, tab names in the caps face with the selected one gilt and underlined, an edit box that shows while typing, copy chat, chat history across sessions, clickable links and class-coloured names.

**The overhaul (KSTY-50).** Lee approved KSTY-44's mock-ups on 2026-11-12: "Chat is a framed card in Frames and bare text on a soft shadow in Orbs, with a setting to override." The `framing` setting is `auto` (follow the HUD style), `card` or `bare`. Auto reads the style the HUD has applied through `KstyleUI.HudStyle.Current()` and switches on its `HudStyleChanged` callback (KSTY-46's contract; without them the chat is Frames). Bare hides the card's material and the rule, lays the kit's soft `shadow` nine-slice behind the text (reaching 36 units past the card, black at 50%), draws the lines with an outline over the kit's shadow when the player has chosen no outline (the world layer), and keeps the tab dock at alpha 0 until the pointer is on the chat. The card follows the mock-up: the tabs in the caps face, the selected one gilt over the gilt underline, the others the dim grey, and a gilt hairline at 35% under the tab row. The chat card is no longer part of the combat calm: its material stays solid in combat, and its lines fade by the client's own chat fading (`SetFading`, `SetTimeVisible`), as KSTY-34 found Lee's card at 72% in a fight. Store migration 23 moves a profile that kept the old `plain` tab style to the underline. The loot feed above the chat follows the same framing.

| --- | --- |
| Module name | `Chat`: its switch in `Core/Features.lua` and the `name` it registers with `KstyleUI.Modules.Register` |
| Approach | Reskin |
| Loads | With the core addon, switched off until the player turns it on |

## Rules

These come from the [design spec](../docs/superpowers/specs/2026-11-07-kstyleui-design.md). The roadmap's Global Constraints and [AGENTS.md](../AGENTS.md) apply too.

- Reskins hook with `hooksecurefunc` or `HookScript`, never `SetScript` on a Blizzard frame. They never write fields onto Blizzard frames, and never call Blizzard functions that open or refresh Blizzard windows. Per-frame state goes in `KstyleUI.Safe.Side(frame)`.
- Blizzard frames keep a reskin after `Disable`, so turning the module off asks the player to reload.
- At load the module only registers itself with `KstyleUI.Modules.Register`. It creates no frames, registers no events and installs no hooks until `Enable` runs. `test-modules-load.lua` checks the frames.
- Every element it shows registers with `KstyleUI.Layout.Register`, and every setting is declared through `KstyleUI.Options.Register`, so the player can resize and customise everything from the settings window.
- UI comes from `KstyleUI.Widgets`, colours from `KstyleUI.Tokens` and strings from `KstyleUI.L`. Translations live in the core string tables; see Languages in the repository README.
- Build mode: check that an API exists before calling it, check `issecretvalue` before any comparison, fall back to a safer path when the preferred one is unavailable, and log the path taken with `KstyleUI.DevTest.Log`.

## Files

`Chat.xml` loads the files in this order:

| File | What it holds |
| --- | --- |
| `Init.lua` | The addon table the files share |
| `Format.lua` | Pure text helpers: timestamps, short channel names, URL links, plain text and class-coloured names. No frames, no game state. |
| `Settings.lua` | The defaults, the module accent and the settings page's rows |
| `Windows.lua` | Finds Blizzard's chat windows, including whisper windows the game opens later, and hands each to the parts once |
| `Stamps.lua` | Chat timestamps through the game's `showTimestamps` setting, and the player's own value back when the module turns off |
| `Messages.lua` | The message pipeline and the dialog that copies a clicked link |
| `History.lua` | Keeps each window's last lines across sessions and puts them back once when the chat starts |
| `Panel.lua` | The glass panel: the `chat.main` Layout element that holds Blizzard's main chat window |
| `Frames.lua` | Restyles every chat window in place: art, tabs, edit box, scroll bar, fonts and buttons |
| `Copy.lua` | The copy-chat window, its Copy button action and the tab menu's Copy chat entry |
| `Preview.lua` | The live preview on the settings window's Chat page |
| `Module.lua` | Registers the module and its settings page, and starts and stops the parts |

Tests: `Tools/regression/test-chat-format.lua` (the text helpers), `test-chat-messages.lua` (the pipeline), `test-chat-stamps.lua` (timestamps through the game's setting), `test-cvars.lua` (the core's restore at login) and `test-chat-panel.lua` (the panel and the window skins) and `test-chat-copy.lua` (the copy window, its button and menu entry, and the preview) and `test-chat-history.lua` (history across sessions) and `test-chat-parity.lua` (the parity options, on and off) and `test-chat-parity-r2.lua` (the button column's round-two options and tabs above the card, on, off, at four screen sizes and on their events), against stand-ins for Blizzard's chat in `Tools/regression/chat_env.lua`.

## Message pipeline

| Feature | How |
| --- | --- |
| Web addresses | A filter on each player chat event through `ChatFrameUtil.AddMessageEventFilter` rewrites the message text. `Format.Linkify` wraps `http`, `https`, `ftp` and `www.` addresses, bare domains with a known top-level domain, and IPv4 addresses in an `addon:KstyleUI:url:<address>` link in the accent colour. Text inside item links, textures and other escape sequences is never touched. |
| Clicking a link | Blizzard routes `addon:` links to `EventRegistry`'s `SetItemRef` event. The module opens the kit's `Popup` with the address selected, ready for Ctrl+C. |
| Class-coloured names | A sender-name filter through `ChatFrameUtil.AddSenderNameFilter` colours the name from `GetPlayerInfoByGUID` with `Theme.ClassColor`, brightened by `Theme.Brighten`. A name the game already coloured is left alone. |
| Timestamps | `Stamps.lua` writes the `timestamp` and `timestampColor` settings into the game's `showTimestamps` CVar as `\|cffRRGGBB[%H:%M]\|r `. Blizzard's chat puts that in front of each chat message as it builds the line (`TimeUtil.BetterDate`), so the module rewrites no line for its timestamp. See [Timestamps](#timestamps). |
| Short channel names | A `hooksecurefunc` post-hook on each chat window's `AddMessage` computes the decorated line and swaps it in through the window's own `TransformMessages`, only when the line changes. The combat log is skipped. |

## History

`History.lua` keeps each chat window's newest lines in KstyleUI's own saved variables (`KstyleUIDB.account.chatHistory.characters[<character>][<window name>]`), so a reload or a relog starts with the chat the player left. Each line is saved as the player saw it: `Messages.lua` hands it the finished line (short channel names and timestamps applied) from its `AddMessage` post-hook, with the line's colour. A saved line is plain text and three colour numbers.

- Never kept: a secret line, a line with a Battle.net name (`|K`, which the game encodes per session), and the combat log.
- Bounded: `historyLines` per window (default 100, 10 to 500); the oldest line goes first. Lowering the setting trims what is saved.
- Restored once per UI load, when the chat module starts: each window gets its lines back, oldest first, through its own `AddMessage`, then one muted line, "Chat from your last session". `Messages.lua` leaves restored lines as they are, and they are not saved twice.
- Off: `history = false` keeps and restores nothing, and turning it off forgets this character's lines.

## Timestamps

| Case | What happens |
| --- | --- |
| The module turns on | It writes its value into `showTimestamps`, out of combat (`Combat.Queue`). An unchanged value is not written again. |
| A setting changes | The value is written again. `none` or a format not on the list writes `none`. |
| Turned off | The player's own value comes back. The module keeps it in `KstyleUIDB.account.chatTimestamps[<character key>]` as `{ original, written }`, because the CVar is saved per character. A value that differs from `written` when the module starts is the player's own. |
| Off at login on this character | The module was turned off in a shared profile while you played another character, so this character's `showTimestamps` still holds KstyleUI's value. The core's [`CVars` service](../docs/core-services.md#cvars) puts the player's value back at login, out of combat, and clears the memory. A refused value keeps the memory for the next login. |
| `VARIABLES_LOADED` after the module started | The client loaded the character's saved CVars late. The module takes that value as the player's and writes its own again. |
| A change in Blizzard's options (`SettingsPanel` shown) | One of the game's six formats, or `none`, becomes the `timestamp` setting, and the module writes it back in its own style. Any other value is not taken. |
| Any other change (`/console`, another addon) | The module writes its own value back on the next frame. |
| The client drops the colour codes | The module writes the plain `[%H:%M] ` and logs it once. |
| The client refuses the value, or has no `C_CVar.SetCVar` | The player's value stays. The module puts its own timestamp on each line through `TransformMessages`, only while the game's setting is `none`, so a line never gets two. |
| A format is on, and the line is system, loot, level-up or another type the game does not stamp | The game's `MessageEventHandler` (`Blizzard_ChatFrameBase/Mainline/ChatFrameOverrides.lua`) stamps only the player-chat path and pings. Level-up lines go through `ChatFrameUtil.DisplayLevelUp` (`Camelot/ChatFrameUtilOverrides.lua`) with no stamp. The 20:22 screenshot was those lines, so a saved format showed nothing. KstyleUI stamps a line the game left bare and leaves a line that already starts with a stamp, so the setting and the chat agree. |

`Stamps.GameDraws()` tells `Messages.lua` whether the game is drawing timestamps. It reads the CVar once after each `CVAR_UPDATE` that names it, not on every line. The module's own writes set a flag around `SetCVar`, because `CVAR_UPDATE` fires inside the call.

## The panel

`Panel.lua` builds a plain holder frame and registers it with Layout as `chat.main` (label from `Setup.Layouts`, module `Chat`), resizable from 260 by 120 to 1000 by 800 units, at the setup's position: 186 units high at the bottom left in every layout, 393 wide in DPS and Tank and 318 in Healer (the rail width, so six tracked bars still fit beside it), on the `screenMargin` token (LEE-20: the picture wins over #210's 372 by 260; LEE-69: 186 is the picture's card edge, 1880 to 2204 px on its 2234 px screen, the 200 of the first measurement counted the loot feed's `+ 14c` line above it). A saved card at the old 393 by 200 or 318 by 200 takes the new height in migration 16; a card the player resized keeps its size. Layout gives it the element settings: position, size, shown rule, opacity in and out of combat, and strata.

The glass is a `Widgets.Panel` child of the holder that fills it, in the `BACKGROUND` strata with `SetFixedFrameStrata(true)`, so a strata the player picks for the element never lifts the glass over Blizzard's chat, whose windows and dock stay in their own strata.

Blizzard's `ChatFrame1` is anchored inside the holder by two points, so it follows every move and resize:

| Part | Where, in root units at the 1080 reference |
| --- | --- |
| Tabs | A 34-unit row. Names are in the caps role (Folio Caps, tracked by its font file), size 10, the selected one `capsGold` over the gilt underline and the others `dim`, with a gilt hairline at 35% under the row (the overhaul's mock-up). The plain and filled styles stay in the setting. The settings window's preview paints its tabs with the live chat's own look (`Frames.TabLook` for the text colours and which piece shows, `Frames.PaintUnderline` and `Frames.PlaceGlow` for the gilt underline and its glow, `Panel.PaintRule` for the hairline), so the HUD, the preview and the gallery draw one design in every style (KSTY-60 item 28, `test-chat-tabs.lua`). |
| Glyphs | The plus and the copy glyph stay at the row's right end, level with the tab labels, but they are hidden at rest and show while the pointer is over the card, as the minimap's controls do. Both are 8 units across in the accent with 20-unit hit areas. The dock still ends before them, so a hover never covers a tab. |
| Messages | The window fills the card's inner area (KSTY-33): the card's padding (`gapMedium`, 16 units) on the left, right and bottom, under the tab row, 34 units, or further down at a small interface size, where the tabs rise higher above the window and their buttons must stay inside the card. With `editBox` at `always` its strip sits under the window, inside the same bottom padding. The scroll bar stays Blizzard's own and is not moved: its alpha is 0 until the cursor is over the window (`ChatFrameOverrides.lua:45`, `FloatingChatFrame.lua:1212`), so no track draws at rest. The panel anchors the edit box to the window's own left and right edges (5 units left, 8 right), so its tile shares the window's side edges whatever the scroll bar does. The window's rect is the card's inner rect to one physical pixel at every screen size and size setting. The tab dock rides the window's top edge and the tab names start on the window's left column (LEE-20). The names keep `13.5` units after the ink, which with the dock's 1-unit gap is the picture's 30 px. Whole lines (LEE-69): the game stacks each line a pitch (line height plus `GetSpacing`) above the one below it from the window's bottom edge and its `FontStringContainer` clips at the window's edge (`ScrollingMessageFrame.lua:595-602`, `ScrollingMessageFrame.xml:10`), so the window shows no cut line when the room above the last whole line is no more than one spacing. `Panel.Geometry` takes the most lines the `lineSpacing` setting allows (it may give up whole pixels, never below one), then spreads the room left over into the spacing in whole physical pixels, so `lineSpacing` is the least spacing between lines and the card's height decides the rest. The card is 393 wide in DPS and Tank. Healer keeps the 318 rail width, at the same 186 height, so six tracked bars still fit beside it. The module never calls `ChangeChatColor`. |
| Edit box | Blizzard keeps it under the window. With `editBox` at `typing` the panel keeps no room for it: it anchors the box of every docked window over the window's last lines, its tile resting on the bottom padding, so the box opens inside the card on every screen and at every card position. A window opened or docked later gets the same anchors on the next frame (the `FCF_DockFrame` hook queues the placement), and an undocked window keeps Blizzard's place under its own glass. With `always` the panel keeps the room under the window: the tile is 22 units tall and rests on the card's bottom padding. |

The offsets come from Blizzard's own geometry in the chat window's units (`FloatingChatFrame.xml` and `ChatFrameEditBox.xml`: the tab text 14 units above the window, the dock 3 units above it, the edit box 32 tall, starting 5 units left of the window and ending 8 past the scroll bar, 2 units below the window by default; the panel anchors it to the window's right edge instead), converted through the ratio of the chat window's effective scale to the panel's and snapped to whole physical pixels. They are worked out again on `ScaleChanged`. The line pitch is the font's own line height plus the `lineSpacing` setting, which goes through the window's `SetSpacing` (`ScrollingMessageFrameSecureMixin` in Forever's `ScrollingMessageFrame.lua`; its lines anchor one spacing apart).

The panel's visibility and opacity carry over to Blizzard's chat: hooks on the holder's `Show`, `Hide`, `SetShown` and `SetAlpha` set the same alpha on `GENERAL_CHAT_DOCK` (the tabs) and every docked window. While the box shows only when typing, the panel anchors it over the window's last lines, its tile resting on the bottom padding, so it opens inside the card on every screen (Blizzard hangs it below the window, past the card's edge); with `always` it keeps Blizzard's place under the window. Nothing in `Blizzard_ChatFrameBase` calls `SetPoint` on the box after load, and the panel anchors it again whenever it places the window. An edit box, which Blizzard fades itself, is at alpha 0 with its mouse off until the player types in it, when it shows at Blizzard's own alpha and takes the mouse again; with `editBox` at `always` a docked window's box keeps Blizzard's alpha times the panel's instead. A window that leaves the dock gets full alpha back, a window opened into the dock takes the panel's at once, and turning the module off puts everything back.

## Copy chat

The copy window is a `Widgets.Panel` titled "Copy chat - <tab>" in the `DIALOG` strata, with a read-only `Widgets.TextArea`, a **Select all** button and a hint. It registers with Layout as `chat.copy` (module `Chat`), resizable from 320 by 200 to 1400 by 1000 units, 560 by 380 by default, 40 units above the centre. Dragging its title bar saves a `CENTER` position through `Layout.Update`. Escape closes it.

| Way in | Window it copies |
| --- | --- |
| The copy glyph beside the plus at the right end of the panel's tab row | The selected docked window. The glyphs fade with `ChatFrame1Tab`, as Blizzard fades the tabs. |
| **Copy chat** in a chat tab's right-click menu, added with `Menu.ModifyMenu("MENU_FCF_TAB", ...)` | That tab's window |

It shows every line in the window's history, oldest first, as plain text: `Format.Strip` drops colours, textures and atlases and keeps link text. A secret line becomes "(a line the game keeps hidden)". The text scrolls to the end and is selected, ready for Ctrl+C.

## Preview

The schema's `preview` builds a small glass panel with three sample tabs and four sample lines (guild, a numbered channel with a zone, party with a web address, and a loot line). `Refresh` redraws it from the current settings: glass opacity and shadow, font, sizes and outline, tab style, case and accent, timestamps, channel names, class colours and links. With the chat buttons on it draws them as kit tiles (the menu with the plus glyph, the scroll button with the chevron) in their order, size and spacing, on the card, on their own strip or beside it, and moves the card under the tabs for `tabsAbove`. A freely moved button's tile sits at its spot against the column's top left, kept inside the preview, and the strip hides in the bare framing as the card's does.

## Why

- Secret values: under chat restriction the game hands addons secret message text and names. Every filter and hook checks `issecretvalue` first and passes a secret on untouched: the filter returns `false` with no replacement, the name filter returns `nil`, and the `AddMessage` hook does nothing. Blizzard's own filter registry also skips addon filters when an argument is secret; the module does not rely on that.
- No protected chat function is replaced or hooked. The send path (`ChatEdit_SendText`, the edit box's `OnEnterPressed`, slash commands) is never touched, so `/cast` and other secure commands typed in chat stay secure.
- No field is written onto a chat window. `AddMessage` is hooked with `hooksecurefunc`, the one change the spec allows. Rewriting a line goes through `TransformMessages`, which `ScrollingMessageFrameSecureMixin` exposes for addons as a secure elevation barrier, instead of replacing `AddMessage` or the `CHAT_*_GET` strings.
- The channel shown in a numbered channel line cannot be shortened in the event filter: Blizzard matches the channel argument's length against the window's channel list after the filters run, so a shorter name would drop the line. The module rewrites the finished line instead.
- `TransformMessages` walks the window's history in its buffer's slot order, not by age, once per new line. The predicate matches only the newest slot, which the window's `historyBuffer:CalculateElementIndex(1)` names, so an older identical line is never rewritten in its place. A client without that function falls back to the first line with the same text, and the devlog says so. A line costs one pass over at most a few hundred entries; the combat log, the busiest window in combat, is skipped.
- A clicked link replaces any link dialog still open or queued behind another dialog, and its address is selected whenever its dialog takes focus, so Ctrl+C copies it even when it had to wait.
- Links use the `addon:` link type because it is the one Blizzard routes to addons (`LinkUtil` hands it to `EventRegistry`); any other unknown type falls through to the item tooltip.
- Build mode: each missing API (`ChatFrameUtil`'s filter registries, `TransformMessages`, `EventRegistry`) is logged once to the devlog and its feature switches off; the rest keeps working.
- Placing Blizzard's chat: the chat is a reskin, so the messages, tabs and edit box stay Blizzard's own frames and every secure chat path keeps working. To let Layout move and resize it, the module anchors `ChatFrame1` to its panel. Edit Mode replaces `ChatFrame1`'s `SetPoint` and `ClearAllPoints` with overrides that update the Edit Mode manager, so calling them from addon code would run Edit Mode in a tainted call. The module calls `SetPointBase` and `ClearAllPointsBase`, the widget methods Edit Mode keeps, and falls back to `SetPoint` only on a client without them. Layout itself never moves the Blizzard frame.
- When Blizzard anchors `ChatFrame1` again (Edit Mode applying a layout), a `hooksecurefunc` on its `SetPoint` puts it back in the panel on the next frame. While Edit Mode is open the module waits, and `EventRegistry`'s `EditMode.Exit` brings it back.
- `ChatFrame1` is not protected, so it can be placed in combat. If a client ever makes it protected, placement waits for `Combat.Queue`.
- Blizzard's chat functions that select tabs, resize the dock or change windows (`FCFDock_UpdateTabs`, `FCF_Tab_OnClick`, `PanelTemplates_TabResize`) are never called: running them from addon code would taint the dock and the edit box behind it, the failure other suites hit as chat tabs dying on a protected table. The module only hooks them after the fact.
- Upper-case tab names are set with the tab's `SetText`. The game sizes each tab from its text the next time the dock lays out its tabs, which anchoring the window into the panel triggers at once.
- The button column is reparented through `Safe.HideBlizzard`, not hidden, because Blizzard lays it out and fades it.
- Copying: secret lines cannot be concatenated into the copy text without making the whole text secret, so each one is replaced by a placeholder line. Messages are read with the window's own `GetNumMessages` and `GetMessageInfo`.
- The tab menu entry uses `Menu.ModifyMenu`, the hook Blizzard's menu system offers addons, so Blizzard's menu builder is never replaced. Its handle is unregistered when the module turns off. A client without it logs that the entry is missing; the Copy button still works.
- The glyphs' room is taken from the messages' width so the dock's tabs and its overflow button never run under them.
- The plus opens the module's settings page because the module cannot do what a plus on a chat strip usually does: `FCF_NewChatWindow` and the chat menu are Blizzard functions that open Blizzard windows, and running them from addon code would taint the dock.
- The invisible resting box also has `EnableMouse(false)`, so a click under the messages reaches the world instead of waking the box; the mouse comes back with focus, with the `always` mode and when the module turns off. The edit box is never hidden or shown by the module: Blizzard's own `Deactivate` hides it only in the `classic` chat style, and writing the `chatStyle` CVar would run Blizzard's chat-style handlers from addon code; in that style `always` cannot bring the resting box back and keeps only its room. The module sets the box's alpha instead, the one call it already makes to mirror the panel's opacity, and the game's activate path (`ChatFrameUtil.ActivateChat` sets alpha 1, then focuses the box) brings it back through the focus hooks.

With Leatrix Plus loaded and `LeaPlusDB.RestoreChatMessages == "On"`, Existing addons switches Keep chat across sessions off once per profile before history restores. Turn it back on to prefer KstyleUI; the choice survives reloads. The other chat features stay on, and Other-addon notices controls the explanation. See the [QoL compatibility notes](../KstyleUI_QoL/README.md#leatrix-plus) for the public source.

### Parity round 2 (2026-11-20)

The last ten rows move to Present: every chat parity row that fits is built. Every new option is off or at today's value, and the chat buttons are off by default, so the default chat is pixel-identical; with the buttons on and the new options at their defaults the column is the game's own stack, anchor for anchor.

- **The column** is laid out by `Panel.Place`, which runs on the chat's own layout triggers (the element's size and place, docking, Edit Mode leaving, the scale) and waits for `K.Combat` when the chat window is protected. `Keep` records each frame's points and scale (and the column's width) before the first change, and `Release` gives them back when the buttons or the chat turn off.
- **Backing** keeps the strip and the gap inside the `chat.main` element: the card's glass leaves the strip and the gap on the buttons' side, and the column sits on the strip with the card's padding on both sides. The strip is a second `Widgets.Panel` in the card's material, opacity and shadow, made the first time it is chosen; it hides with the buttons on hover and fades with the card when idle.
- **Size** is fitted in `Panel.Geometry`: above 1 the scale stops where the friends button and the stacked buttons, with a gap after each, fill the card's height, and the room beside the messages is at least the 32-unit button times that scale, so the room, the strip and the column all widen with it. `Keep` refuses a frame whose scale, width or anchors are secret (`SimpleRegionAPIDocumentation.lua:54`), so it is left to the game, and a scale is written only when it changes.
- **Free move** hooks `OnDragStart` and `OnDragStop` once per button and registers the drag only when the switch changes. A drag needs Shift and the combat check (a missing `InCombatLockdown` refuses it), `SetUserPlaced(false)` keeps the spot out of the game's layout cache, and a secret or missing rect drops the drag. The alert container re-anchors the friends button on its own (`AlertFrames.lua:57-64` and `:417-426`, registered at `QuickJoinToast.lua:16-17`), so a hook on `ChatAlertFrame:UpdateAnchors` puts a saved friends spot back.
- **Hidden buttons**: the voice toggles show only while the player is logged in to voice (`VoiceToggleButton.lua:17-21`). The column stacks only shown buttons, and `OnShow` and `OnHide` on each stacked button reflow it.
- **Scroll button**: Blizzard anchors the scroll bar's foot to the jump-to-bottom button (`FloatingChatFrame.lua:111-112`, and `FCF_UpdateScrollbarAnchors` at 1155-1167), so the anchor that followed the moved button moves to the window's corner, the game's own third choice; an unlocked secondary window's bar that follows its resize grip (`:1162-1163`) is left alone. A hook on `FCF_UpdateScrollbarAnchors` repeats this after the game's update, and giving the button back restores that one anchor exactly. The moved buttons join the hover rule; the game fades them through `UIFrameFade` (`FCF_FadeInScrollbar` and `FCF_FadeOutScrollbar`, `:1212-1235`), so a `SetAlpha` hook holds a hidden button at 0 and keeps the game's newest alpha for the pointer's return.
- **Tabs above the card** moves the card's top edge to the tab row's foot. The plus and copy glyphs are the holder's children at the glass's level, so they stay drawn when the card no longer reaches them.
