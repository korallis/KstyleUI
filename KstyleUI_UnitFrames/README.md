# KstyleUI_UnitFrames

Player, target, target of target, focus, focus target, pet and boss 1 to 5. Portraits (switchable), cast bars, frame auras, class resources, threat glow, raid markers, leader and role icons.

| Field | Value |
| --- | --- |
| Module name | `UnitFrames`: its switch in `Core/Features.lua` and the `name` it registers with `KstyleUI.Modules.Register` |
| Approach | Replace |
| Loads | With the core addon, switched off until the player turns it on |
| Files | `KstyleUI_UnitFrames.toc` lists `UnitFrames.xml`, which loads every Lua file in order, so adding a file never edits the TOC |

## Rules

These come from the [design spec](../docs/superpowers/specs/2026-11-07-kstyleui-design.md). The roadmap's Global Constraints and [AGENTS.md](../AGENTS.md) apply too.

- Unit frames use `SecureUnitButtonTemplate` buttons with `RegisterUnitWatch`. Health goes straight to the bar with `SetMinMaxValues(0, UnitHealthMax(unit))` and `SetValue(UnitHealth(unit))`. Health text comes from `UnitHealthPercent` or `AbbreviateNumbers`, never from Lua arithmetic. A bar's low-health red and the vitals glow take their alpha from `C_CurveUtil` curves over `UnitHealthPercent`, handed to `SetAlpha`. Incoming heals come from `CreateUnitHealPredictionCalculator`. Range fade uses `SetAlphaFromBoolean`.
- Combo points draw as one-point status bars, so the comparison happens in the engine.
- Cast bars use `StatusBar:SetTimerDuration` with the duration object from the cast APIs. Casts by units other than the player and pet can be secret, so the bar never reads the spell name except through widget setters.
- Auras use the AuraContainer engine (`CustomAuraContainerTemplate`, aura groups and filter strings). Never scan auras by index while `C_Secrets.ShouldAurasBeSecret()` returns true. Aura data turns secret during a boss pull before `InCombatLockdown()` returns true.
- Player and target frames are 220 by 70 units at the 1080 reference, the owner's mockup's 279 by 90 proportions with the portrait as tall as the frame, at the scale the owner's in-game test of 2026-11-08 asked for: under two 38-unit action buttons tall, where the mockup's 89 dwarfed the bars. They sit above the action bars on either side of the Cooldown Manager, flanking its essential row. Portraits are on by default, with a switch to turn them off.
- Blizzard frames this module replaces are hidden only through `KstyleUI.Safe.HideBlizzard`.
- At load the module only registers itself with `KstyleUI.Modules.Register`. It creates no frames, registers no events and installs no hooks until `Enable` runs. `test-modules-load.lua` checks the frames.
- Every element it shows registers with `KstyleUI.Layout.Register`, and every setting is declared through `KstyleUI.Options.Register`, so the player can resize and customise everything from the settings window.
- UI comes from `KstyleUI.Widgets`, colours from `KstyleUI.Tokens` and strings from `KstyleUI.L`. Translations live in the core string tables; see Languages in the repository README.
- Build mode: check that an API exists before calling it, check `issecretvalue` before any comparison, fall back to a safer path when the preferred one is unavailable, and log the path taken with `KstyleUI.DevTest.Log`.

## Medallions aura layout

Medallions defaults to **Rows above frames** under Unit Frames > Aura layout. Your buffs stand above your own medallion, aligned to its outer left edge, when Unit Frames > Player > Auras is on (off by default, since the Auras rows by the minimap already show them); your target debuffs (`HARMFUL|PLAYER`) stand above the target medallion, aligned to its outer right edge. The existing native aura row builder wraps upward after six 28-unit chamfered tiles, with two rows by default (on the target, one of each kind with Debuffs and buffs, so the block keeps the same room under the target of target; a saved row count still applies to each kind, so more rows can reach the target of target), engine-bound timers below the tiles and stack counts in the corner. The player's Medallions aura visibility and filter are separate from the Frames choices. Auras remain native engine frames: layout and restyling wait for combat and secret restrictions to open.

**Crest fan** restores the original seven rank windows, geometry, expiry order, tiles, timers and counts. Its existing target toggle still controls the independent fan. Switching layouts caches both native pools and builds the fan only when selected. Existing profiles start with rows, except profiles with a saved crest-fan position: migration 42 selects the fan and preserves the entire position and scale. A scale change alone does not opt out. Saved positions of other elements are never rewritten.

## Medallions crest debuffs

After selecting Crest fan, Unit Frames > Target > Your target debuffs above the crest controls the independent fan (enabled by default). Under Medallions, seven 28-unit chamfered tiles show every `HARMFUL|PLAYER` aura on the target, including control effects; the native `PLAYER` filter also includes your pet and vehicle. The fan is independent of the target frame's Auras switch and Which auras selection, including Buffs only. The target frame keeps its chosen aura set minus the fan's set: Your debuffs leaves no medallion debuffs; All debuffs or Both leaves other players' debuffs and any selected helpful group. Turning the fan off restores the target's existing aura filter. Frames uses its existing paths throughout.

The earliest expiry occupies the apex; subsequent expiries alternate left and right at 18-degree steps. Each clipped window reveals its rank from a native AuraContainer capped at that rank (1 through 7), with the same `ExpirationOnly` comparator. Native flow layout, filtering, updates, cooldown sweeps, text bindings and optional pandemic regions handle secret data. Lua never reads aura identities, counts, time values or region state, and never repositions a button during combat. The shared native-anchor overflow chip counts excess auras. The extra native containers are bounded; there is no Lua aura scan or update loop.

Each rank shares one lazy metal rim on a public frame; native anchors align it with the visible tile and clip it away when empty. The rim builds on first show, including in combat, while engine buttons keep their icon, cooldown, timer, stack and pandemic bindings ready. Font and inset inputs resolve once per styling pass without reading restricted button state.

The `unitframes.crestDebuffs` Layout Mode element moves and scales the fan independently, starting above the default crest and the cast bars. Layout resolves its default position again on display/aspect changes while preserving the player's saved position and scale. Timers use the target aura face at 10 to 12 units; the existing frame layout callback reapplies the physical text floor after scaling. Theme restyles and first construction wait for the existing aura gate. If engine construction fails, the target's original aura display remains active and the reason goes to the devlog.

Each rank window sets `SetClipsChildren(true)`. Native clipping excludes children outside the viewport from drawing and mouse interaction (the documented API is in Forever's `SimpleFrameAPIDocumentation.lua`; the reported clipping/mouse fix is https://www.wowinterface.com/forums/archive/index.php/t-54778.html). Buttons remain owned and reordered by the native engine (`Blizzard_AuraContainerGroups.lua`), so creation order is not a safe rank identifier. No combat-time button inspection or mouse-state write is used. The client hit-test implementation is not in the UI-source repository: verify in Forever that every icon's tooltip matches, including the apex beside container 3's clipped second button, after expiration reorders, target changes and Layout scaling, both in and out of restricted combat.

- **Colours.** The `healthColor` choice `hud` (the default for both): the player's own health is `hudPlayerHealth`, a hostile unit's `hudTargetHealth` (a reaction of 3 or less), a friendly unit its reaction colour. Every health and power bar of every form is the kit's clean `Widgets.UnitBar` (Core/Widgets/README.md, UnitBar; KSTY-47, replacing the LEE-71 ramps, inner `powerEdge` and flush backing): one black pixel and one 45% black pixel outside the bar, the dark `barTrack` track, a fill shaded by colour-free overlays, the pale band for health just lost, the hit flash and the spark. Below 35% a friendly unit's health shows a `healthLow` fill whose alpha is a step curve over `UnitHealthPercent`; a hostile, disconnected or tapped unit keeps its own colour. Column mana uses `hudMana`; other power types and non-column styles keep their engine-derived colours. The cast fill is the `gilt` token, flat, with a two-pixel black edge inside the painted box. Player and target textures default to Flat. Store migration 15 converts a saved Glass key or path to Flat once for their column styles (including an omitted default style); other kinds, explicit legacy styles and custom textures remain untouched. The picker and paint use the same stored value, so selecting Glass after migration draws Glass on the fill, under the same edge and shading. The column power height is `COLUMN.power` (8), like the health height. The power slider stays at 7, step 1, and still drives lumen, plate, card and row. It is hidden while the style is column, so the page does not show 7 for a bar that paints 8. A saved height, including 7, is left alone.
- **Percent text.** `UnitHealthPercent(unit, true, curve)` with a 0 to 100 curve (`C_CurveUtil.CreateCurve`, or `CurveConstants.ScaleTo100` when it is missing) goes straight to `FontString:SetFormattedText`; the result can be secret, so nothing reads it. Source for build 1.60.1.70862: `Blizzard_APIDocumentationGenerated/UnitDocumentation.lua` (`UnitHealthPercent`: `SecretReturns`, arguments `unit`, `usePredicted`, `curve`; `UnitCreatureType`; `UnitCastingDuration`, `UnitChannelDuration`), `LuaDurationObjectAPIDocumentation.lua` (`GetElapsedDuration`, `GetRemainingDuration`, `GetTotalDuration`), `SimpleFontStringAPIDocumentation.lua` (`SetFormattedText` takes secret arguments) and `Blizzard_SharedXMLBase/CurveConstants.lua`.
- **Cast times.** The cast bars' times come from the duration object's `GetElapsedDuration`, `GetTotalDuration` and `GetRemainingDuration`, handed to `SetFormattedText` without a read. A cast with no duration object falls back to the cast times in milliseconds, which are read only when they are plain numbers.
- **Clicks.** The portrait stands outside the secure button, so `Frames.Relayout` widens the button's hit rect with `SetHitRectInsets` (`SimpleFrameAPIDocumentation.lua`: a protected function). `Relayout` queues itself through `KstyleUI.Combat.Queue` in combat, so the insets are never written under lockdown.
- **Reach.** `Geometry.Reach(s)` is how far the portrait and the side auras stand outside the element at the left and the right; `Frames` shifts a saved position that would put them off screen, and the preview fits the pane to them.
- **Cast bar element.** `CastBars` draws a bar in `above` mode (the element) or `below` mode (inside the target's column). Under Frames, `Spell name inside the bar` (per frame, on by default for the player and the target, the finish plan's H1) uses `inside` mode instead: the 14-unit bar keeps its place, the spell and the timer ride inside it at the cast size with at least a thin outline, and the label's row stays free; off brings back `above` and `below`. The near-white label takes the tracked `names` face through `Widgets.ApplyFont`; the face supplies its spacing without thin spaces. Unsupported scripts fall back through the kit's locale font mapping. Both cast labels default to 12 units.

### LEE-71 optical finish

The owner's LEE-20 picture ruling also governs paint, not just reserved rectangles. The acceptance pass's 135-pixel portrait measurement includes the level disc: the main ring is approximately 122 pixels and its disc 47 pixels. The Captain confirmed this correction on 2026-11-10. The 70-unit ring plus 21.5-unit gap retains the previous 91.5-unit outside reserve, so neither bar column, hit reserve nor side-aura start moves. Cropping the ring and disc textures' two-pixel transparent gutter (`2/128`) makes their painted diameter match the frame. Legacy styles restore the full texture coordinates. The level number stays on its configured face, centred on the new disc, with a 0.95 optical size factor; class/creature captions and unit names are unaffected.

Target aura text defaults to 12 units with a four-unit below-tile gap in column mode; other forms retain the previous gap and explicit font choices remain selectable. Cast tracks remove the decorative spark and outside keyline, use the actual Flat fill rather than only hiding lit/shade overlays, and keep the original reserved heights and duration-object behavior. The target's thicker paint consumes one unit of its old label gap rather than moving the column.

`test-unitframes-centre-finish.lua` pins paint, colours, ring/disc geometry, legacy restoration and physical-pixel snapping across the nine acceptance screens. `SimpleTextureBaseAPIDocumentation.lua:580` in Forever 70862 (`9dc84f0`) proves `Texture:SetTexCoord(left, right, bottom, top)` and allows tainted secret arguments; these crop coordinates are plain constants. All other operations use existing module/kit interfaces. No new API, event or template is introduced, and the combat queues and secret-value paths are unchanged.

- **Low health.** The vitals ring has a glow behind it (`view.ringGlow`, the `glow` texture in ADD blend), tinted `healthHostile`. `Unit.Glow` passes a `C_CurveUtil.CreateCurve` curve (0 at full health, rising to 1 at none) to `UnitHealthPercent(unit, true, curve)` and hands the secret number straight to `SetAlpha`, which takes secrets (`SimpleRegionAPIDocumentation.lua`). It never indexes the curve's answer, which may itself be secret (KSTY-47). Nothing compares the health. Without the curve API the glow stays off, and the devlog says so once.

Each frame is a plain holder frame registered with `KstyleUI.Layout.Register` under its key, with the setup's label, `module = "UnitFrames"` and `resizable = true`. The holder carries one `SecureUnitButtonTemplate` button per unit (five for the boss frame). The button has the attributes `unit`, `type1 = "target"` and `type2 = "togglemenu"`, registers for `AnyUp` clicks and is shown and hidden by `RegisterUnitWatch`. Layout moves and sizes the holder; the module anchors the buttons inside it and lays out their parts again whenever the holder's size changes. Hovering a button shows the unit tooltip through Blizzard's `UnitFrame_OnEnter` and `UnitFrame_OnLeave`.

Every frame follows the kit sheet, [`docs/design/mockups/05_kit_hunter.jpg`](../docs/design/mockups/05_kit_hunter.jpg). The accent there is the hunter's green; in game it is the player's class colour.

- **Glass.** One `Widgets.Chrome` panel: chamfered corners, the double-line bevel and a soft shadow. With a portrait, the glass starts under the portrait's centre, so the portrait overlaps its outer end and stands proud of it. On a full frame its far-end chamfer is an eighth of its height, the design file's 8 units on a 64-unit panel; the compact kinds (target of target, focus target, pet) use the tile chamfer. The glass sits inside the frame's top and bottom by 2 units under a chamfered portrait (the design file) and by 0.06 H under a round one, so the panel's lines meet the ring where the owner's mockup joins them.
- **Portrait.** `round` (the default, the owner's mockup): the round mask, the `buttonFill` disc and the ring in the accent. `chamfered` (the design file): a `Widgets.Chrome` frame filled `buttonFill` with a chamfer 15% of its size, its inner bevel line in the accent lifted 15% towards white, with the 2D portrait drawn square (`SetPortraitTexture` with `disableMasking`) and masked by `portraitMask`, which cuts the same 15%. The image draws in the `BORDER` layer under the bevel lines, so its corners never cover them.
- **Level badge.** A regular octagon (a panel-chamfer chrome whose chamfer is `1 / (2 + sqrt 2)` of its size), filled `buttonFill` (the mockup's badges measure #101214), straddling the portrait's bottom outer corner so it stands below the portrait's bottom edge. Under a chamfered portrait it is 36% of the portrait with its centre 0.19 P in and 0.125 P up from the corner, with a neutral `text` line, as measured on the design file. Under a round portrait it is 37% of the portrait centred on the ring's lower outer point (0.196 P in and up), with its line in the accent like the ring, as on the mockup.

A frame 36 units tall or more is a full frame. Its column starts at the portrait's edge with no gap, as the design file's panel line is the portrait's border line. Its side insets are shares of the frame's height `H`: under a chamfered portrait the column starts `0.147 H` past the portrait and ends `0.2 H` before the glass's far end (the design file's 10 and 13.5 units on 68); under a round one `0.085 H` and `0.15 H` (the mockup's 7.5 and 13.5 units on 90). The vertical rhythm is a share of the glass's height `G`: the name's row starts `0.095 G` below the glass's top under a round portrait (the mockup's capitals sit 9 units down on a 77-unit glass) and `0.15 G` under a chamfered one (the design file), the rows are `0.1 G` apart, and the last row ends `0.14 G` above the glass's bottom edge. The two side paddings never take more than 40% of the panel beside the portrait, so a narrow frame keeps its track. Inside the glass, from the top:

1. The name, left-aligned, in capitals when `nameCaps` is on. The default tracked face supplies the spacing; another font receives thin spaces only when `Locale.TrackMode` answers `"space"` (KstyleUI's own Alegreya Sans Tabular files) and the locale confirms the glyph. Source Sans 3, Inter and fonts from other addons get none. A secret name goes straight to `SetText`. The level sits at the right of this row when there is no portrait.
2. The health track, then the health text after it: the text's column is `Format.ColumnWidth` of the format shown at the track's end (`Format.Shown`: `percent` for `both` while the row under the track fits, `currentMax` when the game has no percent curve) and the health font, at least 28% of the column under a round portrait (the mockup's bar takes 72%), right-aligned to the column's far edge; the track takes the rest minus a 4-unit gap, so the fill never runs under the numerals. When that would leave the track less than half the column (a narrow frame, or a long fallback text), the text sits over the track's right end instead. The track takes the height the other rows leave, about `0.19 G` at the defaults. Its fill takes the bar colour, the kit sheet's red (`healthHostile`) for a hostile unit, and its track is `buttonFill`, the mockup's dark track. The health text is a light version of the bar colour (85% of the way to white, as the kit sheet's near-white numerals) with the soft shadow. A secret colour is never mixed: the text then stays `textEmphasis`.
3. A hairline under the track and the health text (`edgeBar`, the bar grade's white at 16%, one border thick, 2 units below the track), as the design file draws it, when a row or the power bar sits under the track.
4. A row under the track, as the owner's mockup draws it: the power bar at the left, a short bar 37% of the column and `powerHeight` tall (7 by default), its fill the power type's colour (the owner's ruling of 2026-11-08: mana blue, rage red, energy yellow; the mockup's class-coloured rage bar is the `class` choice) and its track `buttonFill`, the mockup's dark #101214 track like the health bar's, hidden with its text while the unit's max power is a plain zero (a crocolisk has no power; a secret max keeps the bar, since nothing may compare it); then, with the `both` format, current and max right-aligned at the health text's right edge, in the health font at 85% of its size and the near-white `textEmphasis`; and the power text after the bar, when its format is not `none`. Without any of these, or when the row does not fit whole, it is not drawn and the track grows taller; `both` then shows current, max and the percentage together at the track's end. The full frames show no power numbers by default.

A frame shorter than the kit's room squeezes the gaps first, down to 1 unit between the rows and 4 above the name, and keeps every part.

Text never pushes a bar out of the frame, and no two texts overlap. The track always keeps room for its own text. The row under the track gives way first, then the name, which shrinks to the height of its capitals and is left out below that. Every text rect is clamped inside the frame. A shorter frame is compact: the name and the health text sit inside the health bar, and there is no badge.

## HUD style

Options > General > HUD style (the `HudStyle` section's `style`, saved per profile, in `Core/HudStyle.lua`) picks **Medallions**, the default (see [Medallions](#medallions-hud-style)), or **Frames**, the column, Lumen and plate forms above.

- **Switching.** `HudStyle` applies the style and fires `HudStyleChanged(style)`; `HudStyle.Current()` is the applied style, which modules read, and `HudStyle.Saved()` the saved one. A choice made in combat is saved at once, prints one line, and applies when combat ends (`KstyleUI.Combat.Queue`), so nothing protected moves in lockdown. If a handler raises during the switch, the core offers a reload (`Widgets.ReloadPrompt`). A profile switch applies its own style the same way. Store migration 21 clears a saved style no build knows. Migration 45 moves every profile to Medallions except one explicitly saved on Frames, which keeps Frames. In v0.2.12 and v0.2.13 it moved those too, so a player who used Frames there picks it again; their Frames Layout Mode positions (unprefixed keys) were kept.

## Medallions (HUD style)

Under the Medallions HUD style (`HudStyle.Current() == "medallions"`), `Settings.Form` returns `slab` for every frame whose `style` is not `plate`, so a frame set to plate stays a plate. The Style dropdown offers Standard and Plate under Medallions, and the column, wide bar, sigil and plate under Frames; the cast bar texture row shows under Frames only. `Slab.lua` draws the slab. `Geometry.lua` (`SlabFrame`) lays it out from the KSTY-110 spec's numbers (section 4.3), scaled by the element's height over the mock's height for that kind, so a resized element keeps its proportions.

| Kind | Size (units) | Medallion |
| --- | --- | --- |
| Player | 300 x 58: bar 26, gap 2, power 6, name row | 86 across, its centre 2 in from the left end, plaque lower left |
| Target | 300 x 58: bar 26 | 86, mirrored to the right end, plaque lower right |
| Focus | 220 x 44, bar 15 | 62, left |
| Pet | 170 x 34, bar 14, power 3 | 56, left |
| Boss | 280 x 48 each, bar 16 | 62, right |
| Target of target, focus target | 170 x 34, bar 14 | none: a mini slab with the name under the bar |

- **Slab.** The shared unit slab material, the `medUnitSlab` nine-slice (its corner from the texture's slice), so the unit slabs, the cast bars and the action slab are one material. Nothing is drawn on or around a bar. The bars are the kit's `Widgets.UnitBar`, 5 down from the slab's top, in the Medallions finish (`UnitBar:SetFinish`): a 30% black shade down the fill, a 0.13 white sheen over its top 30% starting a pixel down, and a lit pixel at the fill's end, all inside the fill. On the outer end they start 9 in; on the medallion's end they start half the medallion plus 6 in.
- **Texts.** The name sits under the bar on the medallion side, in Inter SemiBold capitals. With no text beside it, its line runs on into the bar's 9-unit outer inset. A long name shrinks in steps of a tenth of its scaled base size to the 9-unit reading floor (1080-line reference, rounded up to physical pixels), then falls back to the body face at no larger than the last caps size, and finally truncates. A preview whose base size is below the floor never grows while fitting. The level number reserves its measured width first. The creature caption takes its measured width within the remaining lane, clipping only when the slab cannot hold both labels; the name uses the rest and hides when no width remains. Secret captions reserve the measured width of the longest localized type returned by `C_CreatureInfo.GetCreatureTypeIDs` / `GetCreatureTypeInfo`, without measuring secret text. New text clears the previous Text secret aspect. The health value sits in the bar, right-aligned on the player and left-aligned on the target (away from the medallion), 7 in from the bar's ends, in the number role at 15 units, white with a one-pixel outline so it reads on any fill. The player's power value sits at the far end of the name row inside the card, replacing the secondary health percentage while health current/max stays in the bar. Power values keep the number face and use the same muted colour, size and outline as the target's creature caption. Optional target, focus and pet power text takes the same name-row slot, replacing the target caption while enabled. With power text off, the secondary health percentage returns in `labelMuted` capitals. The target's creature type or class also uses `labelMuted` capitals. Sizes are units (name 10, value 15, extra 10, mini name 9, aura text 10), multiplied by the player's own size over the kind's default, so the font sliders still scale them.
- **Debuffs.** The target's debuffs default to one row of six 22-unit tiles, 2 apart, over the slab, the row ending at the bar's medallion end and growing away from it (`Settings.Value`'s Medallions defaults; saved choices equal to Frames defaults use the Medallions look, while other saved values win). Each tile is the `medAuraBorder` nine-slice with the icon 2 in, and a 1.5-unit underline the engine paints in the dispel colour (`AddDispelTypeTexture` with `PreserveAsset`, `Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua`). A live switch of the HUD style or the aura layout (rows or the crest fan) disables both old aura groups to release their active frames and selects tiles born in the new one. Each has its own container and tile pool (`medallionsRows` for rows, otherwise the HUD style's own), reused only for that one; tiles are never converted between them. The Frames dispel tint stays on the skin at BORDER, below the icon at ARTWORK. Rebuilding waits while auras are restricted.
- **Colours.** With `healthColor = hud`, the player's bar takes its class colour, a hostile unit's bar the hostile colour, and other units their reaction colour. A hostile unit's name is `nameHostile` and another player's name is its class colour. The ring (`Medallion:SetRingColor`) is the class colour for players, the reaction colour for NPCs, `steel` for bosses and `medDead` for the dead.
- **Portrait.** `KstyleUI.Medallions.Portrait(texture, unit, "bust")` (docs/core-services.md, Medallions) draws the painted bust when the unit's race, class and sex are plain strings and art exists, and `SetPortraitTexture` otherwise. It runs on the refresh events `Frames.lua` already handles (`UNIT_PORTRAIT_UPDATE`, `UNIT_MODEL_CHANGED`, `PLAYER_TARGET_CHANGED`, `PLAYER_FOCUS_CHANGED`), never per frame.
- **Effects.** A new target flips its medallion in on `PLAYER_TARGET_CHANGED`. Below `Widgets.LOW_HEALTH_SHARE` the low-health ring shows at an alpha taken from a step curve over `UnitHealthPercent`, pulsing through an AnimationGroup. The dead get no ring and a greyed portrait. The player and target portraits carry the sheen. All three are engine animations (Core/Widgets/README.md, Medallion) and follow the motion level.
- **Level plaque.** The plaque is 16/86 of the medallion, centred on its rim at 135 degrees, and the level number is 0.6 of it, and never under the HUD's 9-unit text floor: 9 units of the 1080-line reference, rounded up to whole pixels (6 px at 1280x720, 8 px at 1600x900), or the 11 px text floor where that is larger. A plaque too small for that grows to hold it, so the pet's plaque is larger than its 16/86 share of the medallion on every screen (`Medallion:Layout`, LEE-1539). `test-unitframes-medallions-plaque` holds it for the pet, player, target and focus at eleven screens.
- Focus and boss cast bars sit under the slab inside their slot, as plates do. The player's and target's cast bars are their own elements. Each is a 300 x 20 slab of the same material centred over the hub, the player's 10 over the ring and the target's stacked 6 over it, holding a flat bar 3 in with the caps spell name on its left and the time left on its right in the time role. The player's fill is the class accent.
- `test-unitframes-medallions-auras` covers the debuff tiles, `test-unitframes-aura-style-switch` compares switched debuff/buff trees against freshly created tiles and verifies icon/tint order, `test-medallions-health-ink` the outlined number on every class fill, `test-unitframes-castbar-medallions` the cast slab and `test-layout-medallions` the cluster. `test-unitframes-medallions` covers the forms, the medallion placement, the ring colours, the resolver's secret paths, the effects and the switch back to Frames.

## Cast bars

Each cast bar is a tile-chamfer glass panel with a soft shadow. With `castbarIcon` on (the target, focus and boss bars, as the design file draws them) the spell icon sits in its own tile-chamfer square, as tall as the bar, then a gap of `0.21 H` (the design file's 6 units on a 28-unit bar, at least 2) before the glass; the player's bar has no icon and its glass spans the whole width, as the owner's mockup draws Slam. The status bar sits inside the glass with a `buttonFill` track and no border of its own. `CastBars.Geometry` picks one of three layouts:

| Layout | When | What |
| --- | --- | --- |
| Stacked | Wider than tall, and the glass leaves room for the cast text, a 1-unit gap and a 3-unit bar above its bottom inset | The spell name left and the timer right on a row at the top, and a thin bar (22% of the height, at least 3 units) `0.22 H` above the glass's bottom, `0.5 H` in from each end (never more than a tenth of the glass's width each, so a tall narrow bar keeps its fill and its name): the mockup's Slam bar, 8 units above the bottom and 18 units in on a 37-unit bar. The timer's column is 3 em, never more than half the row |
| Inline | Wider than tall and shorter than that | The bar fills the glass inside its bevel lines, with the spell name and the timer on it |
| Tall | Taller than wide | The icon on top, the glass under it, the spell name at the bar's top and the timer at its bottom |

A fourth layout, the caption, belongs to the column style (`cb.mode`): `above` for the player's element (the spell name in the tracked `names` face and the time left and right of one row, a 9-unit flat tan bar without an outside keyline or spark, "elapsed / total", `%.1f / %.1f`) and `below` for the target's cast inside its column (an 8-unit painted bar, the spell under it, the time left as `%.1f` with no unit). Neither has an icon, a panel or a Casting word; the fill is the `gilt` token.

The player cast bar (36 units), the focus cast bar (20 units) and the target cast bar (18 units) are stacked. The target cast bar turns inline when Layout makes it shorter, and the boss cast bars (10 units) are inline until their height setting makes them 18 or taller.


| Event | What the bar does |
| --- | --- |
| `UNIT_SPELLCAST_START`, `UNIT_SPELLCAST_DELAYED` | Reads `UnitCastingInfo`, then runs the bar on `UnitCastingDuration` through `StatusBar:SetTimerDuration` with `ElapsedTime`, so it fills |
| `UNIT_SPELLCAST_CHANNEL_START`, `UNIT_SPELLCAST_CHANNEL_UPDATE` | The same with `UnitChannelInfo`, `UnitChannelDuration` and `RemainingTime`, so it drains |
| `UNIT_SPELLCAST_STOP`, `UNIT_SPELLCAST_CHANNEL_STOP` | Fades out over `fade` |
| `UNIT_SPELLCAST_FAILED`, `UNIT_SPELLCAST_INTERRUPTED` | Shows "Failed" or "Interrupted" on a full bar in the `hostile` colour, then fades after 0.6 seconds |
| `UNIT_SPELLCAST_INTERRUPTIBLE`, `UNIT_SPELLCAST_NOT_INTERRUPTIBLE` | Greys a bar that cannot be interrupted, and on a Lumen cast line swaps Casting for Locked |
| `PLAYER_TARGET_CHANGED`, `PLAYER_FOCUS_CHANGED`, `INSTANCE_ENCOUNTER_ENGAGE_UNIT` | Shows the new unit's cast in progress, or hides the bar |

- Whether a unit casts comes from `isTradeSkill`, which Forever never makes secret: it is a boolean while a cast runs and `nil` otherwise. No other cast value is ever tested.
- The spell name goes to `SetText` through `CastBars.SetName`: with `castbarCaps` on (the player, target and boss defaults), in capitals through `Unit.Tracked`; off, as the game writes it. The default tracked face needs no inserted spaces. A secret name goes to `SetText` untouched either way. Classic bars show the timer as `1.8s`; column captions use the formats above. The icon goes to `SetTexture` untouched for every unit, a secret file ID included; the repainted icons reach it through the loose-file icon pack the client loads ([`docs/icons.md`](../docs/icons.md)).
- A secret `notInterruptible` colours the bar with `SetVertexColorFromBoolean`.
- The timer counts down on an `OnUpdate` that runs only while a cast shows its timer, every 0.05 seconds, through `SetFormattedText` with the duration's remaining time, which may be secret.
- Fallbacks, each logged once to the devlog: when there is no duration object or `SetTimerDuration` refuses one, the bar runs on the cast's start and end times while they are plain; when those are secret too, the bar shows full with the spell name and no timer. A secret duration object cannot be read, so it drives the bar with no timer text.
- A light sheen crosses a horizontal bar at the start of each cast, as the spec's motion table asks. A vertical bar has no sheen, because the sheen moves sideways.
- A cast start sets no fonts, textures or fill direction: settings, theme and profile changes restyle the bars. The bar colour is set only when it changes, the two colour objects for a secret `notInterruptible` are rebuilt only when a colour changes, and the hold after a failed or interrupted cast reuses one release function per bar.

## Frame auras

Each player, target, focus and boss view gets a `CustomAuraContainerTemplate` container the first time its auras are switched on. The container reads the unit's auras in Blizzard's secure environment, so the module never calls `C_UnitAuras` and never touches aura data.

| Part | How |
| --- | --- |
| Groups | Two groups, `debuffs` and `buffs`. The filter setting enables them and sets their filter strings: `HARMFUL|PLAYER`, `HARMFUL`, `HELPFUL`, or both, with buffs starting a new line. Each group holds `auraRows` times `auraColumns` icons. |
| Order | Each group sorts with the engine's `AuraContainerSortMethod.Expiration` rule: auras from you first, then Blizzard's priority auras, then the ones you can apply, then soonest to expire, permanent last. The engine compares in its own secure code, so a secret aura sorts as well as a plain one. Without the enum the engine keeps its default order and the devlog says so. |
| Overflow | Past `auraRows` times `auraColumns`, an opaque chip covers the group's last socket and reads `+N`, the auras not shown (the covered one included); `+25` is the most it reads. Where the timers hang under the sockets (the sigil's single centred row), the chip stands one socket after the last one instead and reads the auras past the cap, so no covered aura's timer can read as the count's (round 5, Astra #2 and Opus #3) and the chip stays one tile tall (KSTY-69). No count is ever read: a second, hidden container with the same unit and filter lays out one 1-unit element per line, each line two sockets tall, for up to the cap plus 24 auras, so its height is the count. The chip's labels (`+2` to `+25`) hang from that container's foot, one per line, inside a clipping window on the last socket, and the chip's glass sits in a clipping strip that covers the window only when the count passes the cap. The engine moves the labels; the module never compares anything. The counting container's buttons take no mouse and draw nothing. The second group's chip (buffs under debuffs) anchors to the container's far edge, where its last row ends whatever the debuffs filled. A targeted boss folds the chips with its debuffs. Without a second container the row works and the devlog says so. |
| Layout | The group layout sets `elementWidth`, `elementHeight` and the spacing; the flow layout grows from the corner the growth setting names, with lines `auraColumns` icons long. These container-level changes apply at once, in or out of combat. |
| Buttons | `initializeFrame` dresses each engine button in the kit's icon tile (`Auras.NewTile`, shared with the preview): a child frame with the kit's icon chrome (`Widgets.IconChrome`: the near-black `buttonFill` body, the accent rim with its halo, a 3-unit chamfer and double bevel at any icon size), the icon two borders in and masked by `iconMask` (`SetIcon`), a reverse cooldown swipe in the `iconMask` shape (`SetDurationCooldown`), the stack count (`SetApplicationCount`), the time left (`SetDurationText`) and, for debuffs, a `chamferTile` border the engine tints by dispel type with the `PreserveAsset` style (`AddDispelTypeTexture`). The icon size, spacing and gap to the frame snap to whole pixels. |
| The gate | The engine denies tainted code access to its buttons while `C_Secrets.ShouldAurasBeSecret()` is true. A later restyle of the buttons (size, tile, fonts, timer), including a theme change, runs only out of combat while auras are readable, and otherwise waits for `PLAYER_REGEN_ENABLED` or `ADDON_RESTRICTION_STATE_CHANGED`. |
| Placement | The container sits on a host frame on the root, anchored beside the unit's button. The host shows while the button shows and the auras are on, and mirrors the frame holder's alpha and strata, so Layout's opacity follows. |
| Fallback | Without the engine, or if it refuses a group, the frames show no auras and the devlog says why. |

## Class resource

`unitframes.resource` sits under the player frame, beside action bar 1. It shows only what the player's class and form need:

| Class and form | Shows |
| --- | --- |
| Rogue | Five combo point pips |
| Druid in cat form | Pips and the mana bar |
| Druid in bear form, or any form with a power other than mana | The mana bar |
| Anyone else | Nothing |

Each pip is a status bar from `i - 1` to `i` filled with the `dot` texture, and every pip gets the same count, so the engine decides which pips are full and a secret count never reaches a comparison. Combo points are bound to the target on Forever: the count comes from `GetComboPoints("player", "target")` and refreshes on `UNIT_POWER_FREQUENT`, `PLAYER_TARGET_CHANGED` and `COMBO_TARGET_CHANGED`. `UNIT_POWER_FREQUENT` and `UNIT_MAXPOWER` are registered only while the element shows pips or the mana bar, because `UNIT_POWER_FREQUENT` fires on every mana, energy and rage tick. The mana bar reads `UnitPower("player", Enum.PowerType.Mana)` and refreshes on mana power events, `UNIT_DISPLAYPOWER` and `UPDATE_SHAPESHIFT_FORM`.

### Class-themed pips

**Class-themed pips** (Player > Class resource, on by default) draws each combo point as the class's own piece over the plain pip's place, which hides: daggers for a rogue and claws for a cat-form druid. An empty point is the same piece dormant, in ghost steel. While the Medallions crest's crown shows them ([ActionBars README](../KstyleUI_ActionBars/README.md#crown)), which it reports through `Widgets.SetClassCrown`, the row hides; with no crown (Action Bars off, or its slab off or unable to pair its bars) the row stays. The druid's bar keeps its own texture, colour, direction, text and Mana in forms in every form; in cat form under the crown the element sits on the seat the crown offers just above its tips, so the two never overlap, and has no mover there (bear form has no crown and keeps its place). The art is 1.6 times the pip and overhangs it by whole pixels on each side. Off restores the plain pips exactly.

Under Frames the player's resource row also holds the crowns the game feeds, upright and the combo pieces' size: a warrior's banners, a priest's candles, a mage's shards, a hunter's arrows, a bear's talons beside its druid bar, and a shaman's Lightning Shield charges as three storm orbs; the full row glows. Class-themed pips governs it, and Medallions builds none of it here (the crest shows them). `test-unitframes-frames-crowns` holds it.

Each pip is a `Widgets.ClassPip` ([widget kit](../Core/Widgets/README.md#classpip)), shared with the crown: a gain slides the piece out under a white-hot flare, a spend holds, flashes a slash and cools to the dormant art, and at the maximum a glint runs up each piece, 0.05 s apart, and a glow lights under the row. Every lit layer is a one-point status bar fed the raw `GetComboPoints` value now, the value before (stored, never read) or at the maximum, so Lua never compares the count. Motion follows the effects level: Full and Calm play the fades, Off shows the end states and settles a change still playing, and a target change shows the new count at once, as the game's own bar does. A power event that leaves a readable count unchanged plays nothing; a secret count is never compared, so it replays. The row loops nothing.

Forever's own UI draws no other pip resource: at `9dc84f0`, `Blizzard_UnitFrame.toc` loads only `RogueComboPointBar.xml` and `DruidComboPointBar.xml` for `camelot` and excludes `PaladinPowerBar` and `ShardBar` (`[ExcludeLoadGameType camelot]`), so a paladin and a warlock get no pips. The generated `PowerType` enum still lists `SoulShards` (7) and `HolyPower` (9); the crest jewels light those.

## Why

- **One holder per element, buttons inside.** `RegisterUnitWatch` shows and hides the secure button, and Layout's shown rules show and hide the holder, so the two never fight over one frame. The holder becomes protected through its secure children, so Layout queues its changes in combat; the module also re-anchors its buttons only out of combat.
- **The boss frames hide one by one.** `BossTargetFrameContainer` is a managed frame: Edit Mode and the right-side frame manager reparent it back to their container. Its five boss frames are not managed, so hiding each of them stays hidden.
- **Health never reaches Lua.** `UnitHealth` is always secret on Forever. The bar gets `SetMinMaxValues(0, UnitHealthMax(unit))` and `SetValue(UnitHealth(unit))`, the engine eases it, and the text comes from `SetFormattedText` with `AbbreviateNumbers` and `UnitHealthPercent` evaluated through a 0 to 100 curve. Without a curve API the percentage would be a 0 to 1 share, so the text falls back to current and max and the devlog says so.
- **The texts' columns come from settings, never from the text.** A text's width would be secret when its text is, so the module never measures one. The health text's column after the track is `Format.ColumnWidth` of the chosen format and font size, the same rule the compact frames use, and the row under the track is split in halves, so no bar's width depends on what a text says. The design file and the owner's mockup both draw the percentage after the bar, so the fill never runs under the numerals at any health.
- **The glass runs under the portrait.** The kit sheet draws one panel with the portrait over its outer end, not a portrait beside a separate box. Starting the glass at the portrait's centre hides its end behind the portrait at any frame size, and the 2-unit inset lets the panel's top and bottom lines run out from behind the portrait's chamfered corners.
- **The chamfered portrait asks for a square image.** `SetPortraitTexture` masks the portrait round unless `disableMasking` is true, and a round image would leave the octagon's corners empty. The image is then masked by `iconMask` and drawn under the bevel lines, which cover any difference between the mask's chamfer and the frame's.
- **Name tracking belongs to the font.** The default `names` face carries its letter spacing in its glyph advances, including for secret names passed straight to `SetText`. `Widgets.ApplyFont` compensates its trailing advance, and the class caption subtracts `Widgets.TrackPad(name)` from its anchor gap. Fitting uses the full `GetUnboundedStringWidth` advance, not the ink width: the engine can truncate a name whose final tracking crosses the box edge. A missing or secret width is never compared. A readable name in a custom face uses thin spaces only when `Locale.TrackMode` explicitly returns `space`; unsupported scripts use the game's font without added tracking.
- **The frames are 70 units tall.** The kit sheet draws a frame about 100 units at the 1080 reference and the mockup 89, but the owner's first in-game test (2026-11-08) found frames that tall dwarfing the 38-unit action buttons. The HUD now takes the action button as its module: the frames stand under two buttons tall (70), the essential icons one notch up from a button (44), the utility icons a button (38), the cast bar 30. The width keeps the owner's mockup's proportions (279 by 90 from the ring's outer edge to the glass's end), so the frame is 220 by 70, its inner edge 180 units from the screen's centre. The spacing is a share of the height, so a resized frame keeps the same look, and fonts are settings sized for each frame's default height: the name's capitals and the percentage's numerals are the same height, as measured on the sheet.
- **The small parts sit beside and under the frames, except the class resource.** The composition mockup puts the frames beside the essential row, with the utility row, the experience line and the action bars stacked below them. Its 195-unit tracked buff bars take the whole row under the player frame and the target cast bar the row under the target frame, and it shows neither a pet frame nor a target of target, so those two 104-unit compact frames sit beside the frames' portrait ends, 4 units out and bottom-aligned, mirroring each other. The class resource sits on top of the player frame, right-aligned, because the chat panel on the Mac's 1671-unit-wide root reaches up to where a second row under the frame would sit.
- **The target's health follows its reaction.** The kit sheet fills a hostile target red. With `reaction`, any hostile unit, player or NPC, is red; with `class`, a hostile player would show their class colour.
- **Fonts belong to the module.** The kit's `Widgets.Text` restyles its texts to their role on every theme change, which would undo a player's font choice. The unit frame texts are the module's own font strings, styled from their settings and restyled on `ThemeChanged`.
- **Target of target and focus target poll.** Unit events never fire for `targettarget` and `focustarget`. Those two frames refresh on `PLAYER_TARGET_CHANGED`, `PLAYER_FOCUS_CHANGED` and `UNIT_TARGET`, and poll health and power every 0.2 seconds only while their button is shown, as Blizzard's own frames do.
- **One picker, one frame's rows.** Seven frames with the same thirty settings would make a page of over two hundred rows. The page shows the picked frame's rows, and the preview draws that frame.
- **The target cast bar is its own element.** The target frame's footprint has no room for it, and the kit sheet shows it under the frame. It sits under the target frame, right-aligned, with the target of target under it; `test-setup-layouts.lua` checks that nothing overlaps and that every unit frame keeps 2 units from its neighbours.
- **Focus and boss cast bars live inside their frames.** Their footprints already hold a cast bar under each frame, so the bar is a child of the unit's button and moves and hides with it. Their height is a setting that takes room from the frame above.
- **Blizzard's player cast bar may come back after Edit Mode.** `PlayerCastingBarFrame` is a managed frame: Edit Mode can reparent it to its container while it is casting. The next login hides it again.
- **Layout owns visibility.** Layout's shown rules hide a holder with a state driver or `Hide`. The module shows a holder only when it hid it itself, in `Disable`, so a setting change never brings back an element the player set to never show.
- **Cast events match the shown cast.** A spell can fail or stop while another cast runs. Terminal events carry `castBarID`, which Forever never makes secret; the bar ends only when that ID matches the cast it shows, or, without IDs, when the unit has no cast left.
- **Aura containers are not children of the frame.** Layout's mouseover rule hooks `OnEnter` on an element's children four levels deep, and engine aura buttons refuse untrusted scripts. The host is a sibling on the root that follows the button and mirrors the holder's alpha and strata instead.
- **Auras are off on the player and target by default.** The Auras module shows the player's own buffs and debuffs under the minimap, and the space around the target frame belongs to the target cast bar, the target of target and the tracked buff icons. Focus and boss frames have room to their right. Any frame's auras can be switched on and placed on any side.
- **Status icons keep fixed slots.** A leader or PvP flag can be secret, so the module cannot tell which icons show to pack them together. Each icon keeps its own slot in the row, so nothing moves when a secret flag changes.
- **Resting is text.** Blizzard's resting art is a 42-frame flipbook atlas. A "Zz" in the accent colour needs no animation and follows the accent.
- **The class resource is its own element.** The pips sit under the frame in the v3 mockups. As their own Layout element they move and resize on their own, and the setup places them so they overlap nothing.
- **Focus target has its own key.** The element keys had no focus target. It sits under the focus frame, right-aligned, and `test-setup-layouts.lua` checks that it overlaps nothing in any layout.

LEE-94 refines the type after the merged bar geometry without moving its shared baseline: the target creature caption defaults to 14.5 units, its size slider supports half-unit steps, and its mirrored gap is 9 units (the other forms retain 10). A selected font or size still wins. The `unit` face takes off 64 rather than 65 font units per advance (-0.064 em), closing the target core width while leaving the player core box unchanged. On the reference panel the target name, creature word and percentage still share rounded canvas baseline y1733. No `COLUMN` bar height or gap is changed here. The picture's blurred halo remains the documented font API limit, not a reason to enlarge letters or change shadows.

### Parity round 6: icon corners, the PvP timer's place and boss value decimals (2026-11-21)

Every option starts at today's look and behaviour: the frames match staging pixel for pixel at all four test screens in Frames and Medallions, the text slot frames and the unit frame gallery.

- **Icon corners** (every frame): the leader, PvP, combat, elite and raid marker icons each take a Place: In the status row, the default, or a corner. The status row closes the gap an icon leaves, and the icons in one corner run inward from it with the usual gap, after the medallion's edge on Medallions slabs. Top corners sit on the status row's line; bottom corners on the lower edge of the bars and texts, so a card's cast line stays below them. A run that would cross the frame's text (name, health, power, level, caption, cast line or text bar) steps past it, outside the frame, and so does a run across from the status row where the row would meet it. An icon switched off keeps its status-row place, as today, and leaves its corner's run. A cornered raid marker leaves the name its whole lane. The elite badge, made only when a unit first needs it, takes its corner when it appears.
- **PvP flag timer place** (Player): Left of or Right of the badge makes the badge's run leave room for the timer, so it never covers the next icon; Above or Below the badge sits by it, and takes the other side where it would cross the frame's text.
- **Boss decimals on percentages only** (on by default): off gives boss health values two decimals as well, 240.55K / 1.25M, and widens the boss value column (up to 60% of the card) to fit. Plain values are cut in Lua; secret values go to `AbbreviateNumbers` with two-place breakpoints, probed once with a plain number, and a formatter that answers anything else keeps one decimal; a formatter's result goes to the text without a boolean test. The Options preview's boss sample takes 72,432 / 100,600 only while the values take two decimals.

The places are read only when a frame is laid out (a setting, style or size change), never on unit events, and the corner pass is skipped while every icon sits in the status row. ### Cast parity follow-up: smoothing and channel colour

Player > Cast bar now offers **Smooth cast progress**, **Separate channel colour** and **Channel colour**. Both switches start off to preserve the existing cast appearance and motion. Smoothing uses the native duration-bar interpolation, with immediate interpolation when the enum is unavailable; channel colour uses the current kit palette and leaves uninterruptible colour in charge, including secret interruptibility flags. ### Cast parity follow-up: icon side and total duration

### Parity round 3d: aura filters, precise timers and cast text (2026-11-21)

Every option starts at today's look and behaviour: the frames match staging pixel for pixel at 1920x1080 and 5120x1440, and an old profile never touches the engine's candidate filters.

- **Buff lanes** (any aura frame, boss and pet included, whenever its auras include buffs): Stealable buffs, Big defensives and Dispellable buffs each show all, only these, or hide these. Big defensives and Dispellable add `BIG_DEFENSIVE` or `!BIG_DEFENSIVE` and `DISPELLABLE` or `!DISPELLABLE` to the buff group's filter string; Stealable sets the group's `isStealable` candidate filter. The lanes combine with AND, as the engine's filter string does.
- **Filters:** Only auras with a duration (`maxDuration`, which drops permanent auras), Hide Bloodlust lockouts (Sated, Exhaustion, Temporal Displacement, Insanity and both Fatigued debuffs through `excludeSpellIDs`; the engine filters these never-secret spells on friendly units), Hidden spell IDs (buffs of friends, debuffs of enemies, as the engine allows) and Tracked spell IDs with Only tracked buffs. Only tracked buffs applies on friendly units only: on an enemy the engine would reject every unmatched buff, so the frame re-checks `UnitCanAssist` on target, focus, encounter, `UNIT_FACTION` and `UNIT_FLAGS` changes (the engine's own containers listen to both), does nothing when the answer is unchanged, and stops listening once no frame tracks. The +N chip counts with the same candidate filters, and the Medallions crest of your target debuffs takes the same duration, lockout and hidden-ID filters for its tiles and its +N count. An apply that leaves a group's filters unchanged does not set them again, so the engine does not rescan.
- **Layout and timers:** Extra row spacing adds to the gap between aura rows, in the engine layout, the footprint and the +N cell. Precise timers below (minutes) gives the aura timers, the crest's too, a seconds formatter with two units under the threshold and the interval bands of the engine's default formatter above it; the buttons take it when aura data is readable, so a change in combat waits for combat's end. The icons then spread apart by the width of a precise label measured in the aura font, so two adjacent timers never overlap, and the +N cell follows. Zero returns each timer to the game's default formatter and the icons to Aura spacing. Copy auras from (round 3a) carries Extra row spacing and Precise timers with the other look settings, and hides their rows on the copying frame.
- **Cast bars:** Show full spell name (every cast bar) shrinks a long name to fit its room, measured by its full advance like the unit names, down to 60 percent and never below the kit's readable floor; a secret name is never measured and keeps the normal size, and with the option off nothing is measured. The player also gets Show spell rank (`C_Spell.GetSpellSubtext`, only a subtext with a number; a rank that loads after the cast starts lands on `SPELL_TEXT_UPDATE` for that spell), Show latency (world latency after the timer, such as 1.8 (42ms), in a wider column, independent of Latency zone; one `GetNetStats` read per cast serves both) and Whole craft batch (`C_TradeSkillUI.GetRemainingRecasts`: the timer counts down the remaining crafts from the cast's plain start and end times, never from the duration object, and the name shows how many are left).

The new aura settings are read live, not copied into each frame snapshot, and the precise formatter is chosen once per aura refresh, so a reload reads no setting per aura button and makes no new regions or widget calls. Options rows stay in the lazy schema. The live preview shows precise sample timers with their spacing, the extra row spacing and, on a plate player cast bar, the rank, craft count and latency in the live timer format. Each sample aura has a role (a stealable, a dispellable and a big defensive buff, a Bloodlust lockout, plain buffs and debuffs), so a lane, the lockout filter, Hidden spell IDs and Only tracked buffs on a friendly frame drop the samples they reject, and the +N chip with them; with no filter the grid stays full. Every sample has a timer, so Only auras with a duration changes nothing there.

### Parity round 4a: the text bar, boss cast size, trailing zeros and tracked debuffs (2026-11-21)

Every option starts at today's look and behaviour: the frames match staging pixel for pixel at 1920x1080 and 5120x1440 in Frames and Medallions, and in the unit frame gallery's boss cards.

- **Text bar** (Player, Target and Focus): a strip in the bar-track colour with a left, a centre and a right text, each on the shared Text rows with tags, size, outline, colour, width and offsets, plus an optional class icon at either end. It sits on the frame's bottom or top edge, or below or above it with a 4-unit gap at its own width, and takes its room from the frame's own height, so auras, cast bars and the class resource around the frame never move or overlap it. It also keeps clear of what the frame draws: beside a Medallions crest it runs from the crest's edge, content that reaches past the frame's body (a portrait badge, a Wide bar's caption or the aura rows under its bar) shortens it, and where that would leave less than its text's size it is not drawn, so a Wide bar whose auras fill the frame below the bar takes the strip on top or a taller frame. On top, the Wide bar's own aura row under its bar moves down with the bar. The player's strip shows wherever the player frame does. Its strata defaults to the frame's. A slot's format is the tag language the Extra texts use, so `[name] [c:ff8800]>[/c] [target]` gives EllesmereUI's Name > Target with its indicator colour and separator. The texts follow the frame's unit events (health, power, name, level, target) and are painted again when a layout waits for combat's end.
- **Boss cast bar:** Cast bar width now applies to boss frames, from the left end of the card's cast line or the bar under a Plate or Medallions frame, and Cast bar height now sets the boss card's cast line, 6 units taller than the setting so the default 10 keeps the card's 16-unit line and every height can be picked; the slider shows the card's line. The focus card keeps its fixed 16-unit line.
- **Hide trailing zeros** (Unit frames, under the decimal switches): 41% for 41.0%, 41.5% for 41.50%. A linear curve hands `UnitHealthPercent` the secret percent in tenths or hundredths plus a half, and `AbbreviateNumbers` with one breakpoint (significand 1, fraction 10 or 100) writes it without trailing zeros. Three plain-number probes check the formatter's output first, reading a comma decimal mark as a point; a missing API, a curve the client cannot make, or any other output keeps the fixed places.
- **Only tracked debuffs** (Target, Focus and Boss): on enemies the debuff group's candidate filters take `includeSpellIDs` from Tracked spell IDs, which the engine allows only for enemies' debuffs; a friend's debuffs show as usual, and the frame re-checks on target, focus, encounter, `UNIT_FACTION` and `UNIT_FLAGS` changes through round 3d's tracking, for the frame's auras and the Medallions crest alike. A reaction the game does not give (no `UnitCanAssist`, or a secret answer) is not taken as an enemy, so every debuff shows. The switch travels with Spell ID lists from, like Only tracked buffs.

The new settings cost nothing while off: Style.Layout reads one field, the text bar's frame and texts are made the first time a frame turns it on, a strip switched off leaves the tag pass as it was, and tracked debuffs is read only when the debuff filters are built. The strip's texts are coloured again only on unit and colour changes, not on every health or power event. Aura buttons now reuse their view's timer place, timer switch and size from the per-view style instead of reading them for every button, which more than pays for the new defaults (about 191,000 fewer addon instructions on reload and 100,000 fewer on a display resize, counted exactly).
