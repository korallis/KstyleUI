# Render

Draws the UI from the addon's real Lua code, without the game. A scene script boots a stub environment (`Tools/regression/*_env.lua`), drives a module into a state, and `scene.lua` resolves every visible region to a drawable in screen units. `render.js` draws the drawables on a canvas; `shoot.sh` screenshots it with headless Chrome; `compare.py` puts a crop next to the design file, the mockup or an in-game screenshot at the same pixels per unit.

Screen units: the screen is 1080 units tall, x grows right and y grows down from the top left. That is KstyleUI's root unit at user scale 1; the scenes render at the size KstyleUI ships (16 / 19, `Common.ForceScreen`), where a root unit is 16 / 19 of a screen unit. The owner's Mac draws 1.426 px per unit (2383 by 1540, UI scale 768 / 1080), the design file 2.0, the mockup 1.348.

### Alpha model and Forever evidence

The stub owns each object's current alpha; the scene reads that value and
applies ancestor alpha once. Texture colour fields in scene items carry RGB
and an alpha of 1, so the canvas does not multiply an old texture colour alpha
back in. FontStrings retain the previous independent region/text opacity model.

| Object | Model |
| --- | --- |
| Texture | `SetAlpha`, `SetAlphaFromBoolean`, `SetVertexColor` and `SetColorTexture` write one alpha: the last write wins. Omitted colour alpha is 1. `GetAlpha` and the fourth `GetVertexColor` return agree. File pixels, masks and gradient stops retain their own coverage. |
| FontString | Preserve the existing model: `SetTextColor` stores text colour/opacity independently of `SetAlpha`/`SetAlphaFromBoolean`, and the renderer multiplies those opacities. The generated secret-aspect flags do not prove shared storage; stronger client evidence would be required to change this model. |
| Frame | Its own `SetAlpha`/`SetAlphaFromBoolean` value multiplies down the parent chain, stopping at `SetIgnoreParentAlpha`. Colour writes on a child region do not change the frame. |

Evidence is from [Gethe/wow-ui-source at `9dc84f0`](https://github.com/Gethe/wow-ui-source/tree/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns), Forever build 1.60.1.70862:

- `Blizzard_APIDocumentationGenerated/SimpleRegionAPIDocumentation.lua`:
  `SetAlpha` (123) writes `SecretAspect.Alpha`; `SetVertexColor` (191) writes
  both `VertexColor` and `Alpha`; `GetAlpha` (10) and `GetVertexColor` (66)
  are marked with that secret aspect. Colour alpha is optional; secret-aspect
  flags describe information restrictions, not the underlying storage.
- `Blizzard_APIDocumentationGenerated/SimpleTextureBaseAPIDocumentation.lua`:
  `SetColorTexture` (403) takes RGB and optional alpha. The generated signatures
  alone do not specify setter ordering. The client regression below and the
  chat-window code establish the Texture model.
- `Blizzard_ChatFrameBase/Mainline/FloatingChatFrame.lua`: temporary chat
  windows read background opacity through `GetVertexColor` (455), while
  `FCF_SetWindowAlpha` writes those background textures with `SetAlpha` (1056).
  This relies on the two methods accessing the same value.
- `Blizzard_APIDocumentationGenerated/SimpleFontStringAPIDocumentation.lua`:
  `SetTextColor` (675) and `GetTextColor` (367) carry the `VertexColor` and
  `Alpha` secret-aspect flags; its inherited region alpha API is the file
  above. These flags alone do not establish a last-write-wins FontString model.
- `Blizzard_APIDocumentationGenerated/SimpleFrameAPIDocumentation.lua`:
  `GetAlpha` (276), `SetAlpha` (1134) and `SetAlphaFromBoolean` (1145) use the
  frame's Alpha aspect. `Blizzard_ChatFrameBase/Mainline/FloatingChatFrame.lua`
  (1214) fades the scrollbar frame from its current `GetAlpha` value.

The client observation is also recorded in `CHANGELOG.md`, v0.2.2: retinting
the Medallions hub with three-component `SetVertexColor` revived its hidden
shock ring and flash. Retinting now preserves the current alpha in addon code;
the harness must therefore leave those effects absent at rest. The Options
dispel sample explicitly passes `WASH_ALPHA` (0.16) to `ColorSlice`, because
the vertex write replaces the wash's initial alpha.

The live raid dispel wash had the same fault: in
`Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua`, `PreserveAsset` (533)
calls `AuraUtil.SetAuraBorderColor`, which writes the dispel colour's RGBA with
`SetVertexColor` (`Blizzard_FrameXMLUtil/AuraUtil.lua`, 614), and then a
`customDispelColorMap` colour's RGBA (546). Both replace the wash's own alpha,
so a Magic debuff turned Ilyra's raid row into an opaque blue tile. The group
frames now hand the engine the wash's alpha in a colour map, and
`gallery_groupframes` colours the dispel textures with it. The engine passes a
`securecopy` of the options through
`C_AuraContainerUtil.ProcessCustomAuraButtonDispelTypeTextureOptions` (line 114),
whose documentation types the map's values `colorRGB`
(`AuraContainerUtilDocumentation.lua`, 300), so neither the stubs nor the render
can show whether the client keeps that alpha. Retake `frame_raid.jpg` through
`readme.py` once the wash is checked in game at 0, 0.16 and 1.

### Native context-menu fixtures

`native_menus_tracking`, `native_menus_compartment` and `native_menus_quest` open the actual KstyleUI menu generators over `Tools/regression/native_menu_fixture.lua`. Set `RENDER_MATERIAL` to `Native`, `Glass`, `Flat`, `Slate`, `ForgedTicks` or `ForgedBrackets`; `Native` (the default) disables this skin. `RENDER_TEXT_SIZE` and `RENDER_TEXT_FACE` exercise the Skins text controls.

These are simulated menu acquisitions, not screenshots from the client. The fixture models callback ordering, compositor attachment/release, pooled reuse, initializers, actions and submenus. It deliberately does not model native taint, scrolling, grids, narration or gamepad focus. Text widths use the repository's glyph estimates and row padding is approximate. Native client fonts may use the renderer's documented fallback; read each render log. Missing atlas/path textures drawn as gray boxes are not acceptable before/after art evidence: populate the read-only client cache first. Security and restoration evidence comes from the focused regression test and the 70862 source audit in `docs/native-context-menus.md`, not these images.

### Blizzard atlases and textures

```bash
python3 Tools/render/atlas.py build --scan                 # export the client's atlas tables, write the map, fetch every sheet and path texture the last renders asked for
python3 Tools/render/atlas.py build roleicon-tiny-tank     # the same, fetching the named atlases' sheets
python3 Tools/render/atlas.py fetch UI-HUD-MicroMenu-Questlog-Up --scan   # add sheets (and the scanned path textures) to an existing cache
python3 Tools/render/atlas.py paths 'Interface\TargetingFrame\UI-RaidTargetingIcons' --scan   # fetch textures named by file path
```

Run it with `~/.local/share/wow-dev/venv/bin/python` when the system Python has no Pillow; the BLP decoder needs it.

`SetAtlas(name)` draws a rectangle of a larger sheet. The UI source has no atlas data; the installed client does, in three DB2 tables (`UiTextureAtlas`, `UiTextureAtlasMember`, `UiTextureAtlasElement`). `atlas.py build` exports them with `Tools/icons/casc_export.py` (TACTTool and DBC2CSV read the game folder and never write to it), writes `~/.local/share/wow-dev/atlas/atlas.tsv`, one line per atlas name (its sheet's file ID and size, its rectangle in pixels, its size in units, its tiling flags), and fetches each named atlas's sheet into `textures/<fileID>.png`, decoded with alpha at its own size. The game looks an atlas up by its element name; an element can have a 1x member, a 2x member and Forever's own `-c60` art, and the map keeps Forever's art over the shared one and the 2x sheet over the 1x, with the size in 1x units (what `SetAtlas(name, true)` sizes a region to). The cache lives outside the repository and is never committed.

`scene.lua` reads the map when it exists: a known atlas whose sheet is in the cache draws as that sheet with the member's texture coordinates, and `useAtlasSize` gives an unsized region the member's size; a known atlas whose sheet is not fetched, or a name the client has no atlas for, draws as a grey box and is logged with the command that fetches it. Without the cache every atlas is a grey box, so CI needs none. `Scene.ATLAS` lets a test stand in for the file. `Tools/tests/test_render_atlas.py` covers the map and the fetch, `test-render-scene.lua` the drawing.

A texture the game names by file path (`SetTexture("Interface\\TargetingFrame\\UI-RaidTargetingIcons")`) has no atlas entry. `atlas.py paths` fetches those by name through TACTTool's list mode, which looks each path up in the client's install manifest and then in the community listfile (downloaded once, 150 MB, into the cache's `tact/` folder), and decodes each into `~/.local/share/wow-dev/atlas/paths/<key>.png`, the key being the game path lowercased, with forward slashes and no extension (`interface/targetingframe/ui-raidtargetingicons`). `--scan` adds every path the scene JSON files report missing, and `build --scan` and `fetch --scan` fetch those too. `scene.lua` resolves a path through `Scene.PathKey` and draws the cached PNG when it exists; otherwise the texture is a grey box, logged with the command that fetches it, so CI needs no cache. `SetSpriteSheetCell(index, rows, columns)` draws one cell of a grid sheet, as the raid target icons are. `Scene.PATHS_DIR` lets a test point at its own folder.

Run `python3 Tools/render/gen_glyphs.py` when a font changes; `Tools/tests/test_render_standins.py` fails when the table is stale.

To look at a scene in a browser instead, open `Tools/render/out/<scene>.html` with Chrome started as `--allow-file-access-from-files`, or `render.html?scene=out/<scene>.json&ppu=1.426`.

## Render guard

Every `shoot.sh` run checks what it drew, so a shipped render never clips or spills unseen (`guard.lua`):

- **ellipsis**: a text that may not wrap and is wider than its rect. The page reports each text it truncated to "..." (`render.js`, read from the page's DOM after the screenshot), the authority, since it measures the real glyphs; the scene step estimates the same from `glyphs.lua` with the page's half-pixel slack at the render's density (`RENDER_PPU`, which `shoot.sh` sets from `--ppu`), so the regression tests catch it without Chrome. When the page does not finish drawing (its title never reads "rendered"), its truncations are unknown and the run fails, except with `--report`.
- **outside**: content that reaches past its glass card. A card is a frame that owns Lumen frost glass (the panel, card, window and rail shapes; tiles, sockets and bars have none); its glass is its fill as drawn, plus any lens disc on the card itself (the minimap card's arched top). Its content is everything drawn under the frame the glass clothes (the card itself, or the target or parent a backdrop covers to within 24 units); a drawn item belongs to the card whose content root is deepest, and a text no card holds belongs to the smallest glass its centre sits on. An item that reaches more than 1 unit past its card's glass is a spill, unless it sits wholly on the glass of a card that does not hold its card (a popout list hung in the tree under the card that opened it); the glass of a card that holds it excuses nothing, so a label spilled out of a panel onto the window around it is still a spill. A card inside another card's content whose glass reaches past that card's glass is a spill too (`<key path> glass`, a tab column hung off a window), whichever card is bigger. Shadows, glows, gilt corners and grain bleed by design and are never content; an item the page draws through a clip rect is checked as clipped. The arithmetic is `Tools/regression/geometry.lua`'s.

A texture is named by where it hangs (`CharacterFrame.ModeTabs.?.Icon 136224.png`: the fields that hold each frame from the nearest named one, `?` where no field names it), a text by its plain words.

`Tools/render/guard_allow.tsv` lists the findings that pass, one per line, tab-separated: the owner (the round's fix scope that owns the defect, `R1` to `R7`, or `design` for a deliberate straddle such as a tab set on a card's edge), a scene glob (or `scene@WxH`, which covers that screen alone, as `shoot.sh` passes `RENDER_SCREEN`), the kind, the subject's start (or `=` and the whole subject) and the reason. A crop is `x,y,width,height` in that image's pixels, or in screen units with a `u` suffix. The reference crop is rescaled to the render's density, so one unit is the same number of pixels on both sides. `--scale` magnifies both halves. Crop each image with its own coordinates: the mockup is 1909 units wide and the owner's screen 1671, so right-anchored elements sit at different x. The component sheet rendered at 2.0 px per unit puts each section where the design file draws it, so the same pixel box works on both (`--crop 1560,260,990,240 --ref-crop 1560,260,990,240`), except the target frame, which sits at the sheet's right end past the button states because the addon's 280-unit frames do not both fit before the design's button section, and the minimap, which starts 6 units left of the design's map because its element carries the button column outside the map. `compare.py` needs Pillow; it runs itself again with `~/.local/share/wow-dev/venv/bin/python` when the system Python has none.

## Add a scene

A scene script in `Tools/render/scenes/` builds one scene and ends with `return Common.Run(build)`:

```lua
local Common = dofile("Tools/render/scenes/_common.lua")
local U = dofile("Tools/regression/unitframes_env.lua")

return Common.Run(function()
	local env, K = U.New(Common.ScreenOpts({ saved = ... }))
	-- drive the module: set units, fire events, run env.RunTimers() and U.W.Tick(env, 0.05) for tweens
	return Common.Scene.Build(env, { time = env._time })
end)
```

- `Common.ScreenOpts(extra)` is the owner's screen for loaders that take `width`, `height` and `uiScale`. For a loader that does not, call `Common.ForceScreen(env)` in its `setup` hook.
- `Scene.Build(env, opts)` walks UIParent and every parentless frame. `opts.time` is the clock for timer bars and cooldown swipes; `opts.hover` is a set of frames whose HIGHLIGHT regions draw.
- `Scene.Merge({ sceneA, sceneB })` composites modules drawn in separate environments; every environment must use the same screen options.
- `Scene.Rect(env, frame)` gives one frame's resolved rect in screen units, for stand-ins the scene has to size itself.
- `Hud.Module(name, opts)` in `hud.lua` builds one HUD module; `Hud.Build(opts)` merges them all. `opts.icons` picks the icon set. `components.lua` holds the sheet's section origins. `_tracker.lua` holds the objective tracker stand-in both `hud.lua` and `tracker.lua` build, laid out as Blizzard_ObjectiveTracker lays the real one.
- `Common.StandIn(name)` gives a stand-in's path when `standins.py` has made it; `Common.IconDirs()` is the folder list a numeric icon file ID resolves through.
- The `Tools/regression/test-render-scenes-*.lua` tests build every scene (`-hud` the HUD's modules, `-classes` the class-driven modules for each class, `-focused` the focused scenes, `-gallery` the gallery scenes); add yours to the one it belongs to, or to a new file next to them, so it fails when the code it draws breaks. They share `render_scenes_lib.lua`, and a gallery scene is picked up by name.

Saved data for a scene turns a module on and marks the first-run setup seen: `{ version = 2, profiles = { Default = { UnitFrames = { enabled = true } } }, characters = {}, layouts = {}, account = { setupSeen = true }, devlog = {} }`.

## What the renderer models

- Anchors: `SetPoint` in every form, by frame or by name, `SetAllPoints`, two-point stretch, sizes, `SetScale` with offsets in the child's scale, parentless frames against the screen.
- Visibility and alpha chains with `SetIgnoreParentAlpha`, and `SetAlphaFromBoolean(secret, on, off)` resolved from the revealed secret (the later of it and `SetAlpha` wins); draw order by strata, frame level (`SetUsingParentLevel`), draw layer, sublevel, creation order; HIGHLIGHT only for hovered frames.
- Textures: file paths under `Interface\AddOns\` mapped to the repository (`KstyleUI\` is the root), numeric file IDs to `Tools/icons/setB/Icons`, then `~/.local/share/wow-dev/icons/blizzard`; `SetColorTexture`, vertex colour (multiply), 4- and 8-value texcoords (affine), `ADD` as `lighter`, desaturation, rotation, gradients, REPEAT tiling at texel size, masks via `destination-in`.
- Status bars: the fill texture covers the bar times its fraction from `SetValue` over `SetMinMaxValues`, or from `SetTimerDuration` with a `{ start, finish }` object against the clock, honouring orientation, reverse fill and a fill from the centre (`SetFillStyle`), and shows the same share of its texture, cropped rather than squeezed, as the client crops it (a harness-wide model: it changes every status bar whose texture varies along its fill, such as 24 pixels of a warrior's partial diamond at 1920x1080) (a region anchored to the fill's edge rides it, as the fill-up widgets' sparks do); `SetStatusBarColor` tints the fill.
- Cooldown swipes from `SetCooldown(start, duration)` or a duration object with `start`/`finish` or `remaining`/`total`, with `SetReverse`, `SetSwipeColor`, the swipe texture as a mask, and countdown numbers unless hidden. A frame whose `GetCountdownFontString` was called draws the number through that font string, as the game does, so the addon's font, colour and anchor place it; any other cooldown draws a default 12-unit outlined number at its centre.
- Text: `SetText` and `SetFormattedText` (secrets revealed), fonts from `SetFont`, `SetFontObject` or the template name (Blizzard names map to Friz Quadrata sizes), colour, shadow, justify, word wrap, `|c`/`|r` colours, links and textures stripped. A text with no width of its own takes an estimated natural width in the solver and its measured width on the page, keeping its anchored side.
- Edit boxes draw their own text inside their text insets, from the left, and from the top when multi-line; an empty box draws nothing, so a placeholder shows through. A scroll frame's child (`SetScrollChild`) hangs from the frame's top left corner moved by the scroll offsets, as the game places it.
- A frame that clips its children (`SetClipsChildren`) bounds everything drawn under it: an item outside the frame's rect is dropped (counted as `clipped`), one across it carries the rect as `clip` and the page draws it through that rect.
- Screen clamping: a frame with `SetClampedToScreen(true)` that reaches past a screen edge moves back inside it, children and all, as the client moves it.
- Pixel snapping: every rect edge rounds to a device pixel.
- A font string that wraps and has a width but no height of its own is as tall as its wrapped lines, counted with the glyph table at the solved width, so a text anchored under it sits under the whole paragraph (`WordWrap` off, or an explicit height, keeps one line).
- Animation groups: a group the addon played (`Play`, recorded by the stub at its clock `env._now`) is sampled at the scene's `time`. `Translation` moves by its offset times progress, `Alpha` replaces the object's own alpha between its from/to values, and `Scale` draws the object, and everything under a frame, scaled about the animation's origin (`SetOrigin`, the centre when unset), text at the scaled size, without moving anything anchored to it. Start delays, smoothing and `SetOrder` are honoured: later orders wait for earlier orders, and the latest started Alpha animation wins. A Scale counts once its start delay has passed, and every started Scale multiplies the others, in its own group, its other groups and its ancestors', each holding its end until its group's pass ends. Blizzard's tuned chains assume that: the prey widget grows 1 to 1.1 and then 1 to 0.909091 (`Blizzard_UIWidgets/Blizzard_UIWidgetTemplatePreyHuntProgress.xml:66-67`), the encounter timeline's pulse 1 to 1.1 and then 1 to 0.9 (`Blizzard_EncounterTimeline/EncounterTimelineTrackEvent.xml:50-53`), and the countdown's digits 0.25 and then 4 (`Blizzard_FrameXML/Timer.xml`). Of the Forever UI source's chained Scales, 32 from/to chains and all 18 relative ones return to rest only when multiplied, while 17 from/to chains, such as the objective tracker's check (`CheckAnim`, `Blizzard_ObjectiveTracker/Blizzard_ObjectiveTrackerAnimTemplates.xml`), read as replacements; the in-game check under Action Bars in [TESTING.md](../../docs/TESTING.md) settles which the client does. `REPEAT` wraps the clock; a finished group leaves its Translation and Alpha animations at their end until `OnFinished` runs, and its Scales stop counting, as the client keeps no final scale (`SetToFinalAlpha` keeps only alpha). A scene that wants mid-flight numbers advances `env._now` as it ticks (`gallery_combattext.lua`).

## Known limitations

- The corrected complete-HUD auto fit exposes addon pixel defects tracked by LEE-5826. At 3840x1080, for example, the data strip, minimap face, loot feed and quest card have off-grid edges while older findings disappear. The pixel audit measures these before Chrome snaps the drawing; its baseline records the generator's counts at the corrected fit.
- The stub draws no world: the minimap and scenery are real screenshot crops when `standins.py` has run; portrait/model art remains a painted stand-in; the minimap's terrain draws through the mask the module set with `Minimap:SetMaskTexture` (`Hud.Terrain`), so its clipped corners read as the game draws them; icons no folder holds draw as flat boxes. A Blizzard atlas draws from the texture cache when `atlas.py` has fetched its sheet, a Blizzard texture named by file path when `atlas.py paths` has fetched it, else either is a grey box.
- Text widths that other frames depend on come from the kit fonts' glyph advances, or from average glyph widths for a face `glyphs.lua` does not list, so a frame anchored to a text in another face can sit a few units off. The page measures the real glyphs for the text itself.
- Blizzard-owned layout is not modelled: the chat window's lines and tabs, the quest tracker's blocks, the tooltip's lines and the world combat numbers over the target are laid out by the scene the way the game would, and say so in the log. Blizzard's POI buttons are not drawn, and the game fades chat tabs when the pointer is away.
- The HUD scene renders the unit frames with round portraits, the unit frames' default.
- Fonts the repository lacks (`Fonts\FRIZQT__.TTF`, `ARIALN.TTF`) fall back to Source Sans on the page; the log names them.
- Tiled textures repeat at one texel per unit of the region's own scale, which is the game's behaviour as far as the owner's screenshots show; check the grain against a screenshot before trusting it.
- Motion is sampled: scenes tick tweens with `W.Tick` and hold the clock, so a fade or a cast reads mid-way, not at a precise frame. Animation groups are sampled at the scene's clock as above.

`layout_shown` renders the real Elements page and six registered panels using the shared Shown rules. `RENDER_GROUP=party|raid|solo` chooses the roster fixture. The positive rules use protected panels and the opposite rules ordinary panels, all in combat; only the panels whose rules match remain visible. Use `RENDER_SCREEN` and `--ppu` for each screen size.

`layout_hud` renders the real chat, data bars, action bars, unit frames and cooldowns in Layout Mode. It collects their resolved mover rectangles into one registry so tags avoid neighbouring modules, with one toolbar and the shipped integration lanes. Use `RENDER_SIZE=auto`, `RENDER_SCREEN` and `--strict --backdrop docs/media/plates/forest-ultrawide.jpg` to check the gameplay video's ultrawide state; `test-render-layout-hud.lua` guards that state without Chrome.

`video_cards` reproduces the 2026-11-20 gameplay report: Medallions, the three-line Tirisfal guide beside eight quests, the live minimap and native durability body (geometry and UVs from Forever XML). Apply drives native placement through the Edit Mode fake. `options_setup` accepts `RENDER_SECTION=Text` (with `RENDER_PAGE=General`) to navigate to that section through the real scroll list. It also takes `RENDER_LOOK=Forged|Clean|Readable` to wear a Look first, `RENDER_SETUP_FEATURES=off` to turn General > Big pictures in setup and One-click Looks off, `RENDER_SETUP_POINT=DPS|Tank|Healer|centred|spread` to point at a layout or arrangement card on the layout step, `RENDER_SETUP_PICK=DPS|Tank|Healer|medallions|frames` to click a layout or HUD style card, and `RENDER_MOTION=full|reduced|off` to set Motion. `python3 Tools/render/setup_pictures.py --plate <game screenshot> --work <scratch>` retakes the setup's big pictures in `Media/Textures/Setup/` as DXT1 BLPs. Chrome cannot read a BLP, so `standins.py` decodes every `Media/**/*.blp` into `Tools/render/out/standins/` before each shot and `scene.lua` draws those copies; with `--no-standins` a BLP the cache lacks is a grey box, which `--strict` fails. Use the four owner screens, `RENDER_SIZE=auto`, `--backdrop` and `--strict`.

### Action bar text and cooldown parity

`actionbars_parity` drives four real action bars through Options and Layout, then collects each state into a matrix: keybind, count, macro and cooldown text at all nine anchors. Item fixtures use rare and epic items, and the cooldown fixture receives the native cooldown event and show callback. `RENDER_PARITY=before` uses style anchors, ordinary item borders and coloured cooling icons. Use `RENDER_SIZE=1` for this component matrix, `RENDER_SCREEN=1920x1080` with `--ppu 1` or `RENDER_SCREEN=5120x1440` with `--ppu 1.3333333333`, and `--backdrop --strict`. `RENDER_CLASS=WARLOCK` shows the owner's socket finish.

### Data bar parity

`databars_parity` switches on the data bar's parity readouts and options through `Options.Write` on fixture data and draws the top bar. `RENDER_DATABARS_ROUND=2` applies round 2's readouts and options instead (the Medallions dock list), `RENDER_DATABARS_DEFAULTS=1` leaves every setting at its default for base-against-branch pixel diffs, and `RENDER_DATABARS_OPTIONS=<key>` opens the Data Bars page at that setting with a short readout list, so the live preview stays legible. Use the four owner screens with `--strict`.

`options_actionbars` accepts `RENDER_OPTIONS_KEY=bar2.desaturateCooldown` (or another real option key) to scroll its settings while retaining the pinned bar picker. `RENDER_EXTRA_BARS=rows|beside` applies that Extra bars layout first; with `RENDER_HUD_STYLE=Frames` the page shows the selector Frames keeps for undoing it. Concurrent renders of the same scene need separate `RENDER_OUTDIR` directories.
