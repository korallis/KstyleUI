# KstyleUI_Meters

Damage Meter skin, our own threat meter and a swing timer.

| Field | Value |
| --- | --- |
| Module name | `Meters`: its switch in `Core/Features.lua` and the `name` it registers with `KstyleUI.Modules.Register` |
| Approach | Mirror |
| Loads | With the core addon, switched off until the player turns it on |
| Files | `KstyleUI_Meters.toc` lists `Meters.xml`, which loads every Lua file in order, so adding a file never edits the TOC |

## Rules

These come from the [design spec](../docs/superpowers/specs/2026-11-07-kstyleui-design.md). The roadmap's Global Constraints and [AGENTS.md](../AGENTS.md) apply too.

- The swing timer uses Forever's `C_SwingTimer` and the `PLAYER_SWING` event. The combat log is closed to addons.
- Threat values are readable on Forever. `C_DamageMeter` values may turn secret in combat: check each with `issecretvalue` and pass secrets only to widget setters.
- Reskins hook with `hooksecurefunc` or `HookScript`, never `SetScript` on a Blizzard frame. They never write fields onto Blizzard frames, and never call Blizzard functions that open or refresh Blizzard windows. Per-frame state goes in `KstyleUI.Safe.Side(frame)`.
- At load the module only registers itself with `KstyleUI.Modules.Register`. It creates no frames, registers no events and installs no hooks until `Enable` runs. `test-modules-load.lua` checks the frames.
- Every element it shows registers with `KstyleUI.Layout.Register`, and every setting is declared through `KstyleUI.Options.Register`, so the player can resize and customise everything from the settings window.
- UI comes from `KstyleUI.Widgets`, colours from `KstyleUI.Tokens` and strings from `KstyleUI.L`. Translations live in the core string tables; see Languages in the repository README.
- Build mode: check that an API exists before calling it, check `issecretvalue` before any comparison, fall back to a safer path when the preferred one is unavailable, and log the path taken with `KstyleUI.DevTest.Log`.

## Files

`Meters.xml` loads them in this order.

| File | What it holds |
| --- | --- |
| `Init.lua` | The addon table and `ns.Place`, which registers a meter with Layout under its element key |
| `SpellSchools.lua` | The school of every non-physical spell ID, written by `Tools/build/gen_spell_schools.py` from `Tools/data/abilities.json`; the client gives addons no school for a spell ID |
| `Logic.lua` | Pure rules with no frames: readable numbers, percentages, rates, spell school colours, swing progress, threat sorting and threat warnings |
| `Bearings.lua` | Each bundled face's ink side bearings for the characters a damage row joins, written by `Tools/media/make_bearings.py`; do not edit by hand |
| `Settings.lua` | The defaults, the settings schema, checked setting reads (`ns.Get`), and the colour and font rules every meter shares |
| `BarList.lua` | The card the damage and threat meters share: the section cap with the title and a count, an aside or the fight switch, rows (the threat meter's over a 4-unit class pill; the damage card's as full-height bars, the picture's), a note line, the spell rows under a hovered row and the warning colour on the count |
| `Swing.lua` | The swing timer. Each bar carries its name just before its time, inside the track where the fill arrives last (**Swing timer** for one bar, the hand's name when two or three stack; round 6, Fable); both follow the time switch |
| `Threat.lua` | The threat meter |
| `DamageSkin.lua` | The restyle of Blizzard's Damage Meter windows and their spell breakdown windows |
| `Damage.lua` | The damage meter window, its fight segments and spell lists, and the choice between it and the restyle |
| `Preview.lua` | The settings window's live preview |
| `Meters.lua` | The module's registration, `Enable` and `Disable`, and one event dispatcher the three parts share |

Tests: `Tools/regression/test-meters-logic.lua`, `test-meters-module.lua`, `test-meters-swing.lua`, `test-meters-threat.lua`, `test-meters-damage.lua`, `test-meters-skin.lua`, `test-meters-drill.lua`, `test-meters-fights.lua`, `test-meters-fit.lua`, `test-meters-hover-side.lua`, `test-meters-card.lua` (the picture's card), `test-meters-group.lua` (a party of five and a raid of twenty) and `test-meters-preview.lua`. `Tools/tests/test_spell_schools.py` checks that the school table is current. `Tools/regression/meters_env.lua` loads the core and the module with stand-ins for the swing, threat and Damage Meter APIs.

## Elements

| Key | Element | Footprint | Size limits |
| --- | --- | --- | --- |
| `meters.damage` | Damage meter | 269 x 158 | 120 to 600 wide, 40 to 800 tall |
| `meters.threat` | Threat meter | 200 x 112 | 120 to 600 wide, 40 to 800 tall |
| `meters.swing` | Swing timer | 260 x 8 | 40 to 800 wide, 2 to 64 tall |

Each element is a holder frame that Layout places, sizes and shows. The meter draws inside it on a child frame, so Layout and the module never show or hide the same frame. A meter switched off in the settings hides its holder too. The rows that fit follow the holder's height: a taller meter shows more rows. A row is never shorter than its text needs, and the rows counted and the rows drawn use the same snapped height.

The **threat meter's** card is the shared card in the card material (the quest card's and the damage card's) with a content inset (`chrome:Inset()`, about 12 units) all round, the cap (`THREAT` with its count, see Threat meter) above its rows and rows that carry a name, a value and a share over a flat 4-unit class pill in the source's colour. Its rows share out whatever the last whole row leaves (`Logic.FillRows`), and its glass hangs from the holder's top and ends one inset under the last row shown.

The **damage card** is the owner's picture (see "The damage card as the picture draws it" below): a fixed card of the holder's size whose rows are bars as tall as the row.

## Damage meter

- **KstyleUI window** (the default). The window reads `C_DamageMeter.GetCombatSessionFromType(session, type)` on `DAMAGE_METER_COMBAT_SESSION_UPDATED`, `DAMAGE_METER_CURRENT_SESSION_UPDATED` and `DAMAGE_METER_RESET`, at most once every 0.5 seconds: an event starts one 0.5-second timer, and every event until it fires rides on it, so a fight's stream of updates costs two reads a second and an idle card costs nothing. Each source becomes a row: the class icon, the name, a bar of its total against the session's top amount in the class colour, the amount (the rate for the per-second types) as a short number (`Logic.Abbreviate`), and its share of the total. Deaths show the time of death. The bars move by the client's eased `SetValue` (`Enum.StatusBarInterpolation.ExponentialEaseOut`), so no Lua runs between refreshes. While the window shows, `Safe.HideBlizzard` hides Blizzard's `DamageMeter` frame, which holds every `DamageMeterSessionWindow<n>`. Switching the meter off, choosing the restyle or turning the module off gives it back with `Safe.RestoreBlizzard`.
- **The group meter** (LEE-430, Lee on v0.0.7: "if im in a group it should show more like the details damage meter does"). In a party or a raid every member the game has a number for gets a row, sorted highest first. Out of combat the card sorts the plain amounts itself; in combat the amounts are secret and cannot be compared, so the rows keep the game's order, which the game sorts (Blizzard's own window builds its list from `combatSources` without sorting, `DamageMeterSessionWindow.lua:621`). The card shows the rows that fit its height; the mouse wheel scrolls the rest. While the player's own row is out of view it is pinned as the last row with its rank ("14. Korallis"), as Blizzard pins the local player; `isLocalPlayer` is never secret, so this works in combat too. A changed meter, fight or source starts again from the top.
- **Damage or healing.** The cap's title is a switch: `DAMAGE  HEALING`, the meter shown in `capsGold` and the other `muted`. A click on it swaps Damage done and Healing done, or Damage per second and Healing per second; from any other meter it goes to Damage done. A right-click on it steps the fight. While the pointer is on the fight switch at the cap's right end, the title shows the selected word alone, so `Now  Last  All` keeps its room. Other meters (Interrupts, Deaths, ...) title the card with their own name.
- **A player's spells.** A click on a row lists that player's spells as the card lists the player's own when alone, titled by the player; a click goes back. Your own row opens the card you see alone: titled by the meter (`DAMAGE`) with your rate, found by `isLocalPlayer`, so it keeps the rate in combat when the GUIDs turn secret (KSTY-60 item 24: the Tank preset's card read "KORALLIS" with no total). The source call needs the player's GUID as a plain value (`SecretArguments = "AllowedWhenUntainted"`). Out of combat every row has it. In combat `sourceGUID` is secret, so only the player's own row opens (with `UnitGUID("player")`), and a list opened before combat keeps updating.
- **Icons.** Each row leads with a square as tall as the row on a black edge: a member's class icon (`GetClassAtlas`, the atlas Blizzard's meter uses, `DamageMeterEntry.lua:543`, checked with `C_Texture.GetAtlasInfo`; without it, `CLASS_ICON_TCOORDS` on `UI-CharacterCreate-Classes`, logged once), or a spell's icon (`C_Spell.GetSpellTexture`, which takes a secret spell ID). `damage.icons` turns them off.
- **Fights.** The window shows the current fight, the previous fight or every fight (overall). The cap's right end is the fight switch, shown while the pointer is on it (at rest the cap's right end is the rate, see below): `Now  Last  All`, the fight shown in `giltLit` and the others `muted`. A click on it steps to the next fight, and so does a right-click on the title; a spell list stays open on the same source. Its tooltip names the last fight as the game recorded it. The previous fight is the newest fight the game still holds (`C_DamageMeter.GetAvailableCombatSessions`) that is older than the current one, read with `GetCombatSessionFromID`. `DAMAGE_METER_COMBAT_SESSION_UPDATED` names the current fight's ID; until it fires, the newest fight held counts as the current one. On the last fight the switch's middle word is the fight's recorded name ("Now  Hogger  All"); when the switch and the title would not fit side by side it reads `Last`, and on a card too narrow even for that it shows the selected word alone, still lit and still a switch. The fit is measured: the cap's title and aside by the game's string widths (estimated from the letters and the font size while the game has no measure, so a long switch never fails open); beside the title the two must leave the cap's 44-unit reserve, and with the title off the words alone must fit the content width. A title too long for the cap even beside the selected word alone (the German "Verursachter Schaden" on a narrow card) is held to the room left of the word and ends in the game's ellipsis; a title that fits keeps its natural width. The fit runs again on every restyle, so a card that changes width keeps the switch inside. While the game hides the data the switch reads "Paused".
- **Spells.** Hovering a source row opens its split under the row, inside the card, as Details! opens a source's breakdown on the row the pointer is on (`BarList`'s `rowSplit`): the top three spells as rows of the card itself, each the card's row (its spell icon, a bar in the spell's school colour against the source's top spell, the name inside the fill, the amount and share at the right), one row pitch apart, then a muted `Click for all N spells` line in the next row's place when the source has more than it lists; a muted chevron follows the name while the row is hovered. There is no box of its own inside the card (KSTY-60 item 24, the bible's 3.2: a card never gets a second border): the card's fill shows behind the spell rows. The split covers whole rows; the rows it covers are held hidden while it is open and come back when it closes. It hangs under the row; near the card's bottom it stands on the row instead, and a card that hugs fewer rows than the split needs grows to its holder's height to hold it, then hugs again. A middle row of a full card can have room on neither side: the split takes the side with more room and lists what fits there (the count line goes first, then the last spells, never the first), so it never covers the cap, leaves the card or hides the hovered row. A refresh or a restyle while it is open places it again on the same row. While combat hides the source the split says the spells show after combat; a death row has no split. In the spell list a row's tooltip says a click goes back; no tooltip opens for a source row. Click a name for that source's spells: `GetCombatSessionSourceFromType` (or `GetCombatSessionSourceFromID` for the previous fight) with the source's GUID or creature ID. Each spell row shows the spell's name (`C_Spell.GetSpellName`, which accepts secret IDs), a pet's name after its spells, the amount and the share of the source's total, as a bar in the spell's school colour with no icon (the picture's rows). The title names the source. A click anywhere in the window goes back to every source, and so does choosing another meter. Deaths have no spell list. The source calls refuse secret arguments from addon code, so a source whose GUID is secret (in combat) opens nothing.
- Click the title for the next meter type. The meter type and the fight write the settings, so the choice is kept.
- **Combat.** On a client that hides the data from addons in combat, the window keeps the rows it read last and the column reads "Paused" until the data comes back. A view chosen in combat (another meter, fight or source) has nothing to keep and says "Hidden in combat".
- **Alone, the card is your spell list.** Out of a group, a meter that has spells (every type but Deaths and Enemy damage taken) opens on your own spells at rest, titled by the meter, as the picture's card is; a group lists the sources as before. The card reads your GUID with `UnitGUID("player")` (`SecretWhenUnitIdentityRestricted` in `UnitDocumentation.lua`, so the value is checked as a plain string before it is passed to `GetCombatSessionSourceFromType`) and falls back to the sources list when the GUID is secret or the source call is missing. Clicking a spell row does nothing, because there is no list behind it to go back to.
- **Shown solo.** The meter shows while you play alone, in either style (owner, 2026-11-09: no meter was on screen solo). **Only in a group** (off by default) hides it while you play alone: KstyleUI's window hides, and Blizzard's restyled window is held hidden with `Safe.HideBlizzard` and given back in a group. The Store never saves a default value, so a player who never set it got the new default with no migration; a player who switched it on keeps it.
- **Blizzard's switch.** The game draws its own damage meter only while the account CVar `damageMeterEnabled` is `1` (`DamageMeterMixin:ShouldBeShown`), and it is `0` on a fresh account. While the restyle runs, `DamageCVar.lua` turns it on out of combat and keeps the player's value in `KstyleUIDB.account.damageMeterCVars`. Switching the meter off, choosing KstyleUI's window or turning the module off gives the player's value back, and the core's login sweep (`Core/CVars.lua`) does the same on a character where Meters is off. A player who already had it on keeps it on. Edit Mode's visibility setting for Blizzard's meter stays the player's.
- **Restyle Blizzard's window.** One meter design (KSTY-60 item 24): `DamageSkin.lua` strips the header and background art of each session window with `Skin.Strip`, puts the card's material behind it with `Skin.Backdrop`, restyles its scroll bar with `Skin.ScrollBar`, and draws the card's heading and rows. **The heading** is the card's section cap (`Widgets.SectionCap`: diamond, the meter type in the caps face, the rule, and Blizzard's fight timer as the count at the right), on a KstyleUI frame over the header, its left 12 units in and its middle 13.5 units down, level with the fight dropdown (`DamageMeterSessionWindow.xml`), its right end one gap before that dropdown. Blizzard's type name and timer are hushed (alpha held at 0 by a hook on their `SetAlpha`) and mirrored through hooks on their `SetText`, so a secret text passes straight to the cap; the type dropdown's art is stripped and its button still opens the type menu under the cap, and the fight, settings and minimise controls stay where Blizzard puts them. **Each row** is the card's row: Blizzard's full-height fill and its shadow art are hushed, and a flat `Widgets.StatusBar` on the `buttonFill` track fills Blizzard's bar rect from a KstyleUI holder one level under Blizzard's bar, so Blizzard's name and value draw over it. It mirrors Blizzard's bar through hooks on its `SetMinMaxValues` and `SetValue`, so a secret value passes straight to the setters, in the meter's texture, fill direction and colour source, class colours toned as the card's. Blizzard's name and value texts keep their places (the skin never anchors Blizzard's text) and take the card's faces (the body face for the name, the figure face for the value) in `textEmphasis`. A hook on each row's `UpdateValue` rewrites the value text with the card's own formatter (`Logic.Abbreviate` and the share after a middle dot, "284K · 30%"); a death row keeps Blizzard's time, and a secret amount shows the game's abbreviation with no share. Edit Mode keeps placing the window. Hooks: `DamageMeter.SetupSessionWindow` for windows opened later, each window's `Refresh` for its rows, and each row's `UpdateStatusBarColor`, so the colour source wins over Blizzard's colour. The spell breakdown window Blizzard opens on a click (`GetSourceWindow()`) wears the same material, scroll bar, close button and rows, through a hook on its `Refresh`; Blizzard reads it untainted, so it shows spells in combat too.

## What the client gives addons

Proved from the 70862 source (`~/.capy/work/wow-ui-source-70862`, the `forever` branch at 9dc84f0), not from memory of another client.

- **Calls** (`Interface/AddOns/Blizzard_APIDocumentationGenerated/DamageMeterDocumentation.lua`): `GetCombatSessionFromType(sessionType, type)` and `GetCombatSessionFromID(sessionID, type)` return a `DamageMeterCombatSession` (`combatSources`, `maxAmount`, `totalAmount`, `durationSeconds`); `GetCombatSessionSourceFromType` and `GetCombatSessionSourceFromID` take a source GUID or creature ID and return a `DamageMeterCombatSessionSource` (`combatSpells`, `maxAmount`, `totalAmount`); `GetAvailableCombatSessions`, `GetSessionDurationSeconds` and `IsDamageMeterAvailable` carry no secret flag. The three events are `DAMAGE_METER_COMBAT_SESSION_UPDATED(type, sessionID)`, `DAMAGE_METER_CURRENT_SESSION_UPDATED` and `DAMAGE_METER_RESET`. The enums are in `DamageMeterConstantsDocumentation.lua`.
- **Secret flags.** The four session and source calls are `SecretWhenInCombat = true` with `SecretArguments = "AllowedWhenUntainted"`: in combat the values they return are secret, and an addon cannot pass a secret GUID back in. The table and its `combatSources` array stay indexable: the structure marks `classFilename`, `isLocalPlayer`, `deathRecapID` and `classification` `NeverSecret` (`DamageMeterDocumentation.lua:202-209`), which would mean nothing if the table itself were hidden, and Blizzard's own window indexes and writes to it (`DamageMeterSessionWindow.lua:621-638`). `Readable` still checks `issecretvalue` and `canaccesstable` before it indexes, so a client that does hide the table shows the rows read last under "Paused". `C_Secrets.HasSecretRestrictions()` (`SecretPredicateAPIDocumentation.lua`) decides nothing here: it says whether secrets exist, and the card handles both cases. A `DamageMeterCombatSource` has `classFilename`, `isLocalPlayer`, `deathRecapID` and `classification` `NeverSecret`; `sourceGUID` and `name` `ConditionalSecret`; `specIconID` `SecretValue`; `totalAmount`, `amountPerSecond`, `sourceCreatureID`, `deathTimeSeconds` and `sourceDisplayType` carry no flag of their own and follow the call's. A `DamageMeterCombatSpell` (`spellID`, `totalAmount`, `amountPerSecond`, `creatureName`, `overkillAmount`, `isAvoidable`, `isDeadly`) carries no per-field flag either.
- **How amounts and shares show in combat without arithmetic on a secret.** `Readable` (`Damage.lua`) tests `issecretvalue` and `canaccesstable` before a table is indexed, and a table the game hides keeps the rows read last under "Paused". When the table is readable but a field is secret: the bar gets the amount and the top amount through `StatusBar:SetMinMaxValues` and `SetValue`, which accept secrets; the amount and the rate go through `Logic.Abbreviate` (`AbbreviateNumbers` with KstyleUI's breakpoints; `LocalizationDocumentation.lua`: `SecretArguments = "AllowedWhenTainted"`) straight into `FontString:SetText`; names go straight to `SetText`; the share is `Logic.Percent`, which returns nothing for a secret part or total, so the share's text is empty and its dot with it. Nothing compares, adds or formats a secret. Blizzard's own window does the arithmetic on them because its code is untainted; ours cannot, so the share and the sort stay the game's: the rows keep the order the game's session list holds (the game sorts it) and a secret amount shows no share while combat lasts.
- **Short numbers.** `Logic.Abbreviate` writes a whole number under 1000, one decimal from 1K to 10K, whole numbers above, and K, M and B ("412", "1.2K", "12K", "1.2M"). The game's `AbbreviateNumbers` with no breakpoints writes a number under 1000 whole with every digit ("7.7643575668335"; the first in-game test of v0.0.7 showed it on every row), because its default breakpoints start at 1000 (the function was FrameXML before 12.0 and ended in `return tostring(value)`; `LocalizationSharedDocumentation.lua` pairs 1,000 with 10,000 for a caller's own list). A plain number is therefore formatted in Lua from the module's own breakpoint list and never reaches the game. A secret cannot be rounded in Lua, so it goes to `AbbreviateNumbers(value, { breakpointData = ... })` with the same list (`NumberAbbrevOptions` in `LocalizationDocumentation.lua`; GroupFrames does the same for missing health). The first secret call probes the breakpoints with four plain numbers and keeps the game's own `AbbreviateLargeNumbers`, the call Blizzard's damage meter makes (`DamageMeterEntry.lua:125`), when the client refuses them or answers differently. A secret under 1 has no breakpoint and shows the game's default text.
- **The rate in the cap** is the local player's `amountPerSecond` (found with `isLocalPlayer`, `NeverSecret`, or by GUID for an opened source). A plain rate goes through `Logic.FormatRate`: one decimal below 1000 ("38.4 dps"), `Logic.Abbreviate` above; a secret rate is `Logic.Abbreviate` of the secret joined to the unit ("38 dps", "12K dps"): tainted code may concatenate a secret, and the result stays secret, so it goes to the cap's separate figure text and never to a comparison.
- **Spell school.** The client gives none for a spell ID: `C_Spell.GetSpellInfo` returns `SpellInfo` (`name`, `iconID`, `originalIconID`, `castTime`, `minRange`, `maxRange`, `spellID` in `SpellDocumentation.lua`), `GetSchoolString` only names a mask you already have, `DamageMeterCombatSpell` has no school, and `Blizzard_DamageMeter` reads none. The colour therefore comes from the repository's ability data, `Tools/data/abilities.json` (build 1.60.1.70840: every rank's spell ID with its school mask), through `SpellSchools.lua`. A spell with several schools takes the first of holy, fire, nature, frost, shadow, arcane (the order `KstyleUI_CombatText` uses); a spell the data lacks, and every auto attack, is physical.

The settings stay; only their defaults changed.

It keeps the holder's whole height whatever the rows: a rail-foot card that hugged its rows would float off the screen margin.
- **The cap** is the kit's section cap (`Widgets.RailCap`, the pattern the story card's `QUESTS` uses): a gem, the meter's name in the kit's `caps` role (Folio Caps in Folio, Cinzel Caps in Lumen; uppercase, the tracking built into the font, never thin spaces; `Widgets.SectionCap` sets it up) (`DAMAGE` for Damage done and Damage per second; the other meters keep their names), a gilt rule and the rate at the right end in the bold figure face in `textEmphasis` (`38.4 dps`; `hps` for the healing meters; nothing for the others). The caption is `capsGold`, the picture's card-caption gold. The cap sits 12 units from the card's left and top and 15 from its right, so its centre is 18 units down and the gem's centre 17 units in, as the picture's is. At rest the cap names the meter, never the source (alone, the card is your spell list; opened on a source in a group it is titled by that source).
- **The fight switch** does not show at rest. It lives under the cap's right 120 units: hovering there shows `Now  Last  All`, a click steps to the next fight, and the `damage.session` setting and the right-click on the title are as before.
- **The share** follows the amount with the middle dot as its own piece. The ink gap is 5/21 of the font (5 px against the 21 px the 12-unit number face draws on the 3456 by 2234 reference screen), snapped to the panel's pixel and never under one pixel, so a larger font and a smaller screen keep the proportion. The drawn face's side bearings are taken out of that gap, so a trailing 1 does not open a wider hole than a trailing 4. They come from the font files: `Tools/media/make_bearings.py` writes `Bearings.lua` for every face in `Media/Fonts`, and `Tools/tests/test_make_bearings.py` fails when a rebuilt font leaves it stale. Folio's PT Serif Bold, Lumen's Alegreya Sans ExtraBold, a face picked for the `number` role and a bundled face chosen for the meter each use their own. A face KstyleUI does not ship (a LibSharedMedia font) has no table and uses the default bearing. A path the client hands back in another spelling finds the same file. A share that cannot be worked out leaves no dot.
- **The rows** are five bars 18 units tall, pitch 21 (`damage.rowHeight` 18, `damage.spacing` 3), 15 units in from the card's edges, the first 35 units under the card's top. The bar is a `Widgets.StatusBar` the height of the row on the `buttonFill` track, flat (the kit's keyline, highlight and shade are off), in the `Flat` texture; the fill is the share of the top row. The name sits inside the fill at the left in the body face and the amount and share at the right in the bold figure face, all in `textEmphasis`, 7 units in, on a child frame above the bar. The share's middle dot is its own font string (U+00B7, present in the Alegreya Sans faces), so a share that cannot be worked out leaves no dot. The overhaul's card (KSTY-44's plan, row 12: "school colour fill, icon, name, amount and share") puts the icon square at the row's left with the bar 2 units after it, so the name sits 7 units inside the fill, after the icon. There is no class line.
- **Colour.** `damage.colorSource` defaults to "By spell school": a spell takes its school's colour (tokens `meterNature` 2e7d4f, `meterFire` b4501f and `meterPhysical` 7a6a52, measured from the picture; `meterFrost`, `meterShadow`, `meterArcane` and `meterHoly` in the same muted key, appended to `Core/Tokens.lua`); a source in a group list takes its class colour, as before. Class colour, Reaction colour and Custom colour are still choices.
- **The threat meter** keeps its pill rows; it shares `BarList` through the `block` option the damage card passes.


## Threat meter

- The group is the player, the pet, and the party or raid members and their pets. The pets switch leaves pets out. In a raid the player and the player's pet appear once.
- The mob is the target when the player can attack it, or else the target's target, so a healer who targets the tank sees the tank's target.
- `UnitDetailedThreatSituation(unit, mob)` gives each row. Rows sort by the scaled percentage, highest first. The bar runs from 0 to 100% of pulling aggro. The value column shows threat points: Blizzard's raw threat divided by 100. Updates run at most once every 0.2 seconds.
- **The count** at the cap's right end is the figure the warning watches (KSTY-60 item 23): your own share of aggro while you are not tanking, the closest member's while you tank. A secret share passes through to the count whole. With no hostile target there is no count.
- Warnings: a player who is not tanking is warned at `warnAt` and in danger at `dangerAt` of their own threat. A tank is warned when another member reaches those percentages. A warning colours the count `neutral`, danger `hostile`. The card itself never changes: the bible's 3.2 gives a card no second border and no glow, and the old warning edge drew the bright gilt outline that made the threat card unlike every other card (KSTY-60 item 23).

## Swing timer

- One bar per hand: main hand, off hand and ranged. A bar shows when its switch is on and the weapon is there (`UnitAttackSpeed` gives an off-hand or ranged speed), or while a swing runs.
- `PLAYER_SWING(duration, type)` starts a bar. One `OnUpdate` on a parentless driver frame fills the bars while a swing runs and stops when none does.
- With **Hide when idle** on, the bars show only in combat or while a swing runs.
- **Dim out of range** follows `PLAYER_SWING_RANGE_UPDATE` (after `C_SwingTimer.EnableRangeCheck`) and `C_SwingTimer.IsTargetWithinSwingRange` on target changes. As in Blizzard's timer, a running swing never dims, and no answer is not out of range.
- While the swing timer runs, `SwingTimerMainHandFrame`, `SwingTimerOffHandFrame` and `SwingTimerRangedFrame` are held at alpha 0: a `hooksecurefunc` on each frame's `SetAlpha` sets it back to 0. The hook records the alpha Blizzard asks for, so switching the swing timer or the module off restores it.

## Settings

The page has an accent section and one section per meter. Every meter has its text font (the interface font or any KstyleUI or LibSharedMedia font), text size and outline (a soft shadow, thin or thick). Bars have a texture, a colour source (class, reaction or a custom colour) and a direction: the damage and threat bars grow from the left or the right, and the swing bars are horizontal or vertical and may fill in reverse. The damage and threat meters set their row height, row spacing, title and title size. The damage meter adds its style, meter type, fight (current, previous or overall), a group-only switch (off by default, for both styles), percentages and icons. The style list names what Automatic picked on this client. The threat meter adds a group-only switch, pets, the numbers to show and the warning thresholds. The swing timer adds a switch per hand, hide when idle, range dimming, bar spacing and the time.

## Logs

The module logs to the devlog, once each: a missing Blizzard frame or API and the path taken instead, a secret swing duration or type, secret threat values, Damage Meter data that is hidden, and the switch to the restyle.

## Why

- **A holder per element.** Layout shows, hides and fades the frame it places. The meters also show and hide their content (group only, hide when idle), so each draws on a child of the holder and the two never fight over one frame.
- **Our own card is the default, secrets or not.** Layout Mode never moves a Blizzard frame, so only KstyleUI's own window can sit at `meters.damage` and follow the setup's layouts. The window passes secret values straight to `SetMinMaxValues`, `SetValue`, `SetText` and `AbbreviateNumbers`, which take them (`SimpleStatusBarAPIDocumentation.lua:229,355`, `SimpleFontStringAPIDocumentation.lua:664`, `LocalizationDocumentation.lua:26`, all `AllowedWhenTainted`). An earlier version read `C_DamageMeter`'s `SecretWhenInCombat` flag as "the table is hidden" and picked Blizzard's restyled window whenever `C_Secrets.HasSecretRestrictions()` was true, which it is on the owner's client; he then saw Blizzard's window in our frame instead of the card (KSTY-33). So `auto` is the window whenever `C_DamageMeter` exists, and the restyle only without it or by choice. What a secret cannot do in combat is a share, which is arithmetic; it comes back the moment the data is plain.
- **Restyling needs a reload to undo.** Hushed textures and hooks stay on Blizzard's frames, so leaving the restyle prints a `/reload` request and fires `ReloadNeeded`. The module is not marked `reskin`, because its default style changes no Blizzard frame.
- **Blizzard's swing timers are faded, not hidden.** They are bottom managed frames: `ManagedFrameContainerMixin:UpdateFrame` reparents them to its container on every layout pass, which would undo `Safe.HideBlizzard`, and Edit Mode sets their alpha from its opacity setting. Holding the alpha at 0 survives both. They take no mouse input, so an invisible timer blocks nothing.
- **No CVar changes.** Turning `showSwingTimer` off would hide Blizzard's timers too, but it changes the player's own setting and it is not known whether `PLAYER_SWING` still fires without it.
- **Secret swing durations.** `PLAYER_SWING` does not mark its duration secret. If it ever is, the bar is handed to the engine through a `C_DurationUtil` duration object and `SetTimerDuration`. `SetTimeFromStart` refuses secret arguments from addon code, so the call is guarded and a refusal is logged.
- **Threat is read every 0.2 seconds at most.** `UNIT_THREAT_LIST_UPDATE` fires for every mob in combat. A scheduled update with one prepared function keeps the cost flat and allocates no closure per event.
- **Threat points are raw threat divided by 100.** Blizzard's raw threat is a hundred times the threat points players compare. A secret raw value cannot be divided, so it is shown through `Logic.Abbreviate` as the game gives it.
- **Warnings only on readable values.** A warning compares percentages, which a secret value forbids, so a secret percentage or tanking flag never warns and a secret value leaves the group's order unsorted.
- **No tables in combat paths.** Setting reads cache each key's path, rows and their tables are reused, and a bar's colour changes only when it differs. `test-meters-logic.lua` measures the helpers with the garbage collector stopped.
- **The amount and the middle dot are off the pixel grid on purpose.** Since #330 every region should land on whole physical pixels (`Widgets.Point`), and the row's name and share do. The amount and the dot are placed by the drawn face's side bearings (`BarList.JoinOffsets`), so the *ink* gap each side of the dot is a whole number of pixels, 5/21 of the font (5 px on the reference screen; `test-meters-card.lua` checks it on nine screens). Snapping their anchors instead would put that visible gap up to half a pixel off. So `Tools/regression/pixel_allow.tsv` keeps a BarList line per scene and screen for these two anchors per row, and it cannot reach zero. The Captain accepted this as a documented exception on 2026-11-13.
- **Class colours on the card are toned to 62%** (`ns.DAMAGE_CLASS_TONE`), so white names read on priest white and rogue yellow and the group rows sit at the school colours' depth. Blizzard's restyled rows take the same tone, since their names sit inside the fill too. The Captain accepted this on 2026-11-13.
- **Weak-keyed tables for Blizzard frames.** The restyle and the alpha hold keep their state about Blizzard's frames in the module's own weak-keyed tables, as `Safe.Side` does, because the restyle also walks every window and row it has touched when a setting changes. No field is written onto a Blizzard frame.
- **One event frame.** The core gives each module one event frame with one handler per event. The three parts share it through `ns.Watch` and `ns.Unwatch`, so an event is registered only while a part that is on needs it.
