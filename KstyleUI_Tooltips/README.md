# KstyleUI_Tooltips

Tooltips drawn as the quest card (the KSTY-44 design bible, plan row 13), quality and class colours, optional spell and item IDs, and cursor anchoring.

| Field | Value |
| --- | --- |
| Module name | `Tooltips`: its switch in `Core/Features.lua` and the `name` it registers with `KstyleUI.Modules.Register` |
| Approach | Reskin |
| Loads | With the core addon, switched off until the player turns it on |
| Files | `KstyleUI_Tooltips.toc` lists `Tooltips.xml`, which loads every Lua file in order, so adding a file never edits the TOC |

## Rules

These come from the [design spec](../docs/superpowers/specs/2026-11-07-kstyleui-design.md). The roadmap's Global Constraints and [AGENTS.md](../AGENTS.md) apply too.

- Reskins hook with `hooksecurefunc` or `HookScript`, never `SetScript` on a Blizzard frame. They never write fields onto Blizzard frames, and never call Blizzard functions that open or refresh Blizzard windows. Per-frame state goes in `KstyleUI.Safe.Side(frame)`.
- Tooltip content changes use `TooltipDataProcessor.AddTooltipPostCall`.
- Blizzard frames keep a reskin after `Disable`, so turning the module off asks the player to reload.
- At load the module only registers itself with `KstyleUI.Modules.Register`. It creates no frames, registers no events and installs no hooks until `Enable` runs. `test-modules-load.lua` checks the frames.
- Every element it shows registers with `KstyleUI.Layout.Register`, and every setting is declared through `KstyleUI.Options.Register`, so the player can resize and customise everything from the settings window.
- UI comes from `KstyleUI.Widgets`, colours from `KstyleUI.Tokens` and strings from `KstyleUI.L`. Translations live in the core string tables; see Languages in the repository README.
- Build mode: check that an API exists before calling it, check `issecretvalue` before any comparison, fall back to a safer path when the preferred one is unavailable, and log the path taken with `KstyleUI.DevTest.Log`.

## What it restyles

`GameTooltip`, `ShoppingTooltip1` and `2`, `ItemRefTooltip`, `ItemRefShoppingTooltip1` and `2`, and `EmbeddedItemTooltip`. A tooltip missing on the client is logged and skipped.

| Part | How |
| --- | --- |
| Border | `Skin.Strip` sets the alpha of every texture of the tooltip's `NineSlice` to 0 and hooks its `SetAlpha`. Only the `NineSlice` is stripped: the tooltip's own `Texture1` to `Texture30` hold inline icons. |
| Card | A child frame of KstyleUI's own with a window `Chrome` on all points of the tooltip: the card material the player picked (forged iron with brackets by default, the quest card's surface), opaque under every material but Glass (`popup`). `SetUsingParentLevel(true)` draws it at the tooltip's level, behind the text, as Blizzard's `NineSlice` does. It carries no crest: the bible allows ornament on a card's corners and its heading rule only. |
| Edge | The chrome's inner hairline, `edgeInner`, as in the kit. With `qualityEdge` on, an item of uncommon quality or better lights it in `Theme.QualityColor`. `OnTooltipCleared` and `OnHide` return it to `edgeInner`. |
| Rule | Every tooltip with two lines or more draws one rule, one border thick 1 unit under its header (the title line, which on an item holds the caption too), and no other: the quest card's heading rule, the material's `rule` texture (it fades to the right) in `materialGold` at half strength, or `ruleFade` in gilt on a material without one. On an item, the stat lines (`+24 Agility`: a line that starts with a plus and a digit) that softened from white or gold read in the accent; a stat Blizzard coloured keeps its colour. The rule follows the `divider` switch; the stat colour follows `softColors`. |
| Heading diamond | A tooltip that draws the rule is a card heading (KSTY-60 item 17): the card heading's 8-unit diamond in the material's gem (`materialGold`, or gilt on a material without one) stands 7 units before the title, centred on its first line. The left padding grows by its 15 units, so every line keeps the column the title starts on and the C++ layout sizes the tooltip with the room in it; Blizzard's text is never rewritten for it. The embedded item tooltip, which has no padding hooks, draws none. The settings preview draws the same diamond through `Style.PlaceGem`. |
| Fade | Each tooltip fades in from clear over 0.12 s (`hover`) once per opening: an `Alpha` animation group on the tooltip that the client plays (`SimpleAnimAlphaAPIDocumentation.lua`), never a Lua tween. Repeated shows and a hide/show within one refresh keep it opaque; a tooltip still hidden on the next frame can fade on its next opening. Motion set to reduced or off shows it at once. |
| Measuring | Nothing measures a tooltip that follows the cursor (`GetAnchorType` reads `ANCHOR_CURSOR...`, `TooltipComparisonManager.lua:77`) or whose anchoring the game restricts (`IsAnchoringRestricted`, `SimpleScriptRegionAPIDocumentation.lua:400`): `Style.Measurable` says no, and the icon then takes its size setting instead of the lines' height. The card's chrome reads only its own width and height, which the game answers on a restricted region. |
| Type | The title roles are the type set's data, read through `Tokens.TypeDefault("tooltipName")` and `Tokens.TypeDefault("tooltipTitle")`; no tooltip file names a type set. Folio unit, spell and aura names use `names`; item and general titles use `body`. Lumen retains its original `heading` title face. Title and body sizes stay 11, the rarity caption `caption` 9, pitched half a unit apart through `SetCustomLineSpacing`. White and gold lines soften to `text`; Blizzard's green and red lines (the comparison deltas) soften to `friendly` and `hostile`. |
| Title | Blizzard's title data keeps its original case; the names face supplies Folio capitals without rewriting the name. Item names and descriptions retain mixed case. `Logic.TitleText` strips the thin spaces an earlier tracked title carried and the reserved line before it works, so Blizzard's second post-call on the same tooltip changes nothing. An item's name takes `Theme.QualityColor` from uncommon up (the kit's `rare` and `epic` tokens, the game's colours otherwise), and its title gets a blank second line that holds the caption: `Item level N` (`C_Item.GetDetailedItemLevelInfo`) and `ITEM_QUALITY<n>_DESC` joined by a middle dot, or the rarity alone when the level is unreadable or Blizzard's tooltip already carries an `ITEM_LEVEL` line, so the level never shows twice. The caption is in the small line font (never larger than the title's, so it fits the line kept for it), in the muted `text` colour. A title that is secret or holds escape codes keeps Blizzard's text. |
| Line colours | Lines in Blizzard's `NORMAL_FONT_COLOR` gold become `text`, lines in `HIGHLIGHT_FONT_COLOR` white become `textEmphasis`. Green, red, grey and quality colours stay. |
| Icon | On every restyled tooltip but `EmbeddedItemTooltip`: the kit's icon chrome (`Widgets.IconChrome`, the near-black button body with the rim's halo) inside the top left corner, 9.5 units in, with the item's or spell's icon, cropped and masked by `iconMask`, set through `SetTexture` (the loose-file icon pack supplies the repaint). Its size is `iconSize` (the design's 50 units), or the height of the tooltip's lines when they are shorter, so it never hangs below the panel. The tooltip's left padding (`SetPadding(right, bottom, left, top)`) moves every line into a column 11 units right of the icon: the padding is the inset plus the icon plus 11, less Blizzard's own 10-unit text margin. Its hairline is the rarity colour with a `selection` glow from uncommon up, `text` at 35% for poor and common items, and the accent at 50% for spells, as an action button at rest. It hides, and the padding returns to 0, when the tooltip clears. |
| Embedded items | `GameTooltip.ItemTooltip` and `EmbeddedItemTooltip.ItemTooltip` (quest rewards) lose Blizzard's `IconBorder` by alpha. A `buttonFill` tile two borders outside the icon takes the colour Blizzard gives `IconBorder` through a hook on its `SetVertexColor`, or `edgeInner` while it is hidden. |
| Compare label | The shopping tooltips' `CompareHeader` loses its art and its label (alpha 0) and carries a card heading of KstyleUI's own (KSTY-60 item 26 retired the steel-blue `buttonFill` slab): a strip of the tooltip's own card material, 2 units clear of the card under it, with the heading diamond and the label's text in the caps face and `capsGold`. The text is copied from Blizzard's label each time the tooltip is decorated, upper-cased by the caps role. The strip is a child frame, so `Skin.Strip`'s show hook never hides its diamond. |
| Close button | `ItemRefTooltip.CloseButton` gets `Skin.CloseButton`. |
| Fonts | `GameTooltipHeaderText`, `GameTooltipText` and `GameTooltipTextSmall` take the title, line and small line fonts. A name title receives a per-instance face whenever the set's `tooltipName` role differs from its `tooltipTitle` role (Folio today), removed on clear, hide, reuse or Disable; visible titles follow theme, profile and scale changes. Each tooltip scale pass, the first one at Enable included, re-lays the compare header's heading strip, its diamond and caption and the embedded item border at the tooltip's own scale; a type-set or font change reaches them through the core theme restyle. Either way a change at run time lands exactly where a fresh load with that setting does (`test-tooltips-runtime-restyle.lua`). `Disable` restores Blizzard's fonts and shadows. |
| Scale | Each tooltip's scale makes one tooltip unit one root unit, times the anchor element's scale. `Disable` restores each tooltip's own scale. |

## Content

One post-call for every tooltip type runs in this order, so the tooltip sizes itself once with all of it:

1. Soften Blizzard's gold and white lines.
2. The type's part:
   - **Item**: the quality edge, the title and rarity caption, the item and icon ID lines, the icon.
   - **Spell** and **UnitAura**: the title, the spell and icon ID lines, the icon.
   - **Unit**: the name in its class colour (players) or reaction colour (everyone else), `<Guild>` or `<Guild> Rank` on Blizzard's guild line (the line whose text is the guild name, bare or in brackets) in `friendly` green for your own guild and `textEmphasis` otherwise, a `Target` line with the target's name in its colour or `You` in the accent, the unit edge, and the health bar's colour.
   - **Object**: nothing but hiding the health bar: Blizzard watches an object's health too, and the card shows a bar on units only.
3. The heading rule, once the lines are final.

Every value from the game is checked with `issecretvalue` before it is compared. A secret GUID skips the unit's lines; a secret class falls back to the reaction colour; a secret target name adds no line; a secret item or spell ID adds no ID line and no icon. Each skip is logged once.

## Health bar

Blizzard's `GameTooltip.StatusBar` keeps working: its own post-call starts and stops its watch on the unit, and its `OnUpdate` sets its value. The module hides its art by alpha, hooks its `SetValue` with `hooksecurefunc`, and passes each value straight to a KstyleUI `StatusBar` on the glass, so a secret health percentage reaches the engine untouched and Lua never reads it. The KstyleUI bar shows and hides with Blizzard's through `HookScript`. It shows on units only: Blizzard's own rule also watches an object's health (`TooltipDataRules.HealthBar` is a post-call for both `Unit` and `Object`, `Blizzard_SharedXMLGame/Tooltip/TooltipDataRules.lua:130-141`), so KstyleUI's bar shows only after a `Unit` post-call (or one whose data type cannot be read) and hides again on any other type and on clear (`Health.SetUnit`).

The bar docks inside the tooltip's glass: horizontal along the bottom edge (8 units up, 10 in from each side, level with the text margin) or vertical inside the right edge, with the texture, colour source, fill direction and thickness from the settings, a `track` background and a tile border on the button grade. The tooltip makes room for it through its padding: `Style.Reserve(tooltip, right, bottom)` adds the bar's thickness plus a 4-unit gap (`Health.GAP`) to the bottom (or right) padding while Blizzard's bar is shown, on top of whatever padding Blizzard set, and takes it back when the bar hides. Because the padding is part of the tooltip's own rect, screen-edge clamping and the anchor corner account for the bar. When a tooltip's padding reads as missing or secret, the bar hangs outside the glass as before, below or beside it.

## Anchor

`Anchor.lua` builds an empty 180 by 24 frame on `KstyleUI_Root` and registers it with Layout as `tooltips.anchor`, scalable, at the DPS position from `Setup.Layouts`: 8 units over the readout card's right corner, on no card, so a tooltip grows up the right rail and never covers the readout or the menu you hover. Its mover plate shows in Layout Mode; it draws nothing otherwise.

- **Mouse cursor out of combat** (the default): the hook on `GameTooltip_SetDefaultAnchor` follows the mouse with the cursor offsets outside combat and uses the placed anchor in combat. It checks `InCombatLockdown()` when the tooltip is anchored; a tooltip already open may keep its position until it next opens. New profiles and profiles with no saved position inherit this choice; values actually present in saved data stay as chosen. Older versions discarded **Tooltip anchor** at logout even when a player chose it explicitly, because it matched the old default. Those players also move to the new default and can choose **Tooltip anchor** again in Options; it is saved from this version onward. If combat state is unavailable or secret, it uses the placed anchor.
- **Tooltip anchor**: the hook moves `GameTooltip` to the anchor's corner nearest the screen corner, so a tooltip at the bottom right grows up and to the left. Only tooltips Blizzard puts at its default place move; a tooltip a button anchors to itself stays there. Choosing this restores the previous default behaviour in and out of combat.
- **Lift**: a tooltip that grows up first rises over the threat card and the target of target when either is shown in its column (`Anchor.LIFTS`: 300 units wide from the anchor's growing edge, 240 units up from the anchor), a large gap clear of the topmost (`Logic.Lift`, `Anchor.Lift`), so it never covers who holds aggro. Each card's rect is Layout's own (`Layout.Rect`), never a measurement. A tooltip that grows down never lifts. LEE-1535: under every HUD style the item tooltip covered the threat card.
- **Mouse cursor**: the hook calls `SetOwner(parent, "ANCHOR_CURSOR_RIGHT", cursorX, cursorY)`.
- **Open in-game check**: the engine places the three cursor anchors. Forever's source only names them (`Blizzard_AuraButton.lua:45-50`) and the stubs cannot place them, so whether a cursor tooltip covers the pointer or the row it is on (an action bar row, a unit frame) is unproven. An in-game capture of where `ANCHOR_CURSOR_RIGHT` puts the tooltip relative to the pointer decides whether the cursor offsets need a default clearance. KstyleUI's own tooltips open on the side of the hovered item that has room on the screen (`Core/Widgets/README.md`, `test-tooltip-clear.lua`).
- **Keep minimap clear** (on): minimap tooltips open beside the map toward the screen centre in every position mode. Owners are checked through their parent chain against `Minimap`, `MinimapCluster` and the registered `minimap.main` frame, covering nested buttons and the module's controls. Native blips need the `SetMinimapMouseover` hook too: Forever's `Blizzard_Minimap/Mainline/Minimap.lua:279` sets their owner to `UIParent` and resets cursor anchoring on every update. The `SetOwner` hook applies initial placement; the `OnShow` hook restores it when addon buttons clear and replace the points after setting their owner. `SetAnchorType("ANCHOR_NONE")` preserves the owner and lines before placing the tooltip. The core widget tooltip factory is post-hooked lazily to install one `Show` post-hook on its shared tooltip; the same placement rule covers the real minimap column and secure click overlay without creating an unused widget at Enable. Turn this off to restore the selected Tooltip position for minimap owners, the column's original widget anchors and Blizzard's native blip placement.
- The anchor element's scale, from Layout Mode or the element's Size setting, is every tooltip's scale.

Forever API proof (Gethe/wow-ui-source `forever`, `9dc84f0`): `Blizzard_GameTooltip/Mainline/GameTooltip.lua` uses `ANCHOR_CURSOR_RIGHT` and `ANCHOR_NONE`; `Blizzard_APIDocumentationGenerated/RestrictedActionsDocumentation.lua` documents `InCombatLockdown()` returning a non-nil boolean, the same API Core/Combat uses. No combat event handler is needed.

Refresh proof at the same revision: `Blizzard_AuctionHouseUI/Shared/Blizzard_AuctionHouseSharedTemplates.lua:136` installs the owner's `UpdateTooltip`; `Blizzard_GameTooltip/Mainline/GameTooltip.lua:451-458` calls it at `SharedConstants.lua:145`'s 0.2-second interval. `UITimerDocumentation.lua:11` proves `C_Timer.After`; `SimpleScriptRegionAPIDocumentation.lua:568` documents `IsShown`'s secret aspect, checked before testing it. `test-tooltips-refresh.lua` covers these periodic shows, same-refresh hide/show, genuine close/reopen, and Reduced motion at four screen sizes.

Minimap owner proof: `Blizzard_Minimap/Mainline/Minimap.lua:191` checks `GameTooltip:IsOwned(MinimapCluster.ZoneTextButton)`; `Blizzard_GameTooltip/Mainline/GameTooltip.lua:456` reads `GetOwner()`; `Blizzard_SharedXML/RegionUtil.lua` traverses `GetParent()` to check descendants. `Blizzard_FrameXML/Camelot/EquipmentFlyout.lua:806` uses `SetAnchorType`, and `Blizzard_APIDocumentationGenerated/SimpleScriptRegionAPIDocumentation.lua` documents the map geometry. `test-tooltips-minimap-widgets.lua` drives the real column and secure overlay, including repeated shows, a tooltip created before Enable, left/right placement and toggle/module disable restoration. `test-tooltips-minimap-anchor.lua` covers all modes in and out of combat, both screen sides, nested owners, native blips and turning the switch off.

## Why

- Tooltips are Blizzard frames that Blizzard's own code fills, shows, sizes and moves many times a second, so the module restyles them in place instead of replacing them. Everything it draws sits on its own child frames, and per-tooltip state lives in `Safe.Side`, because a field written onto a tooltip taints the secure code that later fills it with secret unit data, and a tainted comparison of a secret value raises an error in Blizzard's own tooltip code.
- Blizzard's border is hidden by alpha, not `Hide`, because `SharedTooltip_SetBackdropStyle` shows the `NineSlice` again on every tooltip, and an alpha hook keeps it hidden without fighting that call.
- Line colours, the divider and the quality edge come from `TooltipDataProcessor` post-calls, the one path Blizzard gives addons into tooltip content. They run after Blizzard adds the data's lines and before it shows the tooltip, so the tooltip sizes itself once with the changes. They run again when Blizzard rebuilds a tooltip for new data, so nothing is added twice.
- The module changes Blizzard's tooltip font objects because the game creates tooltip lines on demand. Folio unit/spell/aura titles are the one per-line exception: content type chooses their names face without inspecting secret name data. Pooled titles return to `GameTooltipHeaderText` on clear, hide, another content type or Disable, preserving their text colour and the current header's shadow. The native header object is proved by 70862 `Blizzard_SharedXML/SharedTooltipTemplates.xml`; `SetFontObject` is in `SimpleFontStringAPIDocumentation.lua`. No tooltip maximum width, allocation, anchor or wrapping policy changes: natural tooltips keep the engine's bounds and truncation, and the Options preview retains its fixed box and paired-row fitting.
- `GameTooltip:SetScale`, `SetPoint`, `ClearAllPoints` and `SetOwner` are the calls Blizzard's own code makes on the tooltip. GameTooltip is not a protected frame, so they are allowed in combat and never block an action. The taint scan does not see them because they run on a parameter or a list entry; this paragraph is their review.
- The icon sits inside the panel and Blizzard's own padding makes room for it, because a tile outside the panel overlapped the comparison tooltips and did not match the kit. Blizzard resets the padding after the post-call (`GameTooltip_CalculatePadding` calls `ClearPadding` on show, and `ItemRefSetHyperlink` calls `SetPadding(16, 0)` for its close button), so `hooksecurefunc` post-hooks on `SetPadding` and `ClearPadding` put the icon's column back while the icon shows. A padding that reads as secret hides the icon instead.
- The rarity caption is a KstyleUI font string on the glass over a blank second line of Blizzard's title, because a tooltip's lines can only be appended and the caption must sit under the name.
- Tooltip sizes are in root units so a tooltip keeps its proportions on every screen and follows Appearance's interface size like every other KstyleUI element. Folding the scale into the anchor element gives the player one size control, in Layout Mode and on the settings page, instead of two that multiply.
- The health bar mirrors Blizzard's bar instead of reading health itself, because tooltip health is secret in combat. Blizzard's secure code reads it and calls `SetValue`; a `hooksecurefunc` post-hook hands the same value to KstyleUI's bar, a widget setter that accepts secrets. Blizzard's bar keeps its own guid in attributes for the same reason, and the module never touches them.
- The target and guild lines read names only after `issecretvalue` says they are plain, and never pass a secret to `AddLine`, because Blizzard's own comments note that secret line data on a tainted path can leave a tooltip with no lines.
- An open GameTooltip is rebuilt with `RefreshData` when a Tooltips setting, a held ID or stack key or an inspected item level changes, so its lines follow at once. In combat it waits for the next hover, because Blizzard's comments note that a rebuild on a tainted path can leave a tooltip without its secret lines.
- Disable puts back the fonts and the scale and hides the KstyleUI health bar, but keeps the glass, because Blizzard's border and bar art are held at alpha 0 by hooks that cannot be removed. The module is a reskin, so the core asks for a reload.

## EllesmereUI parity audit (2026-11-20)

Public surface: v9.9.1 and public source `8abfcbf`, inspected for option labels and observable behaviour only; no implementation, assets or game-data tables copied. Each distinct control, its cog controls and dynamic checklists are inventoried below; repeated controls are qualified by the panel that owns them. Shared visibility choices are listed together because they are values of one control.

Sources: [CurseForge description and screenshots](https://www.curseforge.com/wow/addons/ellesmereui), [v9.9.1 release](https://www.curseforge.com/wow/addons/ellesmereui/files/9708838), [Wago listing](https://addons.wago.io/addons/ellesmereui), [public changelog](https://ellesmereui.com/patch-notes), and the pinned public options links in each row. Wago's product page requires JavaScript in a static reader and does not expose an exhaustive menu inventory; the public source supplies the detailed rows. The [public HUD screenshot](https://media.forgecdn.net/attachments/1664/341/1-png.png) and [public style screenshot](https://media.forgecdn.net/attachments/1663/772/7-png.png) show the product's visible combat styling; they do not enumerate shell controls or prove API availability.

**Counts:** Present: 39; Missing, fits: 0; Missing, breaks consistency: 4; Not possible on Forever: 1. Present includes equivalent controls in another KstyleUI module; the control column names that placement. A partial equivalent states the missing part separately. These are implementation status counts after this PR, not a claim that every fitting option has shipped.

**PR-sized split:** the fitting inventory exceeds 600 implementation lines (multiple data bars, saved bag pins/recent history/list view, whole-panel chat idle state, unit-tooltip inspection and the QoL tools each need their own state and tests). This PR ships nine small, frequently visible controls, preserving existing defaults. Every remaining fitting row is explicitly assigned to follow-up A (minimap/data/chat), B (bags/tooltips) or C (QoL).
