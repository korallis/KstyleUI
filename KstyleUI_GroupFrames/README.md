# KstyleUI_GroupFrames

Party and raid frames up to 40: class colours, role icons, range fade, missing health, incoming heals, absorbs, heal absorbs and a shield line, your own heals over time, debuffs in your priority order with a glow on boss and important ones, six indicator slots, the dispellable debuff highlight, a layout that switches with raid size and role, and the game's Click Casting, bound from the settings page.

Folio preserves the theme-name sentinel and the explicit Alegreya Sans Regular face for compact name lanes. Party and raid health default to class colour, Flat bars and the shared `number` font role. Explicit user font choices still win, including an explicit Appearance role font for `names`, which keeps the lane's face instead of the compact swap and is shortened with distinct abbreviations when the name cannot fit.

| Field | Value |
| --- | --- |
| Module name | `GroupFrames`: its switch in `Core/Features.lua` and the `name` it registers with `KstyleUI.Modules.Register` |
| Approach | Replace |
| Loads | With the core addon, switched off until the player turns it on |
| Files | `KstyleUI_GroupFrames.toc` lists `GroupFrames.xml`, which loads every Lua file in order, so adding a file never edits the TOC |

## Rules

These come from the [design spec](../docs/superpowers/specs/2026-11-07-kstyleui-design.md). The roadmap's Global Constraints and [AGENTS.md](../AGENTS.md) apply too.

- Group frames use `SecureGroupHeaderTemplate` headers of `SecureUnitButtonTemplate` buttons. Health goes straight to the bar with `SetMinMaxValues(0, UnitHealthMax(unit))` and `SetValue(UnitHealth(unit))`. Group, tooltip and tracked bars share a spark-free fill end. Health text comes from `UnitHealthPercent` or `AbbreviateNumbers`, never from Lua arithmetic. Incoming heals come from `CreateUnitHealPredictionCalculator`. Range fade uses `SetAlphaFromBoolean`, because `UnitInRange` is always secret.
- Auras use the AuraContainer engine (`CustomAuraContainerTemplate`, aura groups and filter strings). Never scan auras by index while `C_Secrets.ShouldAurasBeSecret()` returns true. Aura data turns secret during a boss pull before `InCombatLockdown()` returns true.
- Blizzard frames this module replaces are hidden only through `KstyleUI.Safe.HideBlizzard`.
- At load the module only registers itself with `KstyleUI.Modules.Register`. It creates no frames, registers no events and installs no hooks until `Enable` runs. `test-modules-load.lua` checks the frames.
- Every element it shows registers with `KstyleUI.Layout.Register`, and every setting is declared through `KstyleUI.Options.Register`, so the player can resize and customise everything from the settings window.
- UI comes from `KstyleUI.Widgets`, colours from `KstyleUI.Tokens` and strings from `KstyleUI.L`. Translations live in the core string tables; see Languages in the repository README.
- Build mode: check that an API exists before calling it, check `issecretvalue` before any comparison, fall back to a safer path when the preferred one is unavailable, and log the path taken with `KstyleUI.DevTest.Log`.

## Text floor, class colours and whole pixels (KSTY-69)

- Raid names keep the compact Alegreya Sans face, not the party's Cinzel caps: the Captain's ruling of 2026-11-13 (KSTY-60 item 11), recorded again for KSTY-67 item 4. Forty-player density and whole names in the lane win over matching the party's face.
- The party's percents and the raid's names and percents take the 11 px text floor (`Scale.TextFloor()`, KSTY-67 item 3): at 1920x1080, where the game picks 15/16 px per unit, no percent and no raid name is under 11 px. A raid name the floor cannot hold keeps its head and shortens (`Thaldren...` on a 20 or 40-player row at 1080 lines); the Captain prefers 11 px with truncation to 10 px. Party names keep their own fitted size (`Widgets.Fitted`), so a twelve-letter party name still steps down and stays whole. The settings preview's canvases are marked previews, so the floor scales with them.
- Class-coloured names are lifted with `Theme.ClassTextColorForWidget(class, 0.62)` (`Unit.NameColor`), in the frames and the preview, so shaman blue, warlock purple, druid orange and death knight red read on the raid card's dark glass (KSTY-67 item 4); warrior tan and the lighter colours are unchanged.
- The headers lay their rows out on whole physical pixels (KSTY-67 item 21): `Headers` snaps each frame's width, height and spacing, the group spacing, the card's pads and size and the header offsets with `Widgets.Snap` on the holder, so every row, bar and card edge lands on the grid at 1920x1080, 3440x1440 and 5120x1440. A scale change or a Layout Mode change re-applies them. `test-groupframes-grid.lua` holds all three.

## Name typography

The 2026-11-10 typography ruling uses the `names` role where it fits, with explicit compact-party and compact-raid exceptions that preserve whole names. A party is one list: every active member uses the same face and size, including in the independent three-member settings preview. The fitter chooses the largest common size within the existing two-point range and restores it when a long name leaves. Unknown or secret names put the entire group at its existing floor without inspecting the secret text.

A kit lane below nine times its pixel-snapped fitting floor retains the already bundled Alegreya Sans Tabular Regular face; a party also measures its current public names before choosing the semantic face. Captioned parties remain compact at the nine tested densities; KSTY-57's uncaptioned party rows take `names` where the twelve-letter fixture fits and the compact face where it does not. Turning captions off or widening the row lets the party use `names`. The default 45-unit raid lane and the presets' 50-unit lane remain compact. At an exact floor of 8 the twelve-letter `Thaldrenwick` fixture measures 42.352 units in that face, versus 69.32 in the approved Cinzel 600 and 48.472 in PT Serif Regular. The party lane is the distance between its existing snapped anchors minus the fixed caption and gaps, with half a physical pixel of fitting tolerance. No lane, icon, status label or bar moves to make room.

`theme` is the saved follow-kit sentinel, not a captured file path. The picker offers it first; a saved module face or an explicitly selected global face wins. Semantic names keep the original text for native truncation after fitting reaches the existing floor. Compact and custom-face lanes retain the distinct shortening path for oversized data. Fixed class and health labels are never shortened. An unmeasured lane conservatively keeps the compact face; a captioned row with unmeasurable health width puts the party at its floor rather than guessing that the full row is available. Uncaptioned native rows keep their requested size. `test-groupframes-party-names.lua` and `test-groupframes-party-names-hidpi.lua` cover the twelve-letter fixture across all nine classes, the defaults, DPS, Tank and Healer, and nine screens; `test-groupframes-name-roles.lua` covers uniform shrink/restoration, preview isolation, secrets and saved choices.

## Elements

| Key | Frame | Layout options |
| --- | --- | --- |
| `groupframes.party` | The party holder: the party header in a frame sized to five members, with the party card inside it sized to the members shown | Scalable |
| `groupframes.raid` | The raid holder: eight group headers, or one header in role or class order | Scalable |

The holders are scalable rather than resizable: frame width, height, spacing and growth are settings, and the holder's size follows them. Layout Mode scales a whole group block.

## Headers

- The party header shows `player` (when **Show yourself** is on) and `party1` to `party4`. Its state driver is `[group:raid] hide; [group] show; hide`, or `[group:raid] hide; show` with **Show when solo**.
- Sorting by **Group** gives eight raid headers, one per raid group (`groupFilter` 1 to 8), placed by `Geometry.RaidGroups`. Each shows in a raid only.
- Sorting by **Role** or **Class** uses the first raid header with every group, `groupBy` `ASSIGNEDROLE` (tanks, healers, damage) or `CLASS` (`CLASS_SORT_ORDER`), and `unitsPerColumn` columns. The other seven headers are driven to `hide`.
- Buttons come from `SecureUnitButtonTemplate`. The header's `initialConfigFunction` sizes each button from the header's `kstyle-width` and `kstyle-height` attributes and sets `*type1` to `target` and `*type2` to `togglemenu`, so new buttons are right even when the header makes them in combat.
- Every button a header can need is made when the settings apply, out of combat: the header is hidden, every `show*` attribute is turned off, `startingIndex` is set to `1 - count` and the header is shown once. Raid and party changes in combat then only reassign units.
- A hook on the header's `OnAttributeChanged` sees each new `child<n>` and dresses it. The hook on the button's `OnAttributeChanged` follows the `unit` attribute and only touches the plain content frame, so a unit change in combat makes no protected call.
- Attribute, size and anchor changes wait for `KstyleUI.Combat.Queue` in combat.

## Rows

KSTY-57 laid the party and the raid out to the KSTY-44 party mock-up and the KSTY-47 raid mock-ups (renders/KSTY-47/raid-mockup/ in the Captain drive). With the name above the bar, every raid frame and every party frame without a portrait is a row (`Geometry.Button`'s `Overlay`); a party frame with a portrait, or a frame with the name on the bar, keeps the layouts below. A row is, from the top:

- The name line: the role pip (the kit's diamond in the role's colour on a black edge: tank `rare`, healer `friendly`, damage `hostile`; 13 units on a party row, 10 on a raid row), the name in the class colour, your heals over time, and the percent right-aligned at the bar's end. A secret role cannot pick a colour, so Blizzard's role helper draws its role icon in the pip's place. The leader crown is a badge on the pip's corner.
- A full-width bar under it (a party row's bar starts under the name, so the pip hangs in its own column), then a thin power line under the bar at its width. The bar takes the row's height left after the name line and the power line, and the default sizes give the mock-ups' bars: 12 units on a party row, 12, 11 and 9 on a raid row at 10, 20 and 40 players (`test-groupframes-rows.lua` holds them at 1280x720, 1920x1080, 3440x1440 and 5120x1440).
- The indicator lane: three spots at the debuff size (12 units or more) at the name line's end, left of your heals and the percent, off the bar. Indicators take them in slot order, so the three defaults (external defensives, crowd control, big defensives) show there; they cover the name's tail only while they show, never its head, the pip or the percent.
- The raid marker sits in the party's pip column beside the bar, or over a raid bar's left end: never on the name line, so it never covers the percent.
- The debuffs, a row of three at 12 units, overlay the bar's right end, as Cell and Grid2 draw them; past three, the last cell holds the `+N` chip. The first boss debuff also takes a slot centred on the bar, at least 12 units, overlapping the bar's edges when the bar is thinner.
- `Dead`, `Ghost` and `Offline` take the percent's place at the row's end; with no percent (over 25 members) they centre on the emptied bar. The name yields only what the status needs past the percent and your heals.
- No tile behind a row: the party stands bare on the world, and the raid sits in a quest card (the window chrome and a cap reading Raid with the raid's size aside) that hugs the groups in use, in combat too. Either card can be turned on or off (`<kind>.card`).
- The size follows the raid (`auto.size`): up to 10 players the rows are 16 wider, 3 taller and larger in type, over 25 they are 20 narrower, 8 shorter, without the power line or the percent, as the mock-ups draw them. A healer's raid rows are 20 wider (`auto.role`), so three of their heals sit beside a whole twelve-letter name.

## Status icons

Outside the rows, `Geometry.Button` lays the role, leader and raid marker icons out with the texts, so none of the four overlaps at any frame size (`test-groupframes-indicators-layout.lua` resolves them with the renderer's solver at the default, smallest and largest party and raid sizes):

- The role icon sits at the top right, a `gapTiny` in from the edge. With the party role ring on, the ring's letter carries the role, so the icon stays hidden and its corner holds your heals. Its size is the `iconSize` setting, shrunk so three fit across the frame and one fits its height.
- With the name above the bar, the leader icon sits over the portrait's corner, and the raid marker sits inside the frame: in the room between the name row and the bar when it fits there, else centred on the bar.
- With the name above the bar, the name row ends a gap before the role icon and the health text is right-aligned at the row's end; the name ends a gap before the health text and truncates while the text shows.
- With the name on the bar, the leader icon sits on the top-left corner and the raid marker centres on the top edge, no lower than the name row, and the name starts after the leader icon when no portrait carries it. Text on the bar is outlined when its outline setting is the soft shadow, so it reads on any class fill.
- With the name on the bar, the health text centres on the bar at its natural width while its line sits below the icon band; when the bar is so short that the line reaches into the band, the text narrows to the span between the icons.
- The ready-check icon sits on the bar's centre and the assistant icon on the leader icon, as before.

## Lanes

No helpful aura ever paints on the health bar (`test-groupframes-clear.lua`). Harmful auras may overlay a row's bar end. `Geometry.Button` gives each signal its own lane:

- A party frame's debuff block sits outside the frame (the default) or at its corner of the space under the name lane; there the bar keeps the rest of that space's width, never less than half, so the block gives up columns before it squeezes the bar. Rows shrink their icons down to 8 units, then drop to one row.
- Your heals over time ride the name line's right end, flowing leftward from the percent, wholly above the bar. The name keeps half the line on a party frame with a portrait and room for a twelve-letter name at its smallest size on a row; the heals shrink toward 8 units to keep their count, then give up icons. With the name on the bar there is no name line, so they take a row under the bar.
- The indicator slots past the row's lane take the free spots left over, clear of the name, the power line, the debuff block, the boss slot, the percent and your heals.
- An indicator with no room at a legible 12 units (or the smaller size the player picked) turns off, and its settings show a note that names party or raid frames and the remedy: larger frames, a smaller size, or another indicator off.
- With a portrait and the name above the bar, the missing health and a status (`Dead`, `Ghost`, `Offline`) sit right-aligned at the party row's end, and the name ends a gap before them; the status takes the class caption's place, so the name stays whole.

## Extension points

Feature files add to the frame without editing it: `Button.built` (build parts on a new frame), `Style.appliers` (lay them out after `Style.Apply`), `Style.painters` (paint them on preview samples), `Unit.extra` (refresh them with the unit), `Unit.Chain(event, fn)` (handle another unit event, registering it when new), `Unit.ColorSources(f)` (the bar and name colour sources a frame uses), `Unit.SetPortrait(f)` (what fills a shown portrait) and `Frames.events` (global events while the module runs).

## Medallions

Under the Medallions HUD style (`KstyleUI.HudStyle.Current() == "medallions"`, KSTY-87 and KSTY-88's group sheet), `Medallions.lua` changes the look and nothing else; it switches live on `HudStyleChanged` through `Frames.Apply`, so it waits for combat to end like any other change.

- **Party.** Each row gets its medallion (`party.portrait` on): the painted 64 px badge cut from `KstyleUI.Medallions.Portrait(texture, unit, "badge")`, the secret-safe resolver, which falls back to the engine portrait when the unit's race, class or sex is secret. Painted art is pre-circled, so it drops the circle mask the engine portrait keeps. The class-coloured enamel ring (`medEnamel`) sits under a steel bezel (`medRing`); there is no level badge and no tile. Without the resolver, the engine portrait stands in. The role shows as a small pip of the module's own art before the name (`Geometry.Button` is wrapped while a party frame applies under Medallions), never the atlas square at the row's end.
- **Raid.** Class-coloured tiles with no medallion: one fill across the whole tile (`Geometry.Button` is wrapped while a raid frame applies under Medallions), the name on it in white caps in the Medallions label face (Inter SemiBold) with a soft shadow, shortened by Lua with distinct abbreviations so it never runs past its lane, at the text floor or over. The percent sits in a fixed right-aligned column in the number face (PT Serif Bold) with a soft shadow, and the bar's end cap is hidden on tiles so nothing crosses it; a Dead or Offline tile hides its debuff block, which its status may cover. A tile tall enough for two lines puts the name and the debuff pips on top and the percent at the lower right; a shorter one runs name, pips and percent along one line, the percent at the tile's right end. The pips are the debuff block, at most a quarter of the tile wide, and draw only when a debuff is up; there is no role square. The heal row sits inside the fill's lower left on a two-line tile and under the fill on a one-line tile while the player heals. Low health turns the fill and the percent red, and the loss band shows the hit. No power bar, no glass tile: the tile sits in the group tile slab material (the `medGroupTile` nine-slice behind the frame, KSTY-110 WP-C), which goes when the style switches away.
- **Tidy lanes.** Names, indicators, your heals and the percent each keep their own lane on the name line, in that order from the left; the heals flow leftward from the percent, as on Frames rows. When the name would fall under its floor (`Geometry.NAME_EM` times its smallest size), it keeps the floor and the indicators cover its tail only while they show, as on Frames rows. `test-groupframes-parity-r5.lua` holds the heals clear of the percent and the indicator lane at all four test screens.
- **Target ring.** Steel (`#e6ecf3`) instead of the accent.
- **Settings.** The style lays its values over the defaults only: a value the player changed from its default wins. A two-way setting such as `raid.power` has only the style's value and the default, so under Medallions it always follows the style.

`test-groupframes-medallions.lua` holds all of it, and the switch back to Frames; `test-groupframes-medallions-tiles.lua` and `-tiles-wide.lua` hold the raid tile at all nine CREW screens for 10, 25 and 40 players: the fill across the tile, the name clear of the percent and the pips, and the text floor.

## Why

- **Secure headers, not our own roster code.** `SecureGroupHeaderTemplate` places units in secure code, so the roster can change in combat and clicks still target the right member. Everything KstyleUI draws sits on a plain content frame inside each secure button, so drawing never needs a protected call.
- **Buttons made out of combat.** A header makes a button the first time it needs one. If that happened in combat, our dressing code would run in combat. Making every button at apply time, with `startingIndex` and the `show*` attributes off, keeps all frame creation out of combat.
- **Eight raid headers.** One header with `groupBy = GROUP` fills columns of five in turn, so a group with three members pulls the next group's members into its column. One header per group keeps each group in its own column, as the raid footprint plans. Role and class order reuse the first header, because those orders are meant to flow.
- **Holders that scale.** The headers size themselves from the frame size, the spacing and the roster. A holder sized to the largest group gives Layout a stable footprint to anchor, while the settings own the frame size.
- **Secrets go straight to the engine.** Health, maximum health, power and range are secret on Forever. They reach `SetValue`, `SetMinMaxValues`, `SetFormattedText` and `SetAlphaFromBoolean` untouched. Percent text uses `UnitHealthPercent` with a 0 to 100 curve (`CurveConstants.ScaleTo100`, or our own curve), and the missing-health text hides at full health through a step curve on its alpha. Nothing compares or adds a health value.
- **Class colour with secret pass-through.** When a unit's class is secret, `Theme.ClassColorForWidget` passes the secret colour from `C_ClassColor.GetClassColor` straight to `SetStatusBarColor`. A plain class gives `Theme.ClassColor`.
- **The player never fades.** `UnitInRange` reports the player as not checked, so the player's own frame keeps full opacity. Offline members keep full opacity too; their grey bar already says why they cannot be healed.
- **The gamepad interface gets Blizzard's group frames back.** Forever's gamepad group targeting (`Blizzard_GamepadTargeting`, `RaidTargetDPAD.lua`) runs `SmartNavigation` over `CompactRaidFrameContainer` in a raid and `CompactPartyFrame`, a child of `PartyFrame`, in a party. While `InputUtil.IsGamepadUIEnabled()` is true (or, without `InputUtil`, `C_InputInterfaceStyle.GetCurrentStyle()` is the gamepad style), the module gives all three Blizzard frames back through `Safe.RestoreBlizzard`, hides its headers and holders, stops its unit events and binds its debuff containers to `none`. `INPUT_DEVICE_INTERFACE_TRANSITION` switches between the two states. In combat the header changes wait for `KstyleUI.Combat.Queue` and only the last switch applies; until they run, KstyleUI's frames are still the ones on screen, so they keep following their units. Settings changes made while standing down apply when keyboard and mouse return. A secret or missing answer counts as keyboard and mouse.
- **Blizzard frames through Safe.** `PartyFrame` holds Blizzard's party frames and `CompactPartyFrame`; `CompactRaidFrameContainer` and `CompactRaidFrameManager` hold the raid frames and the manager tab. Each is reparented through `Safe.HideBlizzard`, which waits for combat and Edit Mode to end, and comes back through `Safe.RestoreBlizzard` when the module or the setting is switched off. `Blizzard_CompactRaidFrames` can load after login, so `ADDON_LOADED` applies the setting again.
- **Role icons through Blizzard's secure delegate.** `UnitFrameUtil.UpdateUnitFrameRoleIcon` reads the role and wraps it in a secret when the unit's identity is restricted, then sets the texture and visibility itself. Without it, the role from `UnitGroupRolesAssigned` is used when it is plain.
- **Leader and markers without a test on a secret.** The leader flag goes to `SetAlphaFromBoolean`. `GetRaidTargetIndex` is always secret, so the marker hides only when `type(index)` is not `"number"`; `type` sees through a secret, and a secret index goes straight to `SetSpriteSheetCell`.
- **Heals and absorbs anchored to the fill.** Each prediction bar spans the health maximum and is anchored to the end of the fill before it, so the engine places it; Lua never adds health and heals. The calculator clamps heals and absorbs to missing health, and a clip frame over the health bar cuts anything that would still spill out. One calculator is made per frame and reused.
- **Threat is readable on Forever**, but a secret status or colour hides the glow rather than guessing. The glow is the kit's selection glow (`Widgets.Glow`, the shadow falloff) one level behind the frame's tile, so it rings the chamfered silhouette instead of a square box; party frames get an 8-unit glow and raid frames, 3 units apart, a 4-unit one.
- **Debuffs on the AuraContainer engine.** Aura data is secret during a boss pull, and index scans error under restriction. Each frame gets one `CustomAuraContainerTemplate` container bound to its unit with `SetUnit`. The container runs Blizzard's raid frame classification (`SetAuraProcessingPolicy(ProcessAura)`, buffs ignored), and two aura groups take its results through `candidateFilters.processedAuraType`: `dispels` (debuffs your raid can dispel) first, then `debuffs` (boss, priority and other debuffs). Both sort by `AuraContainerSortMethod.UnitFrameDebuff`, which reads the `debuffType` that only the classification fills, so each group holds only classified auras. A `dispel` aura slot draws the highlight. The engine finds, sorts and draws the auras; Lua only sets filters, counts and layout. A client without the processing policy gets one group in the default order.
- **The dispel highlight is the slot's own frame.** The slot's frame covers the group frame, with a faint wash (a `chamferTile` nine-slice at 16%) and the tile's double bevel edge, each piece registered through `AddDispelTypeTexture` in the `PreserveAsset` style, so the engine shows them and tints them in the debuff type's colour only while a matching debuff is on the unit. Lua never learns the debuff type. Every piece follows the 3-unit chamfer, so nothing paints the corners the tile cuts away.
- **Rings are drawn the way the kit draws its edges.** `Style.Ring` builds the tile's double bevel edge as `Widgets.Chrome` does: the corner pieces of `bevelTileOuter` and `bevelTileInner`, which carry the 3-unit chamfer and are sized in borders as the chrome sizes its own so the line in the art is one border wide, and straight sides one `Widgets.Border` thick between them, the inner line one border in. The sides are whole physical pixels on every screen and no piece reaches the corners the tile cuts away. Core keeps its bevel builder private, so the module has its own copy with a draw layer it can choose and pieces it can hand to the aura engine.
- **The target ring follows the chamfer.** The target highlight is that double bevel edge in the accent, on a frame whose alpha follows the secret `UnitIsUnit(unit, "target")` through `SetAlphaFromBoolean`. It traces the tile's own double bevel edge, two lines thick like the old outline.
- **Debuff icons are the kit's icon tiles.** Each engine button gets a `Widgets.Chrome` tile, the icon two borders in and masked by `iconMask`, and a cooldown swipe drawn with `iconMask`, as `KstyleUI_Auras` dresses its buttons. The debuff type colour fills a `chamferTile` nine-slice behind the icon, so it shows as a chamfered border. Icon size and spacing are snapped to whole pixels with `Widgets.Snap` before they reach the engine's layout, and buttons are sized with `Widgets.Size`. The chrome's `Restyle` is wrapped by the same secrecy gate as the rest of the icon, so `Widgets.RestyleAll` never reaches a restricted aura button.
- **Containers are made out of combat, when a frame first gets a unit.** Raid buttons are many and most stay empty, so a container per button would cost ten aura buttons each for nothing. A frame that first gets a unit in combat makes its container when combat ends.
- **Aura buttons are touched only while auras are readable.** The engine denies tainted access to its aura buttons while auras are secret, so icon size and font changes wait until `C_Secrets.ShouldAurasBeSecret()` is false. Container settings (filter, count, layout) go through the container's own methods and apply at once.
- **The party card hugs its members.** The holder keeps the five-row footprint that Layout places and Layout Mode drags. The card inside it is a plain frame, anchored at the corner the rows grow from, sized to the rows the party shows (`Geometry.PartyShown`: you and the others, at least one, all five when the count is unknown) and eased there over the kit's panel time on `GROUP_ROSTER_UPDATE`. Nothing secure hangs from the card, so it resizes in combat with no protected call.
- **Raid names live on the glass.** A white or pale class fill (priests, rogues, paladins) makes white text unreadable. Raid frames put the name in a lane above a class-coloured bar that fills the rest of the tile, so the name always sits on the dark glass. The few figures on the bar (the missing health, a status) carry a thick outline.
- **Your heals over time on the engine.** A second `CustomAuraContainerTemplate` container per frame runs Blizzard's unit frame processing with buffs classified and debuffs ignored (`ignoreBuffs = false`, `ignoreDebuffs = true`), and one group takes `HELPFUL|PLAYER` auras whose `processedAuraType` is `Buff`: the heals over time and shields you cast that Blizzard's raid frames would show. The engine finds and draws them while auras are secret; Lua only sets the filter, the count and the anchor at the name line's right end. It is made out of combat, like the debuff container.
- **A shield line that shows at full health.** The absorb overlay is clamped to the missing health, so a shield on a full-health tank is invisible there. The shield line spans the health maximum and takes `UnitGetTotalAbsorbs`, a secret passed straight to `SetValue`, along the bar's foot.
- **Click casting is the game's own.** Forever's `SecureUnitButton_OnClick` asks `C_ClickBindings` before it reads a button's `type` attributes, and runs a bound spell or macro on the button's unit (`Blizzard_FrameXML/SecureTemplates.lua`). These frames are `SecureUnitButtonTemplate` buttons, so the game's Click Casting (Options, Keybindings, Click Casting) works on them in and out of combat. A second click system of `type1`/`spell1` attributes would only be shadowed by those bindings, so the module points to them instead: until a spell, macro or pet action is bound (`C_ClickBindings.GetProfileInfo`), the unit tooltip says where to bind one, out of combat only.
- **Debuffs fit their cells, highest priority first.** The debuff container sits in a plain clip frame sized to the cells that fit inside the tile (or the party card's lane), in whole rows so the clip never shows more icons than the count, and the icon size shrinks to fit one cell when the setting is larger than the tile. Four groups split the debuffs with the engine's own flags (`isBossAura`, `isPriorityAura`, the processed dispel and debuff types), so none shows twice, and their `layoutIndex` follows the priority list; the flow layout fills the visible cells from the first group on. Each group may take one aura more than the cells, which falls in the clipped row.
- **The `+N` chip is counted by the engine.** A hidden `CustomAuraContainerTemplate` container per frame holds the same four groups as the debuff row (same filter, candidates and processing policy; the dispel group capped at the dispel count) and stacks one frame per line, so its height is the number of debuffs the row would hold. `KstyleUI.Widgets.Overflow` hangs a strip of labels (`+2` to `+13`) from its foot through anchors alone, and a window on the row's last cell shows the label that lines up, on the chip's opaque glass. Lua never reads, compares or sums an aura count, so the count stays true while auras are secret. It replaced a bare `+` in the first hidden category's colour, which said there were more but not how many. Your heals over time keep that bare `+` along the name line.
- **Dispellable debuffs past the dispel count still show a `+`.** The dispel group stops at `auraDispelCount`, so its extra debuffs never reach the shared flow. A hidden `CustomAuraContainerTemplate` container per frame (alpha 0) holds one group with the dispel group's filter and candidates and one frame more than the dispel row shows, stacked one per line at a fixed pitch. The engine sizes the container to its frames; a badge frame made from `DisableUntrustedLayoutScriptsTemplate` hangs from the container's foot inside a clip window on the mark's cell, so it reaches the window only while that extra frame exists. The blue `+` sits on the first row's last cell and draws above the icons' text and the `+N` chip. With a dispel count of 0 there is no dispel row: the other debuffs take dispellable ones too, and the ghost is off.
- **The party card keeps a lane for the outside debuffs.** With debuffs outside the tile, each party frame is narrower by the debuff strip, a gap and a unit per icon for whole-pixel snapping, so the card's width, and the rail, stay the same and the icons stay on the glass. A frame too narrow for a lane, and every raid frame, places outside debuffs in the matching inside corner.
- **One dead state.** A dead, ghost or offline member reads `Dead`, `Ghost` or `Offline` on the bar, with the name dimmed, on party and raid frames alike, even when the frame shows no health text.
- **Short numbers.** Health text uses the shared `K.Widgets.ShortNumber`, so missing health reads `-12.4K` as on every other KstyleUI surface.
- **Distinct short names.** A name first steps its size down two points; a name that still does not fit ends in an ellipsis, and when its prefix matches another member's name it keeps its ending (`Sha...e`, `Sha...r`). A secret name is passed to the engine whole.
- **The role icon leads a raid tile's bar.** On a raid tile the role icon, the leader crown and the raid marker sit in the bar's left corner, so the name gets the lane's whole width up to your heals.
- **Heal absorbs back from the fill.** A reverse-filled bar hangs from the fill's end and takes `GetHealAbsorbs` from the heal prediction calculator (clamped to current health), or `UnitGetTotalHealAbsorbs`, a secret passed straight to `SetValue`.
- **Indicators on the engine's aura slots.** Each slot is an aura slot with a native filter: `HELPFUL|EXTERNAL_DEFENSIVE`, `HELPFUL|BIG_DEFENSIVE`, `HELPFUL|PLAYER|RAID_IN_COMBAT`, `HELPFUL|IMPORTANT`, `HARMFUL|CROWD_CONTROL`, `HARMFUL` with `isBossAura`, `HARMFUL|RAID_PLAYER_DISPELLABLE`, or `HELPFUL` with `includeSpellIDs`, which the engine allows for buffs on group members. Lua never reads an aura or a spell ID from one.
- **Automatic layout out of combat.** The raid size bracket and the player's assigned role are read when the module starts and on roster and role events; a change waits for combat to end, then applies as an overlay on the saved settings.
- **Click casting from the settings page.** The preview pane lists the game's Click Casting bindings (`C_ClickBindings.GetProfileInfo`), removes one, and binds a spell or macro dropped on its slot to the mouse button and modifiers of the next click on it (`MakeModifiers`), through `SetProfileByInfo`, out of combat only. If any binding comes back with a field the client keeps secret, the panel changes nothing and points to the game's window, so a write never drops a binding it could not read. Its help and status lines are sentences in the `body` role. A button opens the game's own window (`ToggleClickBindingFrame`).
- **Clicks pass through debuff icons.** `SetMouseClickEnabled(false)` keeps the debuff tooltip on hover while a click on an icon still targets the member.
