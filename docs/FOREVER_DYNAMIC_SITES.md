# Dynamic Forever API-site dispositions

This is the LEE-28 follow-up to [FOREVER_API_AUDIT.md](FOREVER_API_AUDIT.md), against Forever **1.60.1.70862**, Gethe/wow-ui-source **9dc84f0**. The initial snapshot was **c65b89f8** (992 resolved / 111 dynamic); the final rebase to **f99cf9d3** has **1009 resolved / 110 dynamic**, not the earlier 978/101 snapshot. Occurrence/domain locations below pin c65b89f8 for stable references; changed input domains were rechecked after the rebase. This PR also moves a few lines when adding guards.

All **111 baseline occurrences have an explicit disposition**: 108 current sites are source-proved, contained by an existing runtime probe, a scanner false positive, or guarded here; one was retired upstream in #233 (E6); two are assigned handoffs in code being replaced by another owner (G37, G38). Thus all **110 current sites** are accounted for. The handoffs are not silently called verified. The guard still says `dynamic` because it does not perform whole-program inference or consume a human audit ledger.

## What changed, and what did not

Six optional named-child lookups now reject secret-capable `GetName()` returns before concatenation/indexing (G3, G31, G40, G44, G46, G50). Public names still resolve normally; direct child fields still work when a name cannot be read. No size, anchor, profile default, appearance token or placement code changes. No native script or frame-field write is introduced. The nameplate dispatcher now rejects secret/non-string unit tokens before its lookup (E18). Mail and chat-copy title reads also avoid boolean-testing secret-capable getter results before their existing guards.

The native contract is `Blizzard_APIDocumentationGenerated/SimpleFrameScriptObjectAPIDocumentation.lua:107-119` (`SecretReturnsForAspect = ObjectName`); `FrameScriptDocumentation.lua:287-303` proves `issecretvalue`. A type check alone does not make a secret string public. The new regression installs a global-key trap in the fixture because ordinary Lua permits userdata table keys while the client forbids secret indexing. It fails on each old named-fallback path and the unguarded unit dispatcher, passes all hardened paths, checks public tab/icon/COD/tooltip behavior, and requires no caught addon errors. A source assertion covers pre-guard getter truthiness, which Lua stubs cannot intercept. This is defensive source-contract coverage, not evidence that these exact windows have returned secret names in the owner's client.

`Core/Events` deliberately has one handler per owner/event and retains its existing invalid-input programming-error contract. This audit proves the current callers, not arbitrary third-party arguments or future widget templates. Two caller collisions found during this audit were fixed upstream in #233 under LEE-60; no visibility/layout behavior is changed in this PR.

## Reading the proofs

Source paths are under `Interface/AddOns/` in 9dc84f0. `D/` and `API/` mean `Blizzard_APIDocumentationGenerated/`; an unqualified source basename belongs to the source module named in that row. RXP paths are under the installed, read-only `RXPGuides/` addon and are explicitly third-party evidence.

The generated contract catalog supplies source file/line and signature/secret flags. Every one of the **176 event names** traced through the variable event sites was independently re-resolved through that catalog, which filters loaded source and prefers generated documentation; unfiltered grep hits in WoWLabs or deprecated files are not used as proof. Their exact source locations are in the event appendix. The #235 rebase adds BAG_UPDATE_COOLDOWN, PLAYER_EQUIPMENT_CHANGED and SPELL_UPDATE_USES to E8's domain; the first two were already proved elsewhere in the appendix.

The matching client's FrameXML GlobalStrings name export (CSV SHA256 `24cec99d597d5215c77747c87266215832d00895a7fe9f217ba5870ae2ced60d`) proves the five quest-menu labels, five mouse-button labels, all nine `ITEM_QUALITYn_DESC` names and the thirteen loot-format names. FrameXML flags are checked; no localized values are copied. Numeric `LE_GAME_ERR_*` and colour globals instead have loaded-source uses and explicit runtime type/capability probes. This is name/receiver evidence, not a claim that native timing or protected execution was tested.

**Load rules:** Forever is the Camelot game in the Mainline family. `[Family]` resolves to Mainline, `[Game]` to Camelot, and a Mainline allow-list includes Camelot unless excluded. The matching TOCs explicitly combine `[AllowLoadGameType mainline] [ExcludeLoadGameType camelot]` for replaced character files and load both the Mainline base and Camelot override of ContainerFrame (`Blizzard_UIPanels_Game.toc:44-66,118-119`). The existing source walker and its exclusion tests encode those rules; a bare Mainline tag is not evidence that a file is absent on Forever.
