# Native context-menu materials

## Security boundary (Forever 1.60.1.70862)

Source: Gethe/wow-ui-source `forever`, commit `9dc84f0`, read-only audit copy
`~/.capy/work/wow-ui-source-70862/Interface/AddOns/`.

This skin is limited to three descriptions generated by KstyleUI: minimap
tracking, the addon compartment and quest-card right-click menus. Each receives
its own `KSTYLEUI_` tag. No unit-menu tag, global menu-manager hook, Blizzard
mixin replacement, responder replacement or protected-owner write is required.
Combat-opened menus, protected/forbidden owners and unknown background variants
keep Blizzard's appearance. Other addons' menus and Blizzard's own quest-log
menus are outside this allowlist, even when their labels look identical.

The eligible owners are addon-created ordinary buttons:
`KstyleUI_Minimap/Column.lua` constructs tracking and drawer-toggle icon buttons
without secure templates; only calendar/queue delegates get secure overlays.
`Drawer:OnToggleClick` passes that toggle to its compartment generator. The quest card's
`NewRow` creates an ordinary `Button`; its separate secure quest-item overlay is
not the context-menu owner. The runtime still rejects a protected/forbidden
owner rather than relying on these current constructors alone.

The native pipeline supplies the following integration points:

* `Blizzard_Menu/MenuUtil.lua:145-174` selects the owner's/default style,
  creates a description, populates it, then opens it. We do not replace this
  function or write `owner.menuMixin`.
* `Blizzard_Menu/Menu.lua:2744-2791` runs tagged customization through
  `Menu.ModifyMenu` after the generator and before opening. Our registrations
  name only the three addon-owned tags.
* `Menu.lua:2205-2299` acquires a pooled `MenuTemplateBase`, installs its
  compositor, then calls the original style's `Generate`. At
  `Menu.lua:2483-2486`, `AddMenuAcquiredCallback` runs after that background
  exists but before element creation/layout. We inspect only the menu's direct
  textures, not its children, focus-navigation frames or secure owners.
* `Blizzard_SharedXMLBase/SecureTypes.lua:196-198` implements callback array
  iteration with `secureexecuterange`. `Menu.lua:1029-1070` runs ordinary
  element initializers before the native final initializer. The skin appends
  one initializer; it does not replace the final initializer or enabled-state
  handling. `11_0_0_MenuImplementationGuide.lua:196-207` explicitly demonstrates
  changing `button.fontString` with `SetFontObject` in an initializer.
* `Mainline/MenuTemplates.lua:53-62` attaches one `common-dropdown-bg` texture.
  `Classic/MenuTemplates.lua:47-60,102-115` attaches one classic atlas and an
  inset black texture. Only these complete background patterns are eligible;
  unknown patterns are not hidden. These are compositor attachments, not
  layout frames. `MenuVariants.lua:41-50` similarly attaches `button.highlight`;
  its existing enter/leave handlers continue to control visibility.
* `Compositor.lua:161-179` forbids raw child creation. All new chrome textures
  must use `AttachTexture`, including textures created on resize. Its
  `Clear`/`Detach` at lines 423-454 restores original metatables, releases
  attachments and resets them through `PoolReset` at lines 4-14.
  `Menu.lua:2181-2195,2522-2527` resets pooled menu state and frees scripts.
  Chrome must therefore never join the persistent widget restyle registry or
  outlive the acquisition. Release marks it dead before removing the skin's
  external reference. A surviving extrinsic size hook or queued layout/material
  callback is inert even if `FreeScripts` does not remove that binding; native
  hook removal itself remains an in-game check. Initial paint completes before
  the size hook is installed, and the replacement exists before native textures
  are hidden, so construction failure cannot hide the original background or
  leave a partially initialized chrome size hook behind.

The implementation guide's taint guarantee (lines 415-417) covers inserting
elements without contaminating surrounding handlers. It is not a blanket
guarantee for arbitrary writes to secure-opened menus. `Blizzard_UnitPopupShared/
UnitPopupShared.lua:86-178` is a separate secure-sensitive path. The skin does
not register its tags or touch its frames, in or out of combat. A stub can prove
that our exclusion branches perform no writes; it cannot prove native taint
semantics. The owner's final in-game session must still check repeated pooled
reuse, unit menus after styled menus, combat transitions and gamepad navigation.

Additional API evidence is in `Blizzard_APIDocumentationGenerated/`:
`SimpleFrameScriptObjectAPIDocumentation.lua:242` (`IsForbidden`),
`SimpleScriptRegionAPIDocumentation.lua:365,540` (`HookScript`, `IsProtected`),
`SimpleFrameAPIDocumentation.lua:577` (`GetRegions`),
`SimpleScriptRegionResizingAPIDocumentation.lua:52,65` (anchor reads),
`SimpleTextureBaseAPIDocumentation.lua:45,383,403` (atlas/blend/color),
`SimpleFontAPIDocumentation.lua:199,277` (font/shadow),
`SimpleFontStringAPIDocumentation.lua:529` (`SetFontObject`) and
`UnitDocumentation.lua:3887` (`PLAYER_REGEN_DISABLED`).
`Blizzard_SharedXML/FontableFrameMixin.lua:120,131` demonstrates `CreateFont`.
Security and anchor reads are secret-checked before comparison. Font strings use
private font objects, not the compositor-forbidden `SetFont`, and never enter
the kit's persistent font registry. `Menu.lua:1902-1903` exposes `menu:Close()`;
only acquisitions present in this skin's active set are closed on a setting
change or combat entry.

The close path reaches `FrameFactory.lua:54-56`, whose pool collection is
created at lines 4-9. `Blizzard_SharedXMLBase/Pools.lua:861` aliases that factory
to `CreateSecureFramePoolCollection`; its `Release` at lines 470-479 calls
`securecallmethod` on each pool. `SecureObjectPoolMixin` uses secure active maps,
stacks and counters (lines 205-234), and rejects secret objects (265-277).
This rules out a plain shared-pool write as the reason to avoid the public close
API. It does not replace the final in-game combat-close/taint check.

After a font-object change, the initializer refits the original description
label with `SetTextToFit` (`SimpleFontStringAPIDocumentation.lua:709`).
`MenuUtil.lua:185-186` provides `GetElementText`; the label is secret/type-checked
before use. This happens before native `MeasureExtents`, so a wider configured
font is measured rather than clipped inside the old font's fitted width.
If `GetStringHeight` (`SimpleFontStringAPIDocumentation.lua:325`) exceeds the
native row text height, the initializer expands that height before measurement;
it never shrinks the native minimum. Both dimensions are secret-checked.

## Restoration

Glass and a disabled skin perform no visual writes. Changing material, profile,
scale or the skin switch closes only currently styled menus, so reopening uses
the new settings. Closing lets the native compositor restore the pool; the skin
does not attempt to manually restore font/texture snapshots on recycled regions.

## In-game checks

1. Open tracking, addon compartment and quest-row menus with Flat, Slate, Forged
   Ticks and Forged Brackets. Check opaque fills, kit type, hover, disabled rows,
   check marks, actions and submenu/gamepad behavior.
2. Repeat with Glass, the context-menu switch off and the Skins module off.
   Compare with unmodified Blizzard menus, including their native type/hover.
3. Open a styled menu, close it, then open unit right-click menus. Repeat during
   combat and after combat. Check BugSack for blocked actions or taint.
4. Switch material/profile/scale while a menu is open. It should close cleanly;
   the next opening should have the selected style, with no stale decorations.
